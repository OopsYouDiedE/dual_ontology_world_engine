# 推理原型第二轮：把难度从执行器搬回证据

## 第一轮究竟错在哪里

1. 调查直接派发用途和搬运事实，主要机制很早就明白，但湿椅、杯子身份、人物认知没有构成必须互相解释的问题。玩家误以为已经解完，剩下只是输入。
2. 玩家承担了角色控制器的职责：写查看、写循环、调优先级、用绕路赶未公布的茶铃行动值。合法解释也会因执行细节失败。
3. 椅子、柜子难以发现可点位置；遗漏证据后，界面仍给出似乎快要完成的差异计数。
4. 终局只露出最后一条差异，不能把修改动机带回完整证据。
5. 未先跑通作者参考与另一条合法路线，无法区分设计困难和实现困难。

## 实质改动

### 相互制约的材料

初始共同清点提供每人有来源的旧记忆。盆沿缺口杯印与医生“放回原处”的陈述，要求区分最初归还和最后送洗；第一声铃后的满缺口杯不能被最终洗具台的位置取代。叶纹杯在第一声铃前用于染纸，第二声铃后却已在窗边装满，要求区分物品身份、杯的用途和续茶发生的位置。

椅布只给缺口杯底湿圈、拖长方向和局部干湿，不直接宣布谁倒了茶。取得它才能向整理者问换杯时的暂放、向主厨问最后一次观察。两人的行为分别可能合理，但旧记忆在他人改变承托状态后过时。重新查看与沿用记忆是两种可运行的选择，会得到不同结果。

柜内检查区别“杯碟都在柜内”和“杯叠在碟上”。锁柜前的空杯与锁柜后的满杯都可为真。检查器物说明才能把这一点和铃声联系起来。

### 输入仍是可编辑的行为假设

新增一次性任务句式及参数化组织器：借用并归还、替换并暂放、按记忆或重新检查收布、叠放或分开收存。任务展开为同一组实际查看、行走、拿起、放下、倾倒行动，不直接赋值终态。玩家可任意选人物、触发通知、物品、用途和暂放位置；没有一键填入参考答案。

原有 `当…，则…` 自由规则仍可输入。相同通知下、相同主观状态的相同规则不重复空转；认知发生变化或新通知后可重新响应。通知任务执行一次，不需要手写循环。两种形式可共存。

铃声在通知下的任务实际结束后发生。顺序来自公开值日记录，不再存在隐藏的40/110/180秒数考核。五个可听到的触发为准备、第一声铃后、收布通知、第二声铃后、收柜通知。每份草稿仍从初态完整重演，修改不能锁定此前已经满足的证据。

### 反馈

全部已知差异可展开；中途明确为截至当前的检查。未调查关键材料时不宣布整案成功。可交互物使用名称/检查标记，不用答案箭头。支持定位差异首次出现的帧，重演不制造现实证据。

## 房间与Core

公共研究室有独立的Space Essence。地点/家具归属于它，杯子经茶碟、桌面、柜子形成承托链；持有时归Holder。位置唯一存于现有SpatialProperty，TeaState.Support只是兼容访问器，不再另存一份位置。WorldRuntime现实投影同步得到Parent/Children。

Godot TileMap负责装修、碰撞、绘制和遮挡，不把每一格变成Core对象。当前地点节点仍服务于房内寻路，并非已完成通用家具编辑器。主体认知经Observation维护，房间的客观子物品树不会自动变成角色可见清单。

Core的现有空间查询并不自动遍历任意深度的家具承托链；当前茶案用游戏层的SiteOf解析可到达地点。父子投影同步已经接入，但不能据此声称Core全部通用动作都已支持嵌套容器取用。Godot节点树也不必与这棵逻辑归属树逐节点一致。

## 实现验收与边界

独立检查覆盖：参考完整解、另一人搬送最终空杯的合法解、重新查看避免泼洒、分开收存导致无法续茶、直接泼茶无法生成拖痕、茶量守恒、非法配置整体拒绝、Core空间归属同步、全部交互点可达。

目前通过的第二解只改变最终空杯的搬运者，不能据此宣称已经实现“主要移动茶碟”的整条替代路线。行为组织器也仍是本案的有限动作组合，不是任意自然语言理解；须由盲测判断它是否只是把写程序变成填表。

这仍是原型，不以“编译通过”证明好玩。第二轮使用没有读过答案的新代理盲测，关闭路线指引，记录它形成哪些认识、尝试哪些方案、在哪些地方仍像编程。AI工具耗时不等于人类游玩时长；若只是通过模板快速填空，也不能宣称已形成十到三十分钟的推理体验。

## 第二轮实际结果

新玩家独立取得杯底、茶用途及换杯材料，通过组织器写出三条假设，首次完整重演留下四项已知差异，尚有七项关键材料未调查。本轮在首次运行与证据对照后收尾，未通关；没有测试收齐线索后的第二次提交，也未独立验证自由文本输入。玩家肯定茶流与杯子身份的联系，但仍把行为录入感受为配置事件。不能宣布“编程感”已解决。

其遗漏椅布的可发现性问题得到复核：原检查标记画在父节点，被TileMap覆盖。盲测后将它移至独立高层Line2D；明确显示默认人物及组织器中的人物姓名；删除主界面没有必要的内部行动时刻（玩家误读为分数）；差异文案只描述缺少的椅布痕迹，不直接给出抽布过程。后续修复使用单独有头检查，不追溯改写盲测结果。
