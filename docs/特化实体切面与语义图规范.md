# 特化实体切面与语义图规范

## 商业领域实体组件与属性图体系

在现代工业软件、企业级知识图谱与商业游戏引擎（如 Unreal Engine ECS / Gameplay Ability System、Neo4j 属性图平台）中，实体与属性建模普遍经历了从单体继承向解耦架构的演进。

### 工业化架构标准

现代商业系统中的主流实践分化为两类成熟体系：
- 集中式属性图（Labeled Property Graph，如 Neo4j、Amazon Neptune）：实体以唯一标识符（GUID / String ID）索引，所有属性与关系均以动态哈希表或外部图拓扑的形式集中存储，查询依赖图遍历引擎。
- 实体组件架构（ECS / Actor-Component，如 Unity DOTS、Unreal Gameplay Component）：对象作为空壳容器，通过挂载异构组件实现功能扩展，广泛应用于实时渲染与物理仿真。

商业引擎在处理高频游戏逻辑时，集中式图数据库存在序列化与查询延迟，而纯扁平 ECS 组件系统在处理多层嵌套上下文与语义关系时又缺乏表达力。

---

## 本系统特化设计

本系统将商业组件模型（Component Pattern）与语义本体理论融合，演变为实体宿主直接内聚的强类型轻量切面（Facet）架构。

### 强类型切面绑定机制

实体通过直接内聚的强类型切面引用持有具体的语义能力：
- 实体作为物理与语义宿主，持有类型化切面容器，消除外部中央图数据库的寻址中介。
- 外部交互与物理规则查询特定能力时，通过编译期强类型或模式匹配直接提取切面对象引用。
- 杜绝运行时字符串哈希查找与间接字典跳转，确保纳秒级内存访问性能。

### 场景拓扑与语义切面的正交分层

系统将空间定位与能力语义进行正交解耦：

`
[场景树与通道拓扑 (TreeMember / Passage)]
                   | (空间层级与连通)
                   v
            [实体宿主 (Entity)]
                   | (强类型语义切面挂载)
                   +---> [容器收纳切面 ContainerFacet]
                   +---> [锁闭空间切面 LockFacet]
                   +---> [认知信念切面 BeliefFacet]
                   +---> [交互承载切面 AffordanceFacet]
`

- 空间关系由世界树和拓扑图维护，语义能力由直接持有的切面维护。
- 查询操作严格在实体局部展开，兼具面向对象引用的性能与语义网络的表达力。
