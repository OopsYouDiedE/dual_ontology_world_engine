# Illustrations 场景审查（打样前盘点）

本表保留打样前基线，不作为当前缺陷清单。2026-09-23 已新增[宣传前三场打样](../godot_csharp/scenes/Story/README.md)、对应九名角色v2基础动作、TileMap装修及统一Dialogue界面；下表前三场“暂无运行时动作”等旧状态已被这些实现取代。端盘、取食等专门表演与最终艺术验收仍未完成。当前仍成立的问题另见[当前问题](current-issues.md)。

审查范围：`godot_csharp/ShareAsset/Images/illustrations` 中现有分镜 PNG 与 prompts 文档、当前学园设定、设计与验收规范、宣传片要求、Shot01/02 场景文件、人物 v2 图集说明及 Victorian TileSet。本文是资料审查，不代表镜头已成为可玩片段、美术成品或年代考证完成。

## 总体判断

- 设定的时代是二十世纪初；可见分镜的学院石材与木家具、铜/黄铜器件、图书馆、钢琴、餐桌、纸质记录、仪式空间总体方向相容。宣传设定要求学院哥特复兴/历史主义建筑并结合朴素工业科研设施。现有画面多为室内，无法据此验收岛屿、砖石主楼、板岩屋顶、海洋/火山环境等整体身份。
- **所有分镜提示词把地图格写成48px**，而当前规范和运行时地图是32×32px；提示还描述48px角色宽、64px高。应将其视为概念图的错误规格，不可按原图尺寸直接重建。角色生产规格是32×48帧；当前 v2 扩展承载格64×64，但正常人形约43px高，锚点(32,55)。
- 21名角色已有正面站立身份帧，但不是运行时动作全集。当前 animation_v2 只有侦探和灰色占位人物的通用动作图集；其余正式角色缺运行时动作，不等于缺角色身份设计。职业器具按场景任务取用，不作为常驻身份标记；职业也不等同神秘能力。
- 分镜图是静态首帧参考。宣传标准要求机制片段有实际输入、规则结算、可见结果、失败/重试和回到可操作状态；单张图不能证明片段完成。本轮多数镜头按剧情演戏处理，只有明确展示规则结果的镜头才归机制：06/07言灵成败、09/10阵法错误与纠正、13/14推演操作、19/20通道规则、24/25封印与反制。02早餐、18真名发现、23对峙按演戏设计，不额外扩写成机制展示。
- 房间可按“TileMapLayer装修 + 房间内 Sprite2D 子物件”组织。Shot01/02 已采用地面、墙面、踢脚线、地毯 TileMapLayer，家具/角色等为 Sprite2D；当前 Sprite2D 只是摆景，不自动获得交互语义。核心房间属性能否直接承载这些关系，需实现者依据当前 Core 源码确认，本文不推定 API 或新增重复数据类。

## 正式角色身份帧与缺动作汇总

项目已有21名角色的正面站立身份帧。现阶段缺口是可用于Godot表演的角色动作资源：animation_v2只有侦探与占位人物两套。侦探已有idle/walk/talk/inspect/interact/sit/break/cast等通用动作，不应再列作“缺运行时动作”；场景仍需补其特定表演组合或特殊动作帧。其他出镜角色依据身份帧补动作，不需重新设计成“正式角色”。

按分镜出镜角色汇总（侦探已有通用动作，其余角色已有正面身份帧但需补动作）：厨师、自然学家、工程师、诗人、音乐家、舞者、棋手、盗贼、律师、画家、恶魔、考古学家、化学家、导师、神射手、建筑师、医生。身份站帧已存在，制作动作时保持既有服装、轮廓和道具规则。优先动作族：坐姿/起身、递取餐具、讲述与倾听、弹琴/演奏、落子、书写/翻阅/拓印、指示与观察、纠正、惊惧/救援、射箭或舞蹈训练、对峙与手套整理、各锚点操作。超出标准动作的表演另制专用动作，不把职业器具固定画进待机帧。

分镜资产缺号：现有PNG为01–10、12–14、18–23、26；11、15–17缺图，24和25也缺PNG，只有 prompts-18-26.md 中的文字提示词。提示词不能当作已完成分镜或资源验收。

## TileMap 与房间子物件盘点

Shot01 与 Shot02 场景已具备 `TileMapLayer` 地面、墙面/踢脚线和地毯；适合作为装修与地面布局的技术样板。场景中钟、拱门、长桌、食物、橱柜和人物使用Sprite2D等节点分层摆放。两场景尚是摆景；须逐个确认有交互要求的对象是否有真实交互逻辑、占位、遮挡和通路。

Victorian资源存在 `godot_csharp/ShareAsset/Victorian/tilesets/Victorian.tres` 与大量源图/动画家具，可作为可用性候选库，但其素材名称和资源存在不等于适配本项目：源包48px切片不得直接当32px地图格，逐项核对授权、源尺寸、接缝、透视、遮挡与最终节点比例。尚未发现每张illustration已有对应TileMap场景；Shot01/02以外的镜头应视为缺少已验收的房间装修TileMap。

按房间复用优先安排：Shot06/07同一教室；09/10/12同一仪式实验室；19/20同一铜管走廊；23/24/25同一核心隔离舱（25镜若剧情选择需换机位仍共用装修）；03/05/21可复用公共娱乐室/计划桌区域；其余按场景需求单独建装修。门、桌椅、乐器、书本、档案、阵法锚点、铃、棋盘棋子、器皿、钟、广播装置等可交互或可遮挡物件应是独立Sprite2D子物件。墙、地面、连续装饰和不可独立交互的建筑表面进入TileMap。

## 叙事与对话打样结论

- 以 Dialogue Manager 脚本承载大部分演戏是合适的：对白、短停顿、角色轮流反应、条件分支与结束后回到可操作状态都可由剧情系统表达。现项目包含Dialogue Manager插件及C#桥接，但本次检索未发现Shot场景已有剧情脚本接入或统一自制对话框。
- 不要让对话脚本代替状态结算。Shot01/03/04/05/08/21/26可先按剧情镜头设计；06/07言灵、09/10阵法、13/14推演、19/20通道规则、24/25封印与反制属于机制结果镜头，须由场景/机制产生结果，再由对白呈现角色如何理解。02早餐、18真名发现和23对峙按演戏表达。
- 打样建议先用Shot01：已有TileMap装修、中央厅摆景和侦探的通用运行时动作；增加短剧情脚本（侦探进厅—观察时钟/远处同伴—一两轮对白或旁白—结束并恢复移动），不引入新机制。按实际需求组合侦探walk/inspect/talk，音乐家已有正面身份帧但缺运行时动作，需补最低限度idle/turn或暂不让其承担动作演出。
- 对话框需契合克制学院气质并让场景仍可读：建议深石墨蓝/暖黑底、细黄铜边、纸白正文、说话者名牌、简洁继续提示；尺寸和安全区按实际游戏窗口测定。完成条件是文字不压住人物/可交互物、长句可读、键盘/手柄/鼠标推进一致、结束后输入回到房间操作。仅为审查建议，未制作视觉样稿。
