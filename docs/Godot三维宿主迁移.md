# Godot 三维宿主迁移

2026-10-27 已把正式 Main 入口的世界显示、人物模型、近场碰撞和导航接到三维宿主；但是完整迁移验收仍在进行，资源覆盖与已走通路径分别记录。

## 已实现

`Content/world3d.dv` 声明 70 个房间的三维场景映射、镜像、门洞和新增家具位置，C# `DvPresentationContent` 读取声明；但是既有二维坐标仍作为 DV 会话和地图合同的兼容坐标，不是三维物理测量值。

`WorldStage3D` 装载正式房间、地板、家具、灯光和相机，`StoryBody3D` 使用 CharacterBody3D、胶囊和真实静态碰撞体运动；但是各房间目前使用独立物理区域及正式授权的门口转换，不是整座建筑连续无缝的单一网格。

用户提供的 17 个 GLB 已通过 `character_art.dv` 接到人物身份并替换正式入口的角色显示，导入保留整个模型层级、蒙皮和骨骼，统一整体缩放和脚底位置；这 17 个文件均带蒙皮骨骼，并含 `afraid` 片段，个别另含 `agree`；但是模型没有所需的完整行走、坐起或交互动画，本轮保留原始静态姿态，不把位移和整体转向称为动画完成。

`StoryActor` 与 `CampusMapView` 保留逻辑适配职责，正式身体取消二维碰撞和精灵显示，位移通过三维身体测量后回写；但是旧地图节点仍隐藏加载，以兼容房间身份、门禁、UI、证据位置和正式会话协议。

`DvFieldExecutor` 保留身体实例、站位占用、源站位预留、失败回滚和隔离视口，真实三维运动回执包含身体实例与三维位置；但是远处 NPC 的既有 RoomGraphMotion 仍单独标记为房间图执行，不能当作 Godot 物理运动覆盖。

房间站位从真实地板和障碍物采样，人物间距按三维距离检查，导航根据实际碰撞建立网格，门洞按正式连接重新导出，屏幕拾取使用三维射线；但是可达性须由每条正式路径验证，生成导航网格不等于所有路径已经走通。

## 相机与遮挡

相机近裁剪面 0.05 米、远裁剪面 1000 米，关注点跟随三维人物，`rendering/CameraOcclusion.gd` 使用视图独立材质副本；但是这些是配置值，没有形成性能测量结论。

共用 Shader 使用 Bayer 点纹阈值形成相机到人物之间的渐隐窗口，覆盖登记的墙、屋顶和天花层级，保留原有表面材质；但是渐隐不改变物理碰撞、门禁或人物认知，未接共用材质的外部表面不自动获得此效果。

房间沿用原有环境及 DV 时间灯光，在兼容渲染器下真实运行；但是 Forward+ 专属的 SSIL 会报告不可用警告，不能据此声称间接光效果已启用。

## 覆盖与证据

21 个逻辑地图共有 120 条房间记录，去重后的 70 个三维场景已重新导出并接入统一映射；但是 `artifacts/3d-migration-2026-10-27/room-coverage.json` 是资源清点，不是 70 个房间的逐一实机验收。

正式 Godot AI 新局已实际完成卧室 R-05 → 宿舍走廊 → 活动厅，并取得无宿主错误的观察回执，`ai-formal-hall.png` 和同名 JSON 是真实游戏画面与回执；但是这些图片仅证明拍摄时的场景，不能代表第一、二章通关或最新修改的全部覆盖。

正式 Godot 自动测试保留各次报告与失败诊断，迁移中已定位人物占位、门框和门厅鞋凳阻挡等问题；但是截止报告只记录停止前实际进度，`host_errors=[]` 不意味着行动全部成功。

CLI 正式自动回归独立运行并保留报告；但是 CLI 结果不能验证三维渲染、碰撞和相机。

## 尚待验收

后续验收覆盖公共大厅、室外与其他分区过渡、第一二章交互以及人物多种动作；但是本轮用户要求先展示现有静态模型，动作资源缺失须单独记录，不能用拆分肢体或伪造完成状态补足。
