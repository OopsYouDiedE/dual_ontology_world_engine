# 五日原型的运行机制

正式声明入口为 `assets/data/scenarios/campaign.dv`；五日共用同一个 `RuntimeSession`，世界事实、人物认知、证据来源、资源和机制历史跨日延续。后日文件里的 `knows` 不会倒灌到第一天，后日所知须由观察、感知、交流或证明取得。

## 日常驱动与意见采纳

`DecisionScheduler` / `DriveCalculator` 负责人物日常行动：从本人已经认识的行为中，按需求、目标、情绪和 Buff 评分。新认知会使相关候选优先进入有界候选集合。客观世界的门槛不提前替角色筛掉失败选项；实际执行仍须通过现场检查和共享交互位的原子占用。一本登记簿、一个水槽和一份库存各自保持独占，食堂长桌则有明确的六个共享位置，不能把整张桌子当成只容许一人使用的物品。

候选评分使用有限的 CPU 切片，同一轮尚未完成的评估通过 `HasPendingDecisionWork` 告知宿主，评估期间世界时钟不前进。时钟也会停在下一次正式决策时刻；CLI 与渲染宿主的帧长不会变成额外的救援等待或毒剂暴露。评分器保持人物轮转顺序，只要还有实际候选工作，就可以在同一切片内继续轮转，直至达到评估次数、耗时预算或一次完整的无工作轮转。没有可执行行动的评估仍会扫描完有限候选，并按声明的间隔安排下一轮，不会永久阻止时间推进。Godot 在收到 `decision_pending` 时继续有限地处理零时长切片，保留每帧工作预算。

`RuntimeMechanics.EvaluateSuggestion` 使用另一套人物 `opinion` 参数，独立计算建议是否被采纳。意见分数由说话者信任、实际已知证据、受建议者的价值倾向、成本、风险及其本人知晓的现场条件组成。日常行动分数不进入这个计算。

针对某个说话者的既有疑虑由可选的 `modifiers[].speaker` 限定，并依赖受建议者本人已知的依据。共同晚饭的关系改善不会覆盖具体疑点；不在场的人也不会直接获得那次谈话。`public_completion_text` 只在行动真实完成时交给实际同场的听众，带说话者和证据来源；普通 `completion_text` 仍是行动者自己的记录。

```json
{
  "opinion": {
    "base_trust": 0.2,
    "threshold": 1.55,
    "evidence_weight": 0.4,
    "cost_aversion": 0.6,
    "risk_aversion": 1.2,
    "values": { "duty": 1.4, "fairness": 1.1 },
    "trust": { "detective": 0.3 },
    "modifiers": [
      { "when": { "airlock.lock.sealed": true }, "score": 0.8, "reason": "已见安全通口成立" }
    ]
  }
}
```

建议声明置于普通行动内；`when` 属于行动者认知门槛，`requires` 属于实际现场条件。`appeal` 每维在 −1 至 1 之间，`cost` / `risk` 在 0 至 1 之间。

```json
{
  "suggestion": {
    "target": "ward",
    "evidence": ["detective.infer.dual_ration", "detective.infer.granary_cooperation"],
    "appeal": { "duty": 0.7, "fairness": 0.7 },
    "cost": 0.2,
    "risk": 0.05,
    "result": "ration.doc.ward_accepted"
  }
}
```

拒绝不会消费一次性行动，也不会提交它的成功效果。建议中的证据及其来源会传给收件人；接受或拒绝本身是双方可以观察的事实。完整作者审计保留各项贡献、阈值、缺少的证据和真实结果，受建议者也能查自己的评估。提议者只得到实际答复和自己出示的证据，不能通过来源详情或机制历史读到对方私有的分数、阈值、记忆和顾虑；进一步解释须由对方真实说出。

## 侦探的任务路径与生理路径

`detective-planning.dv` 为侦探声明有限的任务依赖图。任务的解锁条件、目标和步骤完成条件都读取本人认知，步骤引用正式行动；依赖必须无环，不能引用未声明的动作，也不能预先写入未来案件事实。`TaskPlanner` 只把已经完成前序步骤的行动放到任务前沿，再核验当下认知与现场可执行条件。当前任务、已完成任务集合、已完成步骤和被身体需要打断的任务随存档保存。本人已经知晓达成的任务会锁存完成，离开目标房间不会使到访任务重新出现。

生理路径独立读取精力、饱食、水分等声明的需要，使用临界阈值和较高的恢复阈值避免反复切换。它只按实际改善身体需要的贡献选择可用行动，任务奖励、社交动机与意见采纳分数不混入生理收益。紧急需要可中断任务，恢复后续接已有进度；如果任务暂时等待现场变化，可先执行当前可用的身体照护，再继续日常判断。

首要紧迫需要暂时没有合法恢复行动时，可以处理另一项已经低于临界值且确有恢复途径的需要。例如尚未开饭时仍能沿已知路线取水。原本的饥饿状态和恢复阈值继续保留，实际选中的需要单独随决定及检查点保存；喝水不能被记成已经解决饥饿。

饮水路径使用真实已知的 R05 水壶，支持原地饮水及从已到达调查空间出发的有限往返。出发、饮水和返回都是普通正式动作，逐步检查认知、位置、通路和实际需要；一份水的恢复量不足时，只能再次执行仍合法的饮水动作。真实完成回执确认恢复后，计划还须走完返回步骤才续接原任务。实际出发记录返程地点，返回后清空；玩家不会在卧室里看到通向所有未访房间的常驻选项。手动选择路线首步会登记本次行程，后续步骤仍由玩家选择；改做别的行动会明确记作中止。近期 16 份往返回执包含原任务、需求前后值、恢复时刻与执行来源，预览建议单独标为尚未出发。

实际派发的每个动作保留 `Decision.Intent`，包括当时选择的路径、任务、步骤、需要及理由。`player_paths` 是玩家可读投影：手动接管时只给建议，不提交动作、不自动选择推演证据。查询建议会在临时规划状态上计算，最后恢复原状态；打开案卷或自动验收中的观察频率不能写入任务中断、完成或调度选择。

`active_intent` 直接读取本人正在执行的原始决定，实际完成或失败的 `ActionReceipt.Intent` 随本人日记保留；界面和正式观察中的近期行动使用这些真实字段显示当时为何行动。空闲时显示“当前建议”。旧记录没有行动意图字段时保持未知，不能根据后来看到的建议补写路径。

第五天进入声明的开放阶段。`task_guidance_until_game_minutes` 在时间边界停止任务前沿，保留身体需要规划与普通驱动力评分；界面通过 `CampaignProgress` 的阶段字段隐藏任务进度、阻碍和任务推荐。此后不存在需要依次完成的第五日调查列表，前四日已经发生的物资变化、伤情、认知和关系继续有效。

## 自身目标求解与受挫记忆

`GoalPlanning` 提供两种有界求解器：`best_first` 按累计行动代价扩展候选，`beam` 在每层保留一批价值较高的方案继续搜索。`GoalPlanningAdapter` 只向它们提供行动者实际保有的事实、已经认识的行动模型和当前成立的个人目标。DV 的 `goal_planning.goals` 用 `when` 声明目标准入、`target` 声明本人想达到的结果、`weight` 声明其价值；`planning_model` 明确列出本人预期的效果、耗时成本与不确定性成本。未声明的世界执行效果不能直接拿来预测。

预测是在临时认知副本中完成的。角色可以预期别人答应请求，但所有建议模型必须承担正的不确定性成本，执行时仍调用对方独立的采纳判断；预测中的同意、库存和交接都不能写进真实认知。当前实际候选只执行所选方案的首步，取得新证据、受阻或被拒绝后重新评估。未来尚未开放、已经过期和仍在冷却的动作，在整个预测序列中都受到限制。任务路径、紧迫生理路径、个人目标和普通需求评分保留各自的来源。

两种算法采用相同的本人知识和行动模型，`compare_algorithms` 可以保留另一算法的只读结果，方便比较实际行动序列、预期目标、累计代价和展开数量。默认预算为深度 6、展开 512、束宽 20；达到预算会留下明确状态，不能声称已经证明全局最优或无解。完整作者审计保存预测依据，玩家只看到自己的实际行动意图，其他人物的私有目标和布局不进入公开观察。

动作可用 `recognize_when` 区分“认识这个做法”和 `when` 所表达的“预期条件具备”。不声明时沿用原先认知门槛。认识一个配方之后，原料不足可以使其第一次尝试失败；客观 `requires` 仍会阻止资源扣成负数或产生虚假成品。一次性完成位和已处理请求的锁定仍适用于行为认识门槛，不会因新增准入而重复兑现成果。

`ActionFailureMemory` 记录实际失败次数、原因、当时本人知道的相关阻碍和扣分。扣分压低下一次选择，不抹去已知动作。若本人明确知道缺少材料或未满足某项条件，记作 `evidence_change`，直到相关认知确实改变才解除扣分；再次看见同一个空容器不能让失败记忆消失。尚不清楚具体阻碍时默认等待 45 个游戏分钟再查，并随连续失败延长；瞬时交互位争用采用 1、2、4、8 分钟的短退避。远处未被观察的变化不能替角色解除记忆，资源占用失败也不因无关库存更新而被忘掉。恢复、重试和成功清除记录都保留审计与存档状态。

可预期的现场阻碍记作 `blocked_attempt`，保持原始失败原因、`Committed=false` 和零成功效果；独立拒绝、缺证推演、异常效果或不变量失败分别保留各自分类。五日时间完成、实际动作成功、受阻次数和剧情条件通过是不同统计，不能互相替代。

`campaign.dv` 的 `shared_sources` 合并复用 DV 声明，可用 `days` 指定应用于哪一天。`daily-life.dv` 及按人物组织的 `life-*` 片段只在首日组合一次，日常动作依据本人实际醒来、空闲和进餐的记忆准入，避免上一天的空闲条件持续占用救援阶段。`open-day5-*` 和 `social-schemes.dv` 在第五日组合，仍继承前日事实而不重置需要。片段只组织真实声明，不在运行时生成预定故事结果。

## 开放日的资源与观察边界

开放日的行动仍由 DV 声明位置、本人所知条件、实际现场条件、占用、作业时间和效果。共享的水、食物与敷料通过同一事务中的数值增减处理，完成时再次核验数量与现场条件；携带者须实际移动后才可投送，护理也会占用照料者和患者。成功后的冷却由运行状态保存。只有真实在场且可感知的字段发生变化，人物才重新收到相应观察；离场者不能直接读取远处库存。

任务、身体需要、个人兴趣和意见采纳各自保留作用范围。不同人物可以竞争同一份资源，选择补给、帮助别人、休息或处理自己的事情；建议被拒绝时，成功效果不提交，其他合法替代仍可用。内容不预先写入“涌现成功”事件，也不要求水、做饭、护理按固定全局顺序发生。

库存分别归属实际房间。食堂与热厨各自感知和使用本地的干粮、热食与水；人物要先取得物品、实际走到另一间房，再交付入库。离开房间后保留的库存印象可能过时，不能直接读取远处现值。患者对自己的请求与缓解感受有明确的自我感知来源；其他人物只能通过在场观察、记录或交流获知相应信息。尚未交付物品时，普通帮忙候选不能反复领取同类物资，正常投递、照顾身体和休息仍可选择。

食堂热食分成两个实际事务：盛餐只短暂占用公共库存，将一份食物转入本人的 `served_meal`；进食占用本人，吃完才消耗这一份并恢复饱食。尚未吃下不能提前获得营养效果，也不再让一个人的整段用餐时间锁住所有人的饭。日常饮水依据本人清醒、已知路线、缺水与安全条件选择；已经开始的饮水返程依赖实际出发记录和饮水结果，不能因为主线阶段变化而失去回去的行动。

同桌交谈等开放机会可以在执行期间消失。DV 用 `interruptible_opportunity` 明确声明机会丧失条件；只有执行到正常结算、时间与认知仍合法、现场条件明确不成立且没有提交效果时，Core 才附上可恢复中断说明。原回执仍为 `Committed=false`，保留原原因；公开记录只显示“现场机会变化，行动未完成”，私有审计才保存具体世界依据。推演缺证、意见拒绝、资源错误和其他未声明失败各自保留原分类，不能混成成功。自动报告分别统计真实成功、可恢复中断、拒绝及其他失败。

`completion.mode=observation_window` 明确指定观察截止分钟，Core 在真实时钟切片处截断推进，结算截止时已经到期的回执，此后不派发新动作。Godot 读取同一个 `CampaignProgress`；观察窗口结束只表示五天时间范围完整，不自动判断剧情质量或自主交互是否成功。传统事实完成模式仍要求非空的完成事实集合，不能利用空集合使新局立即完成。

## 一次一间房与导航时间

`CampaignRoomHost` 每次只实例化当前房间。Godot 根据该房间真实碰撞体烘焙导航网格，侦探及同房 NPC 都必须沿实际可达路径接近目标。焦点缺失或通路受阻会取消到场，不会以人物当前位置替代缺失家具。脑内活动和显式的本人行动可以原地进行。

首次实例化住民时，声明的地面锚点须通过真实导航路径连到可见房门；默认站位若投影到椅面、桌面等孤立表面，就从附近寻找同一地面通路上的合法出生点。路径同时检查起点与终点，找不到有效锚点则明确停止加载。这个检查只决定房间加载时的真实站位，不在行动中传送脱困；整张导航网格、楼梯和讲台等合法高差保持可用。

开始动作时，Core 的空间阶段保留执行 ID、来源房间、目标房间和导航权威。当前房内的接近时间由 Godot 实际物理移动提交；这份时间与尚未模拟的加速预算分开，不再乘工作或睡眠倍率。Host 先记录实际位置和剩余路径，耗尽已发生移动对应的物理时间，再向 Core 报告到达；Core 同时检查执行仍有效、房间一致、注册目标的实际距离与现场条件。到达之后才开始动作本身的作业耗时。

开门时用短暂遮罩承接跨房间行程。遮罩期间没有室内模拟，Core 按正式路线耗时处理人物与世界事件；Host 只消耗剩余行程预算，收到该执行的真实完成回执即停止。随后释放旧房间及导航图，加载目标房间，在其真实门的可达站位落脚，再揭开画面。入口回执区分请求的门侧与实际采用的门侧；缺少有效门或入口通路会明确报错。过渡期间屏蔽游戏输入，观察和正常关闭仍可用。

在房间卸载时，尚未走完的同房 NPC 导航按真实剩余距离与速度交给 Core；加载时尚在接近的动作交回 Godot，已经开始的作业保留既有剩余时间。高倍率可以加快展示，但人物的视觉移动和物理时间使用同一个有限倍率。`physical_observation` 保留当前实际位置、入口、加载房间数及近期导航记录，供正式实机验收检查，不提供传送或事实修改入口。

## 主动脑内推演

推演声明复用 `CaseTheory` 的有符号 Horn 证明器。每张证据卡绑定人物实际记忆中的条件；未知或有冲突的事实不能成为前提，未见过某事也不能自动成为其否定。规则至少包含一个真实前提，整个推演至少声明两张不同证据卡和一项结论认知。

```json
{
  "deduction": {
    "title": "鞋印与袖口共同指向拖回动作",
    "evidence": [
      { "id": "shoe", "when": { "B_foyer.trace.shoe_vector": "向内" }, "label": "向内鞋印" },
      { "id": "sleeve", "when": { "su.trace.sleeve_vector": "向内" }, "label": "袖口拖痕" }
    ],
    "rules": [
      { "id": "combine", "all": ["shoe", "sleeve"], "then": "drag_supported", "label": "两项方向一致" }
    ],
    "conclusion": "drag_supported",
    "learns": { "B_case.infer.drag_direction_supported": true },
    "qualification": "动作方向得到支持，动机仍未知"
  }
}
```

`DeductionPreview(actor, action)` 只展示该人物已经知道的卡片内容和来源；未知卡片不泄露其命题值。玩家通过 `SubmitDeduction(actor, action, evidenceIds)` 选择实际已知卡片。AI 使用自己当前知道的证据。缺证时，证明器返回未证实，认知、世界结果及一次性完成标记均不提交，玩家可以补证再试。成功时，`LastDeduction` 记录证据 ID、观测来源、规则应用、证明树、理论哈希及结论边界；`learns` 只更新主观认知。其他人物须通过真实交流才能获得该结论。

## 言灵

言灵需要先取得指定认知，并实际消耗资源、承受反噬。它暂时改写一个已声明世界字段，既可影响物理条件，也可被 NPC 观察后影响其意见判断。

```json
{
  "incantation": {
    "formula": "闭合之门，不纳污息",
    "requires": { "detective.infer.safe_airlock": true },
    "resource": "detective.phys.resolve",
    "cost": 12,
    "backlash": { "field": "detective.phys.corruption", "amount": 3 },
    "rule": { "field": "airlock.lock.sealed", "value": true, "duration_minutes": 45 },
    "witnesses": ["huo", "quer"]
  }
}
```

资源、反噬、规则字段必须互不相同，费用、持续时间与反噬量须为有限正数。资源不足或认知缺失会失败。到期时恢复此前世界值并产生真实到期回执；中途存档与加载保留到期时间。施术者获得自己的资源和反噬反馈，见证者只获得其可见的规则变化。

## 策略和自然事件

第二天的四院巡检由实际行动链完成：专业人物完成原岗位工作后，读取中翼路线牌，沿真实拓扑进入所属院室，调查对应家具，返回中翼签署报告，再回原岗位。报告事实只能由已经完成现场调查的人物写入。侦探可亲自走完四室，把四份现场证据、四份签名报告、接驳图与封签清册共十项来源交叉证明。风窗关闭后的报告路径只使用六项已知文书来源，明确记作转述依据，不写入未见过的四项现场认知；院内返程始终可用。初始世界声明变化要求正式新局。

`strategy` 行动把每个方案的本人所知条件编成实际可证明前提，再由 `StrategyActivity` 分摊计算并比较收益。D2 的探针、药卷与口粮方案，以及 D4 的锁门、盘查与值守方案都使用此机制。谋划结果保留在人物自己认知中；剧情只有通过后续真实行为或观察才能向侦探揭示。

```json
{
  "strategy": {
    "output": "ruan.plan.selected",
    "publish": true,
    "options": [
      { "id": "probe", "label": "借走探针", "when": { "probes.phys.owner": "quer" }, "utility": 17, "basis": "本人已经核对持有人" }
    ]
  }
}
```

顶层 `world_events` 声明时刻、客观条件与实际变化，适用于微震等非人物行为。跨日合并会偏移事件时刻并使 ID 唯一。

```json
{
  "world_events": [
    { "id": "microquake", "at_game_minutes": 1050, "writes": { "island_environment.phys.earthquake": true }, "tell": ["detective", "huo"] }
  ]
}
```

## 持久化和正式验收

`RuntimeSessionState` 版本 4 包含机制、规划与空间检查点，并保存动作冷却和待排出的真实效果记录。它同时保存推演选证、机制回执、临时规则租期、已触发自然事件、策略活动、任务进度、生理中断、导航权威以及两份独立时钟预算。恢复时检查人物、动作、资源、运行中的执行和声明兼容性。改变人物、物资初值或任务定义要求正式新局，不能靠改存档接入。

原生宿主的存档外层版本 2 还保存内容指纹与源码归档摘要。每份实际使用的内容版本只保存一次压缩源码合同，按内容指纹和归档 SHA256 双重寻址；存档无需重复嵌入剧情原文。旧版存档只接受项目正式发布的原内容归档。加载器会重新解析归档中的 DV 并重算指纹，再比较新旧声明，不能通过 `allowContentChange` 跳过校验。

当前兼容范围限于沿既有路线增加可重复的 `manual_only` 导航动作，以及收紧非在行动作的准入条件、修改行动显示文案和追加验收项。新增导航只允许改变并观察执行者自己的房间，不得新增世界初值、一次性完成位、认知初值、资源槽或其他效果。既有人物、认知规则、自然事件、世界对象、行动效果、耗时和完成条件必须保持一致；正在执行或已经进入评分中的受影响行动会阻止更新。恢复在独立候选会话中进行，完整 `RuntimeSessionState` 与原存档结构等值后才原子替换，并留下 `content_update` 校验记录。未通过校验的内容更新须使用新局。

正式 CLI 与 Godot 主宿主共用 Core。完整审计用 `MechanicHistory` 记录 `time`、`execution`、`actor`、`action`、`kind`、`success`、`details`；玩家视图必须调用 `MechanicHistoryFor(actor)`，只返回本人记录及证据来源确认该人物已经获知的世界事件。同房 NPC 的内部策略、推演和私有行动 ID 不进入玩家历史，完整磁盘审计仍保留这些内容。前四日的剧情条件、核心机制实际成功、认知边界和交互位互斥须独立检查；开放阶段以实际人物行为评估，观察窗口完成不能替代这些判断。玩家接管时，侦探的 AI 候选评分不适用，搜证、选证、推演、言灵和独立意见的实际使用仍须核验。

Godot 私有审计使用有序的 `seq` 与明确的内容指纹，记录实际决定、候选评分、当时读取的认知及其证据来源。`action_effects` 记录真实 `World.Apply` 产生的字段前后值、字段版本和行动前后的身体需要；`evidence_received` 逐条记录新增证据，物理观察携带实际字段的版本，交流携带来源人物和证据 ID。关闭时写入完整计数，普通观察仅暴露审计路径、计数和持久化错误，不向玩家泄露 NPC 的私有认知。分析只能通过同一会话中明确的执行、字段版本或来源 ID 建立关联，不能用时间相邻补造因果，也不能把预设行动链自动称为涌现。

玩家事件记录按实际发生日整理，保留失败与重试，将同日重复生活动作归并显示，并可展开真实来源。Godot 公共日记保留最多 8192 项，记录被截断数量与覆盖起止；旧存档已经缺失的记录不会补造。CLI 同时输出简读文本及含原始行号、来源和覆盖范围的详细记录，原始追加日志继续独立保留。剧情生成的作者合同与文学转折评审见 `tools/story/`；静态作者检查和文学审读不能代替两个正式 Godot 五日运行。
