# 特化产生式规则专家系统规范

## 商业业务规则系统（BRMS）技术体系

产生式规则系统在现代软件工业与商业软件开发中演变为成熟的业务规则管理系统（BRMS，如 Red Hat Drools、IBM Operational Decision Manager）。其工程架构具备高度工业化的流水线分层。

### 工业化架构标准

现代商业规则引擎的标准形态包含如下核心组件：
- 规则知识库（Knowledge Base）：由高层业务规则通过预编译技术转化为可执行的模式匹配网络（如 Rete-OO 或 PHREAK 惰性求值网络）。
- 工作内存（Working Memory）：保存领域业务对象（POCO / POJO 实体）。引擎监听对象变更并执行增量模式匹配。
- 议程与执行上下文（Agenda & Execution Context）：维护满足匹配条件的激活规则队列（Rule Activations）。根据既定冲突消解策略依序调度规则触发。
- 事实断言与推论（Fact Assertion & Consequence）：规则命中（LHS）后，其右侧操作（RHS）直接调用实体 API 修改状态，或向工作内存插入新事实诱发链式推论（Forward Chaining）。

## 本系统特化设计

本系统的特化设计在于构建了 主观心理压力加权与客观世界法则阻断的双层分流机制，解除了传统规则系统非黑即白的硬性绑定。

### 双层规则求值机制

规则网络对同一套 AST 规则根据调用上下文执行分层裁决：

1. 主观心智决策层（心理规则压力）：
   - 在智能体心智决策阶段，规则评估不产生物理强制阻断。
   - Mode.Require：匹配时产生正向驱动压力（+100 + 优先级）；未匹配时施加负面违抗压力（-80 - 优先级）。
   - Mode.Forbid：匹配时施加负面抑制压力（-100 - 优先级）。
   - Mode.Prefer：提供偏好加权（+50 + 优先级）。
   - Mode.Permit：提供许可豁免（+20 + 优先级）。
   - 最终评分公式为  = Score_{RulePressure} + Score_{Utility}$。若违背规则的行为带来的外部效用极大，智能体能够顶着负面心理压力违抗规则，实现符合人性的动机冲突建模。

2. 客观契约与物理法则层（硬性法则阻断）：
   - 在言灵契约（Kotodama Contract）与客观物理判定阶段，规则作为客观世界法则生效。
   - 系统调用客观求值接口，若存在 Mode.Forbid 匹配或 Mode.Require 未满足，系统立即判定非法并实施硬性物理阻断（BlockedIntents++），拒绝事务上树执行。
   - 对于包含履约义务（Obligation）的契约，在客观效果发生时强制触发违约惩戒（Breach）。
