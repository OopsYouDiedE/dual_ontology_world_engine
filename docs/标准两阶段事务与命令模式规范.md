# 标准两阶段事务与命令模式技术规范

## 1. 概述与理论溯源

两阶段事务处理机制源自吉姆·格雷（Jim Gray, 1978）在分布式数据库系统中创立的两阶段提交协议（Two-Phase Commit Protocol, 2PC），并与 GoF 设计模式中的命令模式（Command Pattern）及游戏回滚架构深度融合。
在复杂的离散状态机和回合制游戏引擎中，一次复合行动往往牵涉多重实体状态修改、背包扣减与空间位移。两阶段架构确保复合变更具备强原子性（Atomicity）与隔离性（Isolation），彻底消除“部分成功、部分失败”导致的脏状态残留。

## 2. 两阶段生命周期模型

完整的事务执行周期严格划分为两个相互隔离的阶段：

```
[外部输入 / 动作意图]
        │
        ▼
   [Phase 1: Prepare 准备阶段]
   (无副作用检查、资源锁定、生成不可变计划 Plan)
        │
   ┌────┴────┐
   │ 成功?   │
  是         否
   │         │
   ▼         ▼
[Phase 2: Commit 提交阶段]   [Phase 2: Abort 中止阶段]
(原子性状态写入、广播事件)   (释放资源、清理临时视图)
```

### 2.1 准备阶段（Phase 1: Prepare）

准备阶段的核心准则是**纯函数性与零副作用**：
* **前置条件与依赖校验**：检查执行者属性、所需道具额度、空间访问权限与硬性规则约束。
* **资源锁定与虚拟占用**：若操作涉及排他性资源，记录锁定意向，防止事务并发争抢。
* **计划构造（Plan Generation）**：计算所有的状态变更增量，生成不可变的效果执行计划对象（EffectPlan）。
* **禁止操作**：此阶段严禁修改真实世界的内存对象、严禁推进时间轴、严禁消耗不可逆的伪随机数序列。

### 2.2 提交阶段（Phase 2: Commit）

当且仅当准备阶段完全通过且全局审查无异议时，执行提交阶段：
* **原子写入**：将计划中记录的所有物理属性、关系与所有权变更一次性应用到真实世界实体中。
* **状态持久化**：生成不可变的因果审计事件（Event），挂载执行时间、执行主体与实际状态差分。
* **后效触发**：事件生效后，触发外界观察者、监听器与后续级联反应。

### 2.3 中止阶段（Phase 2: Abort）

若准备阶段中任意一项校验不满足，或在提交前被外部硬规则拦截，触发中止流程：
* **全量放弃**：直接丢弃已生成的执行计划对象。
* **锁定解除**：释放准备阶段暂存的全部资源预留标记。
* **零污染保证**：真实世界状态未发生任何改动，无需执行复杂的逆向补偿逻辑。

## 3. 虚拟沙箱视图与状态隔离（State View Isolation）

为了支持对复杂连锁动作的深度预测与多步推演，系统引入虚拟状态视图（State View）：
* **隔离读写**：在准备阶段，所有读取操作首先查询虚拟视图中的覆盖记录，若未覆盖则回退读取真实世界；所有写入操作仅写入虚拟视图，不修改真实实体。
* **分支与合并（Fork & Discard）**：智能体进行可能结果推演时，从当前状态派生分支视图（Fork）。推演完毕后直接丢弃沙箱，不留任何痕迹。
* **连续预测**：后序效果可以在虚拟视图中读取前序效果的预测输出，实现诸如“先从箱中取药，紧接着服下该药”的连续声明式链式预测。

## 4. 事务计划消费约束

* **一次性消费（Single-Use Plan）**：生成的执行计划对象具备严格的一次性生命周期。严禁对同一个计划实例进行重复提交（Double Commit），避免造成资源双重扣除。
* **过期失效性**：执行计划依赖其生成时的世界状态基线。若在准备与提交之间发生时间推进或其他主体的干扰，该计划立即失效，必须重新进入准备阶段生成新计划。
