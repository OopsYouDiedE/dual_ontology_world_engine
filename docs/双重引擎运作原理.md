# 双重本体世界引擎：Core 现状

本文只记录当前 C# Core 中可以由源码确认的模型与入口。游戏设定、宣传片镜头和 Godot 场景不属于 Core 规范。

## 模型边界

`Essence` 表示对象的客观身份，`Projection` 表示对象在某个主体或现实层中的表现。`ProjectionWorld` 保存主体可用的投影、属性和观察历史；`ObservationEvent` 记录观察来源与时间。`Property` 承载状态、空间、通路、门锁、表面、规则和程序等可变机制。

Core 不负责房间内坐标、碰撞、实时循环、渲染或 UI。场景几何、可见性和交互呈现由游戏层提供。

## 当前入口

- `WorldRuntime`：持有运行时世界及投影转换入口。
- `SimulationSession`：管理行动执行过程与 `Pending`、`Completed`、`Failed`、`Cancelled` 状态。
- `ActionRuntime`：按 `ActionIntent` 准备并结算效果，返回 `ActionResolution`。
- `CTBSystem`：按离散行动值登记和激活延迟行动。
- `DecisionSystem`：根据候选效果、规则和主体投影生成 `DecisionAssessment`。
- `AstDecoder`：把文本表达式解析为类型化条件、效果和规则；解析结果仍需由调用方提供对象与上下文。
- `TemporaryStateProperty`：管理带到期时间的临时状态覆盖。
- `SocialSystem`：处理当前 Core 提供的社会姿态与评分数据。

## 行动与观察

行动以 `ActionIntent` 表达行动者、效果、延迟、要求条件和依据投影。执行阶段返回明确的失败原因，不能把游戏层的空间碰撞或 UI 行为伪装成 Core 结算。主体认知变更应通过观察入口产生 `ObservationEvent`；内部提交阶段可以直接应用已准备的效果计划。

规则由 `RuleMode`、条件、效果和权重组成，支持 Require、Forbid、Permit、Prefer 等模式。Core 可计算规则对候选行动的影响，但不替游戏层决定所有角色行为。

## 维护边界

核心实现保持独立 .NET/C#。Godot、TypeScript 或其他宿主可以把场景、输入、绘制和实时调度转换为 Core 可理解的对象、条件与行动。文档中的场景数量、角色数量、宣传片镜头和具体数值属于游戏层设计，不能反向视为 Core 已实现能力。
