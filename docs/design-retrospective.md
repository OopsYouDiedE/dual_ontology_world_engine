# 设计复盘与交叉讨论裁决

日期：2026-09-23。三个低成本子代理分别采用源码因果检查、资产引用与生产链检查、Git 历史与文档对照；主代理核查证据并主持两轮交叉质疑。本文记录讨论依据，执行规范仍以[设计与验收规范](design-standard.md)为准，不另立一套标准。

本轮是只读调查与文档修订，没有重新构建、运行游戏或进行美术验收。工作区已有大量未提交修改；当前文件、既有验证报告与 Git 提交历史分别取证，不能把所有工作区变化归因于某次失误，也不能把既有报告当作本轮复验结果。

## 已有证据支持的弯路

### 规格混用造成错误生产目标

[分镜审查](illustrations-audit.md)记录分镜提示词采用48px地图格，与当前32px地图冲突；[人物连续帧初稿](../artifacts/character-animation-v1/README.md)明确记载生成图不遵守画布、锚点与朝向。它们证明具体规格问题，不能据此说所有生成资产均不可用。

[v2资源说明](../godot_csharp/ShareAsset/Internal/Characters/animation_v2/README.md)说明当前64×64是透明承载格，人形约43px；这与32×48基础设计画布是不同维度。旧规范表格把“普通行走单帧画布”固定写为32×48，容易与同页v2说明冲突，本轮已明确区分。外部素材按源规格切片，缩放派生如实注明，不能改名为原生像素制作。

### 推理难度被执行器细节挤占

[第二轮设计记录](reasoning-round2-design.md)直接记录首轮问题：玩家写循环、调优先级、赶未公布的茶铃时刻，且未先跑通完整参考与另一合法路线。纠偏方向是把重复执行交给角色，把证据与行为假设留给玩家。

[独立盲测报告](../artifacts/tea-reasoning/round2-player-report.md)仍指出录入像配置事件、漏查椅布与柜子，并在首次完整重演后收尾。椅布标记被TileMap遮盖得到后续复核；柜体误点和部分点击失效未逐次重现，不能全部列为已确认程序故障。此轮没有证明整案不可解，也没有证明编程感已解决。替代解目前只覆盖最终空杯搬运者变化，不能宣传为主要因果路线多解已完备。

### 资产、演出与机制的完成证据不同

[动作验收室](../godot_csharp/scenes/CharacterAnimationPreview/README.md)明确不接Core，接触帧可以让演示箱子改变外观并解除碰撞；[预览脚本](../godot_csharp/scenes/CharacterAnimationPreview/preview.gd)实际实现这类事件。因此它可以证明动画与局部交互联动，不能证明案件规则已结算。

[中央厅说明](../godot_csharp/scenes/Story/README.md)保留审美与步幅限制，[茶案说明](../godot_csharp/scenes/Reasoning/README.md)保留整案和Core接入范围。既有文件已在纠正“看起来完成”的问题；本轮加强的是完成声明与证据范围的对应，不把所有当前产物重新定性为失败。

## 当前边界与尚未证实的风险

[ActionRuntime](../csharp/ActionRuntime.cs)中的可达判断基于逻辑空间等关系，[WorldRuntime](../csharp/WorldRuntime.cs)明确感知范围由调用方筛选，映射不推定角色识别。游戏层仍需处理实际通行、交互距离与感知来源。这里确认的是职责边界与规范缺口，不据此宣称已经存在信息泄漏或所有场景不可达。

Git 中 `ecfa209`、`6b825d7`、`da4550a` 等提交显示展示场景、素材和适配器多次迭代；当前主线也已从动物园演示转到学园。仅凭提交标题不能判断重建是否浪费，更不能推算返工成本。类似地，先做通用动作图集可能是规格验证，也可能过早扩产；现有证据不足以定性。规范只要求批量扩产前验证代表性片段，不追溯否定所有探索。

## 两轮交叉质疑与裁决

第一轮针对候选规范找反例；第二轮由主代理提交收窄后的条款，子代理复核适用范围并纠正表述。下列为争点摘要，不是逐字会议记录。

1. **要不要建立通用空间适配接口？** 源码审查提出跨层契约缺口；历史审查反对把单案问题升级成新框架，茶案已有局部 `SiteOf`。裁决：说明相关状态、可达与感知来源并验证真实交互；不规定新接口或平行数据模型。
2. **动画帧是否一律不能改变状态？** 资产审查提出将提交与播放分离，但一度建议输入时就提交。规则审查和主代理指出这与延迟激活、嵌套阶段及局部演示冲突。第二轮收回“输入即结算”：对应规则阶段负责权威结果，动画允许同步事件；相关跳过、中断、重播不得重复或遗漏结算。验收室演示保留其有限证明范围。
3. **每个案件是否必须有两个解？** 全部审查反对硬凑数量。裁决：推理片段跑通一条完整作者轨迹和有意义的因果反例；多解按设计承诺及证据开放性检查并报告范围，不要求穷举，更不向玩家泄露参考解。
4. **失败是否必须解释真正原因？** 主代理质疑失败码直译可能泄密；第二轮规则审查补充失败本身也可能产生新观察。裁决：反馈事件中可观察的现象与可知依据，隐藏真因保持未知，仍应让玩家知道可以如何继续。
5. **所有素材是否全项验收？** 资产与历史审查均反对让装饰图做四向行走、让纯剧情做整案验证。裁决：按片段用途及完成声明选验收项；尺寸与帧数不证明审美，局部操作不证明整条路线。32×48基准与64×64承载格分别登记，不用一个数字推断碰撞或源切片。
6. **如何证明体验改善？** 茶案原始盲测有明确停止位置和后续修复。裁决：保留原始失败与限制，回归另记；AI试玩用于发现问题，不能换算为人类时长或替代用户审美判断。未完成的整案体验继续标为未验证。
