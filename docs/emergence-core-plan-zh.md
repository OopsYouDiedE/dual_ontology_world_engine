# 面向低配置涌现的 C# 核心改进方案

状态：2026-09-05 修订。当前主线为 C#，新增接口尚未实现。[文学范式与人物模拟设计](./literary-simulation-design-zh.md)是本轮完整设计及验收依据：不考虑旧代码兼容，文学范式、灵异物品、数值和人物表达均由 Core 默认提供。本文保留共用执行层的技术路线。

## 1. 目标与范围

让游戏通过对象装配、能力定义、角色价值取向和初始知识建立模拟。新增一个使用已有原语的能力，不应修改核心、职业决策分支、独立动作评分表或逐项后效处理器。

涌现的工作定义：共同机制在不同局部状态、知识、关系和约束下，产生未逐条编排的行动及后果链。行为可追溯、同初态可复现，改变关键条件会产生可以解释的差异。随机选动作、增加台词数量、跑完指定剧情都不构成充分验收。

本轮完成规则、契约与言灵共同参与的完整默认机制，包括十二种文学范式、十二种灵异物品、集中数值档案和人物交互。房间内几何、碰撞、实时运行、UI、完整经济生态、存档和无限深度规划不属于本轮。

## 2. 主要问题及代码落点

1. `Intent.Resolve` 多为不透明闭包。`Soul.Assess` 主要依赖外部 utility、偏好和动作重复惩罚，难以从行为结果判断价值；学园用操作名及职业补足这一缺口。
2. `KotodamaSystem` 已有 `Register/ValidateEffect/Apply` 和成本原语，普通行动却在 `BaseActions` 及学园闭包内直接修改实体。同类变化有不同执行路径，难以统一预估、审查和记录。
3. `Effect` 同时用作行动语义与底层操作。不同调用路径的同名操作可能具有不同参数含义。只审查外层动作，不能充分约束言灵内部的真实变化。
4. `SimulationSession.Activate` 在选择前使用客观 `Runtime.Review` 筛选。对于未知约束，这会替角色排除本来可能误判的行动。认知体系需要真正进入候选与预期计算。
5. 规则、契约和言灵具有现成结构，尚缺少共用的机会发现与后果反馈。仅有发布物、硬约束或执行函数，不足以自动形成协商、违约、见证及新决策。
6. `Event` 主要保留行动与 Outcome，没有统一的状态变化明细。部分叙事比实际变化丰富，通用表现层很难可靠解释模拟。

这些问题优先通过合并路径与补足机制语义解决，不以增加一套大型框架解决。

## 3. 固定架构决策

### 3.1 保留现有实体与运行时

沿用 Entity、Facet、Expr、Effect、Intent、Soul、Rule、Recipe、Rite、Covenant、Timeline 和 SimulationSession 的有效职责，允许直接调整或删除其旧接口。普通能力以 Entity 加 Facet 表达，不为每种能力或角色行为增加派生类。

`Intent.Effect` 保留“角色正在做什么”的语义，用于规则匹配与表现。能力的 Cost/Effect Facet 则表达“实际改变什么”。两者职责明确，普通行为与言灵都遵循这一分工。

### 3.2 一个共用效果执行层

从 `KotodamaSystem` 提取 `EffectExecutor`。沿用已有 Expr/Effect AST 和原语注册方式。第一批覆盖实际需要的属性/标签修改、投入支付、对象迁移、关系增删与事实断言/撤销，不扩充为新的脚本语言。

拟定核心调用为 `Prepare(effects, view)` 与 `Commit(plan)`：

- Prepare 在只读状态视图及局部覆盖值上依次计算效果。后续扣费能够看到前面已计划的扣费，避免两次独立检查都认为余额充足。
- 计划包含将改变的实体引用、字段或关系、变化前后值及来源。仅为统一结算新增必要的变化项和执行计划载体，不复制整个世界。
- 执行前依据最新世界重新准备。所有声明式投入与效果检查通过后，一次提交状态变化；提交期间不调用游戏监听器。
- 没有实际应用变化前不发送成功 Event。预期失败返回明确原因；部分失败策略必须由机制明确规定。
- 自定义效果原语注册一次准备逻辑，使预估与执行共用计算。删除旧闭包兼容入口；进入正式模拟的效果必须走可准备的执行路径。

只有这一层负责模拟效果的实际写入。扩展原语必须产生执行计划；外部副作用只能在成功提交后的宿主通知中进行。仪式按阶段分别提交，已完成阶段的代价不会因后续阶段失败而自动返还。

源质与投入去重使用实体引用。修正 `AggregateAspects` 中以对象哈希值代替来源身份的做法，避免不同来源碰撞，也保留同一来源不能反复贡献的约束。

### 3.3 一个能力装配入口

新增能力工厂，返回 Entity，复用已有槽位绑定、Requirement、Cost、Effect 等结构。游戏只需提供：

- 参与对象与条件；
- AV 成本及实际投入；
- 声明式结果；
- 可选展示文本。

工厂将定义绑定到具体对象并生成 Intent。`Affordances` 接收对象或角色挂载的能力定义。旧 `Offer(factory)` 不要求兼容，最终接入以范式和预设工厂为准。

言灵沿用现有 Recipe 的槽位、源质、语义指向及投入检查，增加生成候选 Intent 的适配入口。角色只能从自己掌握的配方、已感知或已知且可指向的对象中生成绑定，不能默认遍历全世界。

普通能力与言灵都生成 Intent，都由同一 Runtime 执行。配方增加一种已支持效果时，不再添加同名职业分支或专属动作奖励。

### 3.4 主观预期与客观结算分开

对状态查询建立两种读取语义：世界视图用于执行，认知视图用于预期。状态仍以实体为唯一客观来源；认知视图读取已有 Observation、Knowledge 与 Belief，并保留信息来源。

未知不能等同于已知为假，也不能回退到直接读取真实属性。涉及隐藏门禁、契约、他人意图或材料性质的预估允许不确定；只有实际执行才获得真实结果。

默认自主选择依据角色所知的候选与预期。执行前始终做客观复核。已知身体绑定与明确能力归属仍按真实运行时约束处理，不把技术绑定错误当成角色误判。

真实反馈是否被获知，由观察范围决定。失败可以成为调查或重新选择的依据；它不能直接向角色泄露未被观察到的全部失败原因。

### 3.5 按后果评价与有限准备行动

`Soul.Assess` 的基础效用改为：预期状态变化对角色价值的改善，结合关系、已接受规则、承诺、资源代价、时间与不确定性。复用现有 Preference 与 Decision 保存分项来源。游戏定义价值倾向，不再为每个动作建立独立评分。

Core 提供完整的默认人物取向与价值组合，数值通过集中档案和场景校准。游戏覆盖目标与倾向，不再依赖旧手写 utility；不内置所有角色共享的道德或人格。

为不可立即完成的目标提供有界的前置候选搜索：利用声明式结果匹配尚缺条件，优先寻找一项准备行动；执行后重新观察、重新选择，不锁定长串过时 Intent。提供默认搜索预算与循环去重，只有大型游戏需要调整预算。

正式行动不使用不透明执行闭包。第一版不要求通用最优规划，必须能处理本轮场景中获得介质、请求许可或调查条件这类准备行动。

### 3.6 规则、契约和言灵的协作

普通规则是可传播、可接受或拒绝的信息。发布不自动修改所有 Soul；接收不等于接受；违反普通规则不自动构成物理失败。规则压力进入 Decision，相关社会后果由掌握信息的角色产生。

契约保留 HardConstraint、Obligation、Exception、Breach 的区别。绑定明确的参与者、适用范围和生命周期。及时义务响应已完成事件，带期限义务登记到同一 Timeline；履行、撤销和失效均停止后续追索。

硬约束检查同时覆盖主行动语义和内部实际变化，传递真实施术者、契约与配方来源，避免换个动作名称就绕过禁止的结果。被授权的超自然能力可改变现实，但不能借普通 `assert` 直接宣称物理状态已经成立；物理改变必须由对应效果产生。

契约惩戒、言灵后效和仪式阶段统一通过效果执行层，产生独立的、有来源的变化记录。连续触发采用现有递归保护并按具体契约与事件去重，不阻断后续独立事件的合法触发。

Core 默认提供社会反馈与人物交流机制：根据被见证的承诺履行、违约及对象关系产生认知、关系倾向和候选反应。文化或人格差异由少量价值配置表达，不强制每个角色作出相同道德判断。

### 3.7 表现建立在事实之上

扩展已有 Event 与 ActionResolution，关联 Decision、投入、真实变化、因果来源和观察者。复用同一变化记录，不另建一套叙事世界状态。

提供无 UI 的默认解释格式，输出选择依据、执行结果和直接后果；游戏可以替换措辞、动画与镜头。客观审计视图可完整查看，角色视图只显示其能观察的信息。

拒绝、执行失败与成功明确区分。拒绝保留 ActionResolution，不伪造成功事件。言灵造成关系变化或触发契约时，解释能沿 cause 追溯到真实来源；没有对应变化的数据不生成肯定描述。

## 4. 模块改动与简化范围

| 现有模块 | 改动 |
| --- | --- |
| `core/kotodama/KotodamaSystem.cs` | 提取共用效果原语；保留配方、源质、仪式和契约职责；增加候选适配。 |
| `core/mind/intent.cs`、`core/entity/base_actions.cs` | 增加声明式能力到 Intent 的入口，删除旧闭包与分类壳，重写默认行动。 |
| `core/simulation/Affordances.cs`、`SimulationSession.cs` | 接入能力定义与认知候选；去掉默认依靠隐藏客观信息筛除误判的路径。 |
| `core/mind/soul.cs`、`decision.cs` | 后果效用、未知信息处理、分项解释与有限准备行动。 |
| `core/rule/RuleEnvironment.cs`、`RuleSystem.cs` | 共享状态查询与绑定；分开行动语义和实际变化约束；避免重复权威状态。 |
| `core/timeline/Timeline.cs` | 接入准备、前置反应后重新准备、提交及完整因果事件。 |
| `simulation/AcademySimulation.Decisions.cs`、`Motives.cs` | 迁移一条规则—言灵链，删除被替代的职业分支、重复收益与后效代码。 |
| `simulation/TrajectoryRecorder.cs` | 使用真实变化生成解释，区分客观记录与角色视角，不要求旧导出格式兼容。 |

移除没有独立行为的 Intent 分类派生壳，并重写本轮使用的调用方。通用灵异物品、调查、质证、承诺与人物表达纳入 Core 默认机制库；作品专属谜底和人物经历留在游戏。核心模块可拆文件提高可读性，不能为形式分层增加空服务类。

## 5. 实施顺序与阶段验收

下列 P0—P4 是技术依赖说明；最终交付范围及先后顺序采用新版设计的 A—E，包含十二范式、十二物品、数值校准与两个不同主题场景。

### P0：统一变化语义

落地效果执行层、变化记录与视图读取；迁移投入扣除、状态修改、关系与对象移动的必要路径。

验收：连续两笔投入不能透支；后置检查失败不能残留本次声明式扣费；未知原语明确拒绝；源质按对象来源去重；普通动作与言灵的同类变化走同一执行器。

### P1：让规则与言灵共同运行

落地能力定义、配方候选和契约后果适配。完成发布—认知—选择—执行—见证—再选择闭环。

验收：未获知规则不会自动接受；普通违规可以执行；有效硬约束阻止真实受限效果；履约、违约、豁免、撤销有不同后果；言灵改变对象后，其他能力自动重新可用或失效。

### P2：让选择由预期变化驱动

迁移认知视图、后果效用和有界前置搜索。提供默认偏好与社会反馈装配。

验收：不添加动作名评分也能选择新能力；相同客观世界、不同知识会产生不同决策或不同预期；失败后能利用新观察重选；获取介质等准备行动无需专属剧情链。

### P3：独立场景与表现验收

新增只引用 Core 的“夜班守则”和“封闭学园质证”场景，分别覆盖错误规则、异常与有限护具，以及证据、归还义务、保密承诺与真言。两者复用相同范式、物品与人物机制。

只配置对象、关系、规则、配方与角色初始取向，不编写“第几步谁做什么”，不按角色名称指定解法。角色能够通过普通许可、准备或言灵路径改变局面，后续选择受真实信息和义务影响。

固定初态保持可复现，分别改变规则是否获知、是否采信、契约是否生效、介质是否存在以及行为是否被见证，检查真实状态与行为链变化。不是要求所有变量都改变结局，而是要求相关变化在契约规定的位置生效。

默认解释必须能展示计划依据、实际投入、失败或违约来源、观察差异与连锁后果，不能依赖专属事件台词证明机制存在。

### P4：学园迁移与收敛

重写学园中有价值的规则—契约—言灵内容，删除被替代的判断与奖励代码。按新语义重写验证，不要求保持旧剧情接口、数值或五日轨迹。

各阶段完成时保持新项目可构建。直接删除被替代的旧实现并同步本轮入口，不维护兼容层或第二套效果执行器。

## 6. 最终完成条件

1. 两个不同主题的游戏场景引用同一 Core，规则、契约与言灵不依赖学园命名。
2. 为其中一个场景增加一种由现有原语组成的能力，只修改内容定义或装配；候选、基础评分、约束检查和默认解释无需另补分支。
3. 世界与认知分离得到可运行验证；错误信念不会改写真相，隐藏事实不会自动泄露给决策器。
4. 言灵和普通行动通过共用变化机制相互影响，至少存在一条跨越规则认知、行动、言灵或契约后果、他人反应的真实因果链。
5. 支付、源质、嵌套反应与契约生命周期没有被本轮迁移绕过。主要验收检查真实状态与因果记录，不以文案字符串或固定整段轨迹代替。
6. 提交迁移前后的必要配置对照：能力定义、职业判断、评分及后效各改了哪些文件。复用范围扩大时，新增配置应主要增加内容，不能要求修改越来越多核心模块。

完成上述条件才认定本轮达到“低配置涌现底座”。不以新增类数、动作数或演出长度作为完成标准。
