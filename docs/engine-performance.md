# 会话决策与耗时记录

## 统一指标

`DvSession` 为 CLI 与 Godot 提供同一份统计。三个主指标都使用当前统计会话的现实游玩小时作为分母。计时只观察实际调用和接口边界，不参与世界状态、行动资格、报价或规划。

| 指标 | 字段 | 计算 |
| --- | --- | --- |
| 推进速度 | `game_hours_per_real_hour` | 累计正式推进游戏分钟 × 60,000 ÷ 现实游玩毫秒 |
| 决策频率 | `decisions_per_real_hour` | 累计正式选择数 × 3,600,000 ÷ 现实游玩毫秒 |
| 接口耗时率 | `interface_hours_per_real_hour` | 当前控制来源累计接口毫秒 ÷ 现实游玩毫秒 |

单位分别为“游戏小时/现实小时”“次/现实小时”“累计接口小时/现实小时”。接口耗时率表示每运行一个现实小时对应多少累计接口小时，不是每次决策延迟，也不是每游戏小时的耗时。

主界面只显示这三个比率及采样现实时间、推进游戏时间。旧的每游戏小时引擎秒数、每游戏小时决策数、每游戏小时整段现实秒数和每计算小时决策数已从新合同中移除，不保留互为倒数的别名。原始数量与毫秒保留用于报告拆解。

现实窗口从新开局或恢复完成开始，到宿主请求关闭时冻结，包含阅读、思考、输入等待、现场执行、界面投影和引擎处理；初始化与关闭归档单列。暂停、离席和后台停留不自动扣除。零现实分母显示缺失；游戏未推进而现实分母有效时推进速度为 0。不足一现实小时按实际窗口计算并标记 `sample_window_partial`，不能声称已经运行一小时或据此预测整局。

游戏推进只计最外层正式 Prepare、后台 Prepare、采用正式预备结果和 Complete 期间物理时钟的前进量；开发调时不计入。回退游戏时钟开启新 epoch。恢复存档新建统计会话，不把历史耗时或决策重计。

## 接口耗时与控制来源

| 来源 | 累计接口耗时 | 原始边界 |
| --- | --- | --- |
| `engine` | 正式计算 `engine` 加提前准备 `speculation` 的排他墙钟耗时，包括未采用的提前计算 | 实际同步操作及嵌套阶段开始、结束 |
| `human` | 真实可选请求对人工可见至选择被接受、取消或会话关闭的区间 | request、已提供的阶段切换、accepted/outcome |
| `llm` | 真实可选请求对外部模型可见至选择被接受、取消或会话关闭的区间 | request、已提供的 response、accepted/outcome |

人工和大模型不再用整段会话耗时充当接口耗时。宿主没有报告可见请求时，外部接口耗时和比率为缺失；不能填 0 伪装测量。请求已出现但尚未完成时，当前已等待时间计入累计，并单独保留在途状态。

`BeginDecisionInterface(actor, phase)` 只能在对应选择实际可见后调用。同一主体重复刷新页面不重启计时。`SetDecisionInterfacePhase(actor, phase)` 只记录宿主实际观察到的阶段，例如模型 response；未提供的网络、队列、内部推理或人工思考阶段不能估算。`RecordDecision` 在人类或模型的正式选择事件进入状态时自动结束接口等待，并记录 accepted 与原事件引用。`EndDecisionInterface` 用于取消、界面撤回等实际边界。关闭把尚未完成的区间记为 `closed-pending`。

所有来源共用同一现实分母。`decision_sources` 报告按来源列出正式选择数、次/现实小时、接口累计毫秒、接口小时/现实小时。主界面接口指标对应当前控制来源，`controller_label` 明示引擎、人工或大模型；主界面决策频率对应全体实际主体的正式选择总数。人工或模型会话中的 NPC 引擎消耗继续在来源表中记录。

接口等待可能与 NPC 引擎计算重叠，因此各来源的累计接口时间不能直接相加当作整段现实时间；并行接口的累计小时/现实小时可大于 1。同步引擎墙钟包含该段操作系统调度和 GC，不等于线程 CPU 时间。

控制来源在首次正式、预备或开发操作前确定，并与真实 player_actor 控制权相符。`player`/`human` 为人工，`llm` 为模型，`ai`/`engine` 为引擎自主。`--jsonl` 只决定传输格式。存档仅保留 `performance_controller` 诊断标签，旧存档按实际控制权推定标签。

## 正式决策与动作生命周期

决策只消费当前统计会话内新进入正式 `state.events` 的 `action_selected`。NPC 和自主主体归引擎，外部控制主体按 human 或 llm 归类。UI 聚焦、候选搜索节点、无候选阶段、未采用预备分支、恢复前历史及开发命令不新增正式决策数；采用预备分支后新增事件只消费一次。

选择数、已排队数、实际 Complete 数和待执行数分列。Complete 包括实际成功和拒绝回执，其成功/失败结果由 `outcomes` 记录；选择与完成的差值不自动解释为失败。短窗口内尚未到期的排队动作保持 pending。

`SetPerformanceLifecycle` 接收会话事件游标和关闭边界已经取得的事实，不另建会话或第二状态。生命周期记录包含：

- 当前 trace 的 selected、scheduled、completed、pending。
- 最近可恢复存档点的 durable_selected、durable_scheduled、durable_completed、durable_pending。
- trace/durable 游戏时刻、最后事件和状态版本。
- 尚未进入存档的选择数、在途宿主回执及关闭原因。

轨迹保留正在准备或等待回执的真实尾部；存档来自最近可恢复提交点。报告同时列明这两个截止点，不以 trace 的选择数冒充存档中的选择数，也不将尾部尚未保存解释为动作失败。

## 计算与投影拆解

| category | 内容 |
| --- | --- |
| `engine` | 正式 Prepare、后台准备、采用预备结果、Complete |
| `speculation` | PrepareAhead 的实际计算，含最终未采用的计算 |
| `projection` | 主观/客观地图、目录、选项、状态、意图、快照和正文投影 |
| `startup` | 新会话初始化与恢复 |
| `persistence` | 存档、轨迹封存及会话关闭 |
| `development` | 显式开发操作 |

报告只列实际出现的分类与阶段。人工/模型接口区间独立列出，不伪装成同步计算阶段。认知、选策、候选、地图成员、站点和通道沿真实 `rt_phase` 配对边界记录，不改变预算或调用逻辑。

`planning` 拆解消费新正式 `action_selected.data.planning_work`：按主体累计候选检查、资格求值、预测、展开节点和候选路径，记录峰值前沿、缓存命中与停止原因。命中缓存时 `reused_work` 仅标示此前工作来源，本轮实际工作不重复累计。预算、深度及展望限制取本窗口观测最大值，缺失字段保持缺失；这些计数只解释实际选策成本，不改变搜索预算或决策顺序，也不增加主界面指标。原始逐决策工作与来源保留在正式轨迹事件中。

生产默认的 `selective-task-v1` 是允许近似的任务选择策略，`--planning precise` 可恢复内容声明的完整搜索。报告从实际配置及正式事件记录 `planning_strategy`、`planning_approximation` 和停止原因，不能把两种策略的耗时差解释成严格同条件算法提速。选择性策略有正价值当前任务便停止展开，需要路线时再使用本人已采纳预测；稳定路线续行、无任务让出及缓存命中都必须保留实际原因。`forecasts` 只计真正执行的预测，`forecast_reuses` 计预测复用；`route_reuses` 计通过重核的续行，`skipped_expansion` 计没有新展开的决策。已完成行动、实际代价、知识来源和判答条件不作近似。

短时性能目标按实际工作段判断。采集器的 `--game-minutes N` 在正式时钟实际推进至少 N 分钟后停止发送 `next`，不会设置时钟、预填路线或伪造事件；若下一真实事件跨过目标，报告实际终点及超出量。`--seconds` 与 `--hard-timeout` 仍限制现实时间，归档预留包含在硬上限内。进程启动至退出的实耗、会话游玩窗口、初始化、引擎与投影排他耗时、关闭归档分别报告；不能把单次决策低于目标当作整段会话达标，也不能遗漏归档或冷启动后宣称总时长达标。回放截图导出独立列明耗时与来源，不计为新的 AI 决策。

`operations` 的时间字段明确区分：

| 字段 | 口径 |
| --- | --- |
| `inclusive_total_ms` | 操作累计墙钟，包含子阶段 |
| `exclusive_total_ms` | 操作累计墙钟扣除子阶段 |
| `inclusive_mean_ms` | 含子阶段累计 ÷ 实际调用次数 |
| `exclusive_mean_ms` | 排他累计 ÷ 实际调用次数 |
| `inclusive_p95_upper_ms` | 含子阶段时长的固定直方图 P95 上界，受实测最大值约束 |
| `inclusive_max_ms` | 含子阶段实测最大时长 |

分项总和使用排他值；含子项总计和均值不可重复相加。P95 上界不冒充精确分位数。分配字节是当前托管线程累计分配，不是峰值内存、保留堆或泄漏量。正文投影耗时不等于终端打印耗时。

操作维度分为 `trigger_actor`、`viewer` 与 `projection_scope`。触发一次全局或目录投影的行动主体并不是该投影的唯一成本所属者。观察者和范围由调用者明确传给 Measure，DV 投影子阶段继承该范围；不能再把全体地图的耗时解读为某个人的地图。

`measured_until_ticks` 标明这份摘要的采样截止，`wall_measured_until_ticks` 标明现实窗口截止，二者使用同一个 Stopwatch 原点及 `stopwatch_frequency`。世界状态版本另存。一个交互帧应在所需投影完成后取一次新摘要，并将同一份摘要放入帧顶层和嵌套预览，避免两处口径错位。

## 分段归属与原始证据

`.hourly.csv` 按游戏时钟的绝对 60 分钟区间归属数据，用于定位发生时段。计算归操作开始的游戏小时，决策归原事件游戏时刻，现实等待归当前已提交时刻；状态推进完成后才切换等待归属。实际推进分钟按跨小时边界拆分，不假定跨小时计算或等待均匀耗费。

这些归属片段继续使用各自行内现实时间计算三个比率，分母为零时留空。它们不代表完整现实小时。累计比率以全局累计分子除以全局现实分母，不平均各行比率。向后调时的 epoch 独立列出。

调用 `StartPerformanceRecording(prefix)` 开启缓冲二进制记录。已有内存尾部先按原记录序号写入，随后每条计算样本、正式决策引用和外部接口边界都顺序写入同一 `.dvlog.partial`。运行期使用缓冲流，关闭报告时写完整汇总与 seal、Flush 并原子发布为 `.dvlog`。尚未开启记录时已经从尾部淘汰的前缀数量明确记录；开始得晚不能声称记录完整。

计算、决策和接口事件各自保留最近 8192 条供在线查看与临时导出；累计主体、小时及会话汇总持续保留。尾部淘汰不删除已经写入流中的记录。没有开启流式记录时，导出明确为 `bounded-tail-export` 并给出缺失前缀数量。

原始流写入失败不会更改世界决策；错误记入报告，保留 partial，最终封存报告错误。不能用新文件或尾部补写冒充原流完整。报告自身生成与写盘不计入该份快照；采样机制的额外开销仍属于运行条件，不能和没有该插桩的旧窗口宣称严格同条件提速。

## 导出合同

`dv-performance-v3` 导出以下五个文件：

| 后缀 | 内容 |
| --- | --- |
| `.md` | 三个核心指标、控制来源、接口阶段、计算拆解、主体决策、发生片段、来源和提交边界 |
| `.hourly.csv` | 按游戏时钟归属的覆盖量、现实时间、三个比率、原始决策数与分类耗时 |
| `.operations.csv` | 分类/操作/触发主体/观察者/范围的含子项与排他时间 |
| `.decisions.csv` | 主体及控制来源的正式选择数、次/现实小时与首末事件 |
| `.dvlog` | 顺序原始计算、决策、接口边界及完整聚合快照和 seal |

CSV 是派生表，原始证据使用二进制。文件独占创建 partial 并原子发布，不覆盖同轮既有结果。某一导出失败仍尝试其他派生文件，最终汇总错误。活动录制前缀只在关闭时封存；运行中需导出快照时使用不同新前缀。

来源由 `SetPerformanceProvenance` 写入结构化记录，包括实际 host/executor、是否 Godot 执行、控制者、检阅者、源码版本、程序集及驱动方式；不存在的值保持缺失。formal-model 不能被固定标签描述成 Godot 现场回执。

## CLI、回放与宿主接口

CLI 在时间栏下方固定显示三个核心比率，附采样现实时间和游戏推进量，分页保持。最新事件正文先以全宽呈现，候选和地图随后显示；窄屏换行，缺失显示“—”。人工及模型 AI 评分默认隐藏；引擎默认仅给选中项显示已有短分，`scores on` 展开评分并显式请求即时估值，`zoom detail` 展开已有显示细节，均不新增正式决策。关闭显示“本次记录停止”，不据此认定剧情完成。

`perf` 展开汇总及拆解，`perf NEW_PREFIX` 导出当前快照。`--performance PREFIX` 选择自动流式记录与退出报告前缀；没有显式前缀时沿用会话输出位置推导前缀。回放只显示当前历史帧已经记录的指标，不创建新统计会话，不把播放时长计入历史现实时间，也不倒算旧合同缺失的新指标。

公共 API：

- `PerformanceSummary()`：轻量核心指标、原始累计量、采样截止及在途状态。
- `PerformanceSnapshot()`：来源、生命周期、所有聚合拆解与原始记录覆盖信息。
- `SetPerformanceController(kind)`：首次操作前设置真实控制来源。
- `BeginDecisionInterface(actor, phase = "decision")`、`SetDecisionInterfacePhase(actor, phase)`、`EndDecisionInterface(actor, outcome = "accepted")`：外部接口实际边界。
- `SetPerformanceProvenance(value)`、`SetPerformanceLifecycle(value)`：发布宿主来源与正式事件/持久化边界。
- `RecordPerformancePlanning(actor, eventId, work, stopReason)`：在正式事件游标处累计本次选择的实际规划工作；与 `RecordDecision` 采用相同的新增事件边界。
- `StartPerformanceRecording(prefix)`：为该会话开启唯一原始性能流。
- `StopPerformanceClock()`：幂等冻结现实窗口，结算尚未完成的外部等待。
- `WritePerformanceReport(prefix)`：导出快照，或在关闭后封存对应正式流。

Godot 性能页读取同一摘要；接口计时仍由实际可见选择和接受边界驱动，不能因性能页打开而启动或因离页而停止。宿主关闭先冻结现实时间，再保存输入、轨迹、存档和报告。原始记录失败与部分封存应保留在关闭清单。


### 部分根层与展示计算

选择性规划可在根层第一个有实际信息、核验或成就价值的已准入任务处提前停止。`candidates_skipped` 只记录已生成列表中的实际未求值候选，`partial_layer` 累计部分层选择次数，`examined_layers` 与 `completed_layers` 分别记录进入求值与完成全层求值的次数；不估计尚未展开的树，也不将部分层结果描述成完整最优。新增 `selection-evidence`、`decision-record` 阶段归属正式准备开销。

默认观察者列表不额外重算每个候选的即时分，只显示真实规划记录中的根分／选择分。显式请求即时评分时，其计算记入 projection，不计为新决策。关闭前实际取得的最后观察者预览与版本写入 `closing_preview`，回放沿用已记录性能截止，播放本身不补造测量。

选择性根层的 `candidate_order` 留在逐决策原始工作记录，区分声明顺序、短时长任务优先、整次规划缓存、路线续行及休眠复用。`candidate_order_scans` 是本次为稳定排序读取声明的候选数；`candidate_order_reuses` 是本次完整排序依赖的缓存命中数。两项放在规划拆解中，不增加 CLI 主指标，排序读取也不计作准入检查或资格求值。

## 主观投影与本轮限时运行

本轮 AI 正式会话的进程硬上限为 45 秒，关闭预留包含在内；采集器默认 `--seconds 41 --grace 4 --hard-timeout 45`，最后 250 毫秒预留给终止与回收，独立 watchdog 仍在 44.75 秒触发。构建只在整批修改完成后进行。以同一现实窗口内实际正式推进的游戏时间与剧情节点共同评估，记录与截图导出分别列明成本。完整工作顺序、JPG 与独立审查合同见 [cli-throughput-contract.md](cli-throughput-contract.md)。

证物卡目录为会话内不可变复用数据，行动呈现以实际行动者和完整声明为缓存输入；检视结果仍在对应 Complete 后公开。普通 AI 候选投影省去人工重演组合的额外枚举，人工控制保留相同的合法重演入口。主观地图复用以本人实际对象信息、已知路线、行动声明、已提供候选和身份绑定为依赖；实时游戏时刻与会话状态在每次投影时覆盖，不把缓存时刻当作当前时刻。

后台准备的 pending 必须保留对应 NPC 与玩家等待位置，执行完毕后恢复玩家输入。此修正属于调度一致性变化，单独记录；未运行 Godot 时不声称实机后台行为已经验收。

### 到期义务、持续等待与历史存储

内容动作可声明 `obligation: true` 和 `obligation_due`。调度器优先处理已到期且本人具备完整行动资格的义务，仍检查本人前置、余额、报价及剩余游戏时长，并经过排程、Prepare、真实回执和 Complete。08:00 晨间通知使用内容层独立的零分钟通知类型；调查、取证和声路试验的既有费用不因此缩减。

等待复用保留原 `source_stop` 和全部失效条件，只推进已检查事件的游标，不再为每个空转扫描追加 `planning_stop_reused` 并复制完整事件列表。唤醒仍取决于本人收到的新观察、言语、同处变化和声明时界；无法证明的时间依赖保留原复查边界。

可提前中断的行动必须显式声明 `interruptible=true`、`activity="wait"`，`kind` 为 `wait` 或 `wait.*`，且费用模型满足 `minimum.time=0`、`actual.time>0`；不能夹带 answer、speech 或 travel。`dvs_interrupt_waits` 只接受本人的实际新听闻、观察事件或当前可见接触变化，远处行动与私有世界变化不能唤醒本人。中断记录原起点、原到期点、实际 `elapsed` 和来源，缩短排队时长后仍走 Prepare → 真实 receipt → Complete，实际回执必须匹配 elapsed；非时间费用照常结算。原完整等待法则不执行，该动作不进入 `completed_actions`，也不写普通拒绝签名封锁后续等待。`failure_class=activity-interrupted` 单独表示活动中断，不能混同普通执行失败或成功完成原等待。

固定点休眠仍要求认知处理已完整结束、本人输入未变且没有待收闻或阻塞。对于 `heard_when` 恒真但没有实际来源的 topic，已完成且输入相同的认知捕获可以休眠；不能为了填平恒真条件而补造 `heard_topics`、观察或知识。本人输入、真实来源事件、可见接触及声明时界变化继续使 guard 失效。

普通记录中的 `action_execution.receipt.execution.world` 只有在 `rt_raw_ref` 返回真实原始 DAG 引用时才可改存 `world_cut`：完整世界节点先进入原始日志，再由 `journal`、`node_id`、`definition_frame` 定位。当前 CLI 没有打开 live `RawDagWriter`，最近实测中这条 `world_cut` 路径未生效；性能采样的 `.dvlog` 流不能当作该世界记录器。没有原始引用时保留原世界，不能声称本轮已经通过该压缩改善体积或性能。当前存档的完整现实状态、各人认知及正式推理读取的推导和观察历史均保留，没有删除完整历史；完整 audit 模式仍保留嵌套世界。未来评估须注明实际生效的存储模式，不能把删除唯一证据当成优化。

运行时列表追加可复用经认证的冻结前缀，只处理新增后缀；任何子树写入必须使该认证失效。规划工作量上限与实测毫秒耗时分别报告，未实现或未测量的墙钟硬期限不得列为已完成能力。

选择性规划的 `selective_candidate_budget` 默认每片 48 个候选。未完成的 frontier、节点与候选游标保存在主体的 `planning_continuation`；`planning_yield` 只记录计算进展，不是正式行动或游戏时间推进。恢复先核对完整本人输入，改变则重算；未扫完不能建立休眠凭据。每片仅计本片节点增量，最终选策说明累计搜索片数。恢复后需要追加的候选列表使用独立可写根，既往冻结证据保持不变。

本批等待中断、固定点 guard、主观称谓与回执呈现、CLI 布局和字体回退仅完成源码实施，尚无下一轮实际会话及逐图验收结果；既有实测与三代理评估见 [cli-optimization.md](cli-optimization.md)。采集进程的 watchdog 已有实现，规划器内部的墙钟硬期限仍未实现，两者不能互相替代。
