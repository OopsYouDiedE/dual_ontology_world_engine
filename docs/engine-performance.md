# 引擎耗时记录

## 指标与范围

`DvSession` 为 CLI、Godot 共用的统计入口。计时由 `Stopwatch` 的单调时钟完成，仅包围实际同步计算；统计不写入 DV 世界、人物心智、行动费用或规划输入。

核心指标是：

`每游戏小时引擎现实秒数 = (正式计算排他毫秒 + 提前准备排他毫秒) / 1000 / (实际前进游戏分钟 / 60)`

分母只取正式 Prepare、后台 Prepare、采用提前准备与 Complete 期间物理世界时钟的真实前进量；只在最外层操作记一次。读取地图、切换视角、等待输入、阅读正文、Godot 移动及动画均不增加该分母。开发命令引起的时间跳跃单列；加载存档开始新的统计会话。比率在零推进时为缺失值，终端显示“—”；不足一小时按实际覆盖分钟折算。

这是同步计算的墙钟耗时，包含该段期间的操作系统调度和 GC，不能作为线程 CPU 时间或 Godot 帧率。报告携带控制方式、审计方式、开发模式、主体数、.NET 版本与程序集 MVID，便于区分运行条件。统计本身带有开销，不能把不同插桩条件下的数字当作同条件性能比较。

## 分类与嵌套

| category | 内容 | 是否计入核心指标 |
| --- | --- | --- |
| engine | 正式 Prepare、后台准备、采用分支、Complete | 是 |
| speculation | PrepareAhead 实际计算，包含最终未被采用的提前计算 | 是 |
| projection | 意图、快照、增量、观察者地图、选项、状态与正文投影 | 单列 |
| startup | 新会话初始化、存档恢复 | 单列 |
| persistence | 稳定存档、轨迹、会话关闭与序列化 | 单列 |
| development | 显式开发命令 | 单列 |

认知 `phase.cognition` 与选策 `phase.choice` 使用已有 DV 阶段边界记录，并带有真实主体 ID。更外层的 Prepare 等操作保留总耗时与排他耗时：`total_ms` 包含内部阶段，`self_ms` 扣除子阶段。分项相加只使用排他耗时，避免把同一段认知同时加到认知、Prepare 和总引擎中。以操作/阶段/主体为键汇总调用次数、被报告的异常、未闭合阶段、平均值、峰值、P95 上界、总分配字节和排他分配字节。异常计数来自 DV 调用和持久化异常；参数拒绝不代表世界动作已经执行。动作结果另保留 applied、blocked 等真实回执计数。

P95 使用固定直方图的上界估计，并以已观测峰值收紧上界；它不是保存所有样本后求出的精确分位数。分配字节取当前托管线程的累计分配，不能作为仍驻留堆内存或进程内存。未结束作用域单列，不补成已完成样本。

## 小时表与原始记录

小时表以物理游戏时钟的绝对 60 分钟区间排列。每项排他耗时归到该操作开始时所在的小时，实际前进分钟按跨小时边界拆开；不能从一个跨小时的整段耗时推断每分钟均匀耗费。表中同时提供覆盖分钟、整小时标记、引擎/提前准备/投影/开局/归档/开发分项，并在小时CSV中进一步列出认知、选策、Prepare本体、后台准备本体、Complete本体和采用分支的排他耗时。阶段列是前述分类的进一步拆解，不能与分类总量重复相加。向后调整游戏时间后创建新的 epoch，不与此前同名小时合并。全局平均值使用累计耗时除以累计覆盖时间。

累计汇总保留所有已结束作用域；原始采样使用固定 8192 条尾部环。超出部分仅淘汰原始样本，累计和小时汇总继续保留，报告公开总数、保留数与淘汰数。正常计算过程不逐样本写磁盘，也不依赖 Godot 性能页是否打开。

导出以一个前缀生成四个文件：

| 后缀 | 内容 |
| --- | --- |
| `.md` | 中文指标定义、运行条件、分项与小时报告 |
| `.hourly.csv` | 每游戏小时区间的覆盖和耗时拆解 |
| `.operations.csv` | 按分类、操作及主体的聚合数据 |
| `.dvlog` | 带校验的二进制原始尾部采样、完整聚合快照及 seal |

CSV 为派生聚合表，原始计时只写二进制。每个文件独占创建 `.partial`，写完后原子改名；失败保留部分文件，其他文件继续尝试，随后报告具体失败。报告生成及报告自身写盘不计入该次报告快照。

## CLI

顶部状态栏在游戏时间下固定显示每游戏小时现实耗时、累计引擎耗时和已推进游戏分钟；地图和行动分页保持该行。旧回放缺少记录的统计值时保持缺失；新交互预览保存当时的统计摘要，回放消费已记录值。

`perf` 显示完整当前拆分，不推进世界；`perf NEW_PREFIX` 同时导出上述四个文件。`--performance NEW_PREFIX` 指定退出报告前缀。所有正式 CLI 会话关闭时自动尝试导出；已有 --trace 或 --save 时放在该文件旁，以去扩展名后的路径加 `.performance` 为前缀；其余会话放在 `artifacts/performance/<UTC时间与会话标识>/engine`。无会话示例和只读回放不创建新的引擎统计会话。

## Godot 与桥接口

`PerformanceSummary()` 返回只读轻量摘要；`PerformanceSnapshot()` 返回完整只读汇总；`WritePerformanceReport(prefix)` 导出报告。它们均不触发 Prepare、Complete 或人物认知。GameEngine 暴露相同摘要和快照接口供控制台读取。

Godot 性能页保留原有 120 帧图，并每 0.25 秒读取一次会话摘要，显示每游戏小时、累计、投影、初始化及归档耗时。离开性能页只停止原有帧诊断采样，会话统计持续记录。退出归档写入 `user://dv-sessions/<会话>/engine-performance.*`，统计导出独立于完整审计开关，并在关闭清单登记导出失败。

本次交付只实现记录与报告接口，没有运行会话、构建、测试或检验，也没有产生当前版本的实测性能结论。
