# 标准空间门禁与容器收纳技术规范

## 1. 概述与理论溯源

空间门禁与容器收纳体系是冒险游戏、RPG 以及空间模拟系统中最经典的游戏机制之一。该体系理论由欧内斯特·亚当斯（Ernest Adams）与安德鲁·罗林斯（Rollings & Adams, 2003）在《游戏设计理论》中形式化定义为“锁钥空间拓扑结构”（Key-Lock Spatial Puzzle Architecture）与“层级物品收纳模型”（Hierarchical Inventory Model）。
该系统负责确立物理空间与道具资产之间的可访问性边界，实现防套利、防循环嵌套且方向自洽的客观封闭机制。

## 2. 空间门禁与开合物状态机

开合物实体（如门、闸板、暗格、宝箱）遵从严密的三状态互斥状态机：

```
         ┌───────────────┐
         │ 闭合未锁状态   │
    ┌───▶│   (Closed)    │◀───┐
    │    └───────┬───────┘    │
    │ 关门       │ 开门        │ 解锁
    │ (Close)    │ (Open)     │ (Unlock)
    │            ▼            │
┌───┴───────────┐       ┌─────┴─────────┐
│  开启通达状态  │       │  闭合上锁状态  │
│    (Open)     │       │   (Locked)    │
└───────────────┘       └───────▲───────┘
                                │ 上锁 (Lock)
                                └────────────────
```

### 2.1 状态流转契约

* **开启状态（Open）**：实体对外完全连通。实体无法在开启状态下直接挂载有效锁；触发上锁动作时，系统必须自动先将其闭合（Close）。
* **闭合未锁（Closed）**：实体在物理上阻断通行或视野，但主体无需钥匙或特殊工具即可执行开启。
* **闭合上锁（Locked）**：实体被一把或多把锁记录强行阻断。在全部相关锁被解除之前，禁止执行开启动作。

### 2.2 方向性锁阻断模型（Directional Locks）

门禁处于两场景边界上，往往具备非对称的阻断特性（例如门从室内反锁，室外无法推开，但室内可以直接拉开）：
* **锁记录结构（LockRecord）**：
  * **锁强度（Strength）**：整数标量，数值归零表示锁已损坏或解除。
  * **受阻侧方向（Side）**：指向受阻场景实体的强类型引用。若为 `null`，表示该锁为全向/双向死锁；若指向特定场景，表示仅当主体从该场景方向尝试访问时生效。
  * **来源追溯（Source）**：记录施加该锁的物理钥匙、机制或法术实体引用。
* **通达性裁决公式**：
  给定主体所在场景 $S$ 与目标门禁实体 $E$：

$$\text{IsLocked}(E, S) = \exists l \in E.\text{Locks} \;\Big(\; l.\text{Strength} > 0 \;\land\; (l.\text{Side} = \text{null} \lor l.\text{Side} = S) \;\Big)$$

$$\text{IsAccessible}(E, S) = (\neg E.\text{IsOpenable} \lor E.\text{IsOpen}) \land \neg \text{IsLocked}(E, S)$$

## 3. 容器收纳与所有权层级

容器（Container）用于容纳其他物理实体，在世界树中扮演子树分支容器角色：

### 3.1 环路安全约束（Acyclic Constraint）

移动实体进入容器时，必须执行严格的祖先拓扑检查：
* 严禁将容器放入自身内部。
* 严禁将容器放入自身当前所属的任意后代实体中。
* 违规操作直接在准备阶段拦截并报错，防止世界树出现不可遍历的拓扑环路。

### 3.2 存取原子协议（Safe Put & Take Protocol）

* **收纳操作（Put / Store）**：
  1. 验证目标容器处于当前主体所在场景且满足 $\text{IsAccessible}$ 通达条件；
  2. 验证物品当前已被主体随身持有（`item.Parent == actor`）；
  3. 验证容器未超过其容量上限；
  4. 提交阶段执行 `item.Reparent(container)`，将物品从角色背包移入容器。
* **取出操作（Take / Retrieve）**：
  1. 验证目标容器满足 $\text{IsAccessible}$ 通达条件；
  2. 验证物品确实直接位于该容器内部（`item.Parent == container`）；
  3. 验证主体具备随身携带物品的负重或槽位余量；
  4. 提交阶段执行 `item.Reparent(actor)`，将物品转移至角色背包。

## 4. 凭证匹配与解锁逻辑（Key & Token Matching）

* 拥有 `AccessToken` 角色或 `Tool` 角色的实体可以作为钥匙使用。
* 解锁动作必须同时指定门禁实体与使用的钥匙实体。
* 只有当钥匙与门禁上某条处于激活状态的锁记录来源（`Source`）相匹配，或具备专门的解锁切面时，该锁记录强度才被核销置零。
