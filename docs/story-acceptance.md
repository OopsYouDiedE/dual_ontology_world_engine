# CLI 剧情与实际体验验收

本流程适用于两阶段接手验收。执行已授权验收前，先核对设备插件、源码、工作区与入口；保留已有未提交工作，不以历史报告证明当前版本已通过。

## 批次与隔离

每批冻结实际源码、配置及 Release 程序集，记录提交身份和 SHA-256。用户明确授权并行验收时，使用独立 Agent、进程、窗口、输入通道、存档和输出目录；性能比较仍遵守根 AGENTS 的测量隔离要求。并发耗时按实际竞争条件报告，不冒充隔离性能。代码修正在独立分支进行；同批运行不修改其源码与程序集，修复后重新冻结并复测。

剧情接手验收任务的固定输出为 `artifacts/story-acceptance/current/`；其他任务使用各自的固定目录。各场景单独占用目录；每次替换前确认对应游戏和审查读者均已结束。其他任务的证据、源码与未提交内容保持完整。

本文描述验收接口与证据要求，不授权启动正式会话；AI 运行、现实秒数、指标及盲玩须由用户明确指定。

## 第一阶段：引擎 AI

使用正式 `dv_core/cli`，由 `--controller ai` 驱动，测试工具仅提交正式自主推进命令，不选择剧情答案或路线。当前生产任务图默认关闭，显式记录 `--opt-taskgraph off`。案例包括标准侦探乙、甲、丙、丁区，无侦探（`--zone none`，使用实际存在的观察者），以及愚蠢侦探；标准和愚蠢第二章比较必须使用同版法则与相同非策略配置。

分别审查实际调查、正确答复被接受、雀儿实际开门及人物反应，以及调查与心结、实际合作、开仓、药剂配制领取与施用、病程和伤亡的连续证据。人数目标与流程是否结束分开；相似剧情效果明确写出与现行设计的差异。不能预置答案、合作、伤亡，或经开发命令跳过正式行动。

## 第二阶段：外部模型盲玩

第一阶段通过后创建全新上下文的操作 Agent，仅提供启动方式、通用输入协议及体验评价要求。使用 `--controller llm` 关闭受控人物内置 AI，NPC 仍由引擎运行；玩家固定主观视角，不提供客观地图、源码、设计、答案、路线或过去记录。输入通过实际 CLI 交互通道完成，操作 Agent 与审查 Agent 分开。分别记录模型名称、实际输入、可见信息、失败和达成情况。

## 画面与正式证据

真实窗口截图与记录画布导出分别标明。现有 `capture_cli.py` 的 JPG 是已记录单元画布的离线栅格导出，不能标为操作系统终端截图。窗口隔离必须先验证句柄归属、独立输入、后台真实截图与中文显示，避免操作共享焦点。

关键行动前后留存 JPG。输入、当前窗口原文及画面编号使用带校验的二进制记录；正式 `.dvdag`、`.dvsave` 和 `.dvlog` 保持原始字节。离线审查以 `cli_interaction` 的聚焦、确认、结果及正式 `host_completion`、`action_execution`、观察、听闻等事件交叉核对。截图证明实际可见内容，结算事件证明世界效果；任何一方缺失均不得补推。

只读工具：
```powershell
python mcp/verification/audit_cli_evidence.py <场景>/session.dvdag --out <场景>/audit
```

该工具验证封存后输出原始节点和事件引用的 `events.dvlog`、`visible.dvlog`、`state.dvlog`、`key-events.dvlog`，并生成事件导航摘要。它不执行游戏、设置状态、判定通关或代替因果审查。索引中的缺失字段保留缺失，原始文件是权威依据。

## 报告

最终结果分别列出剧情逻辑、画面与正文、引擎 AI 达成、外部模型实际可玩性。失败列场景、输入、截图及事件依据；未执行、未到达、证据不足均明确写“未验证”。正常退出、达到时域和会议收束均不自动等于剧情达成。
