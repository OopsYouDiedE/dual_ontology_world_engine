# 五日原型：运行与游玩

正式入口是 `scenes/main/Main.tscn`，五日内容入口是 `assets/data/scenarios/campaign.dv`。玩家接管侦探，其他人物继续按照各自的需求、职责和已知信息行动；也可以把侦探交给 AI，观察全员自主运行。场景使用已发布的房间与家具，调查、推演、协商、言灵和日终推进都经过同一套 Core 规则。前四天有调查目标，第五天进入没有剧情任务指示的自主生活阶段。

## 1. 启动游戏

命令均在工程根目录执行。正式环境准备支持 **Windows / Linux x64**，使用工程指定的 **Godot .NET 4.7.2、.NET 8 SDK**；Python 依赖固定在 `mcp/game/requirements.txt`。已经准备好项目环境时，直接运行启动器即可。启动器会调用正式环境 MCP，校验资源、构建 C#、完成 Godot 导入，再打开游戏窗口。标题页选择 **“新游戏”**；继续已有进度选择 **“读取”**。

**Windows PowerShell：**

```powershell
# 仅首次准备 Python 环境时执行前两行；需要已有 Python 3.12。
py -3.12 -m venv .runtime/python
.\.runtime\python\Scripts\python.exe -m pip install -r mcp/game/requirements.txt

# 正常游玩
.\.runtime\python\Scripts\python.exe mcp/game/play.py
```

**Linux：**

```bash
# 仅首次准备 Python 环境时执行前两行；使用 Python 3.12 环境。
python3.12 -m venv .runtime/python
.runtime/python/bin/python -m pip install -r mcp/game/requirements.txt

# 正常游玩
.runtime/python/bin/python mcp/game/play.py
```

已经用 `mcp/game/.venv` 等其他项目虚拟环境安装过依赖时，可以使用那个环境的 Python 执行同一脚本。无需重复创建虚拟环境。启动参数如下；Windows 将示例里的 Python 路径替换成上面的 `.exe` 路径。

上述 Linux 图形启动需要可用的 X11 `DISPLAY` 与 Vulkan 驱动。无桌面服务器还须准备虚拟显示；本轮云端实机使用 `.runtime/linux-display/` 中已安装的私有 Xvfb 与 Mesa，整个验收不操作用户本地桌面。`run_environment.py` 安装项目引擎和工具，不负责系统显示依赖；相应准备条件与新机器配方见 [正式游戏 MCP](../mcp/game/README.md)。

```bash
# 新局中让侦探也由 AI 控制；进入窗口后仍需选择“新游戏”
.runtime/python/bin/python mcp/game/play.py --ai

# 打开项目对应版本的 Godot .NET 编辑器
.runtime/python/bin/python mcp/game/play.py --editor

# 另需编辑建筑或模型时，准备项目使用的 Blender
.runtime/python/bin/python mcp/game/play.py --with-blender

# 只准备和核验环境，不启动游戏
.runtime/python/bin/python mcp/game/run_environment.py --local-copy
```

第一次启动需要下载依赖、构建与导入资源；后续运行会复用已经核验的安装和编译结果。运行游戏不需要安装 Blender。压缩模型包由 `assets/packs/campaign_assets.json` 和 `campaign-models-000.bin` 至 `campaign-models-031.bin` 组成，32 片必须来自同一版本并全部存在；正式准备和 Godot 构建会校验并还原清单中的模型。若出现 `Missing or damaged versioned asset part`，按报错文件名补齐该版本资源后再启动。只下载源码而缺少这些分片，不能得到完整可运行的场景。

## 2. 玩家控制与存档

| 操作 | 作用 |
| --- | --- |
| WASD / 方向键 | 在当前房间内行走。 |
| 左键点击地面 | 沿当前房间可行走区域移动。 |
| 左键点击人物或家具 | 查看与该对象有关的已知行动；右侧也可以直接选择对象和行动。 |
| E | 选取身边有可用行动的人物或物件。 |
| Tab / 顶部“案卷” | 打开“证据与认知、脑内推演、言灵、协商、空间与动线、事件记录”。 |
| M | 打开案卷中的“空间与动线”。 |
| 鼠标滚轮 | 缩放视野。 |
| 右键 / Esc | 合上案卷，或取消尚未提交的接近路线与当前选取。 |
| “暂停 / 继续” | 暂停或恢复游戏时间及人物行动。 |
| 1× / 16× / 128× / 1024× | 调整时间倍率；高倍率适合等待日常活动和观察 AI。 |
| “交给 AI / 接管侦探” | 切换侦探控制权，其他 NPC 仍自主行动。 |
| “保存” | 保存当前正式会话进度。 |

选择行动后，侦探会先实际走近对应人物或家具，到达有效交互位置才向 Core 提交。跨房间行动也从当前合法行动中选择；地图记录已经到过的空间，不能用地图跳过行动条件。遇到“正在走近”或进度条时，等待该动作完成再选择下一项；若提示通路被挡住，可以调整接近方向并重试。行动是否出现取决于侦探当时知道什么、人在何处以及现场状态。

前四天现场分别显示任务进展和身体需要。任务建议只引用侦探已经解锁的目标及其前置步骤；精力、饱食或水分紧迫时，身体需要会提示先照顾自己。接管时由你选择行动，建议不会替你搜证或勾选推演卡片；交给 AI 后，它会保留被需要打断的任务，恢复后继续。第五天隐藏任务进度与任务推荐，保留身体需要、实际行动和自己认知所允许的现场选项。

房内接近时间跟随真实走动，人物到达后才开始交互。开门会出现短暂的目的地过渡，随后从目标房间的实际入口进入；跨房间路程仍会推进世界时间，路上的人物活动和事件继续发生。一次只加载一间房，过渡过程中请等抵达后再操作和保存。

**打开案卷不会自动暂停时间。** 需要慢慢读证据时，先点顶部“暂停”；准备继续调查或执行动作时恢复时间。若当前显示“全员自主运行”，先点“接管侦探”再亲自选择证据与行动。高倍率下 NPC 的工作、风险和事件也会继续发生，第一次游玩建议在调查和阅读时用低倍率，需要等待时再加速。

同伴会先完成自己的行走、护理、调查或签字，再留下可用的证言和记录。汇合时若目标列表暂时为空，留意现场人物与案卷事件；保持时间继续推进，等同伴到场或报告完成后再看新选项。阅读时暂停、等待时加速，可以保留调查时间，也能看清行动的先后关系。

每次玩家行动结束、会话回到可保存状态后会自动保存；离开游戏前仍可点一次“保存”并确认反馈。普通启动器的存档是 Godot 用户目录中的 `character-session.dvsave`，标题页“读取”恢复 Core 状态、人物认知、已发生事件和玩家视图，同时保留暂停状态与时间倍率。读取后仍处于暂停时，点“继续”即可。存档按实际剧情声明校验，改变剧情结构后应开新局；不要用替换事实或编辑存档的方式延续验收。通过 MCP 开出的独立会话使用自己的存档槽，见第 5 节。

## 3. 怎样完成调查、推演与协商

**先搜证，再行动。** 从居室、门锁、窗槛、家具、账册和在场人物开始调查。证据与认知页分开展示调查所得与已经推得的结论，新认知会解锁新的物件交互、追问和协作请求。一个人物暂时没有可谈的内容，或一件家具没有新选项，通常意味着尚未得到与它有关的线索；结合事件记录和空间动线继续调查。

“事件记录”可以按日筛选、合并重复生活记录，并展开证据来源与机制结果。转述和亲自调查保持区别，未查明的来源不会标成亲见；失败的推演或请求也会留下记录，方便比较补证前后的变化。

**脑内推演需要亲自选证据。** 当新的推演问题出现，打开“脑内推演”，选择问题，勾选支持结论的已知证据，再点“提交选中的证据并推演”。右页保留待检验的问题与适用范围，提交后显示实际支持或反驳结果；未解问题不会预先显示完整答案规则。系统只接受该侦探实际取得的证据，并记录来源；少选关键证据时可能得到“未成立”，不会凭空生成认知。失败后仍可补查、重新选择并再试。空间通路、门锁状态、痕迹先后和人物是否能在相应时刻到达，都是可进入推演的依据。

**协商由对方独立判断。** “协商”页中的请求会带上已掌握的证据，由目标 NPC 根据证据、信任、职责、风险和代价分别评估。对方忙于工作与是否采纳建议是两个不同问题；一次拒绝也不等于此后永久无法合作。先读具体反馈，再取得新的依据或改变真实作业条件，之后可再次提出尚未完成的请求。对方答应后，有些事项还需要其实际归还物品、修理、签字或操作机关；只得到口头承诺不足以完成案件。

**言灵要先理解边界与代价。** 第四日调查能解锁局部封隔的认知。到合适现场后，在“言灵”页选择当前合法语句，查看结果中的资源消耗、反噬、规则和失效时刻，再利用短时改变争取协作。当前封隔言灵消耗 12 点意志、增加 3 点侵蚀，维持 45 个游戏分钟；亲见效果的协作者会重新评估作业风险。临时规则会到期，后续机械作业需要在其有效时间内落实，完成后的机械防护有自己的持久状态。

## 4. 五日实际内容

以下是已经写入正式剧情与机制的内容范围，不表示每条可选分支都已经完成了最终实机验收。

| 日程 | 现场与故事推进 | 玩家需要做的事情 |
| --- | --- | --- |
| 第一天：苏醒与四区调查 | 居室中的异常、乙区痕迹与人物动线、四区历史、讲堂诗稿、契约和共同生活逐步展开。 | 搜查房间、门锁、窗与痕迹，交叉核对人物证言，通过多项推演建立痕迹顺序、第五实体线索、历史关联及诗稿归属，参加后续共同活动。 |
| 第二天：粮仓、配给与四院初探 | 开仓受真实结构、锁芯和绞盘条件约束；四位专业 NPC 分别前往文契、白塔、铁工、星仪院巡检，返回中翼签署记录。 | 核对账册与存量，推演双轨配给并分别说服相关人物；午后按真实接驳关系进入四院搜证，用十项证据交叉核对现场与报告。对工具和药品的提前保管会改变后续情境。 |
| 第三天：阮清月的试探 | 根据她知道的情境和收益，实际选择探针、药品记录或配给票据相关的谋划。各分支使用不同的物证、授权关系和归还或更正后果。 | 沿物品与文书的真实去向搜证，区分知情、授权和占有，完成相应推演与对质；确认失物真正归还、记录真正更正及当事人的实际表态。 |
| 第四天：微震、倒灌与夜间防护 | 自然微震引发地下层危险，救援、暴露剂量、搬运、施药与伤情有实际状态；空间包括独立的控制室、阀廊与坡道。 | 搜集拓扑、闭合边界、污染旁路和契约限制，推演安全作业范围；评估夜间方案，用言灵改变短时条件并争取协作。封隔、转移与守夜具有不同代价和结果。 |
| 第五天：自主生活 | 延续此前的伤情、物资、认知和关系。煮饭、个人饮水及清洗敷料共享资源，携带、配送、护理与休息占用真实时间和位置；各人也可处理自己的兴趣与交流。 | 没有固定剧情任务。根据自己看到的情况选择行动，照料身体、调查或帮助同伴，也可交给 AI 观察。意见采纳仍独立评估，角色可拒绝、改做别的事或采用可行替代。 |

第二天完成配给协调后，从 12:30 起可到二楼中翼展开四院调查。文契 W-102 的纸墨台、白塔 B-102 的配药柜、铁工 F-104 的备件台和星仪 S-102 的校准仪器各有独立现场证据；四院通过建筑拓扑规定的楼层与接驳通路访问。风窗 17:00 关闭，16:30 停止新出发、16:45 停止新作业；已在院内时仍可沿原通路回楼。中翼登记台可以读取四份由 NPC 实际到场后签署的报告。亲访四室并核对十项证据，会得到带现场来源的资源边界判断；若错过风窗，17:01 后仍可用已读的路线、清册和四份签名报告做有限推演，所得结论保留“转述”依据，未见过的院内痕迹仍然未知。完成判断后回食堂继续晚间流程。

第四天进入伊莲娜房间后，可通过房门选择沿原路回地下控制室；这条返程不依赖伤情对话是否仍可进行。时效性调查与作业应以当前可见状态为准。四院和第五天自主生活均改变了新局的世界初始声明，旧版存档需要保留在原版本游玩；本版的完整流程从标题“新游戏”开始。

第五日 24:00 到达观察边界，界面显示“观察窗口结束”，不要求全员归档、签字或入睡。这个提示只表示五天已经走完，调查结果和人物生活状况仍由实际行动决定。案卷保留亲见、转述、推演和仍有限定的假说，部分世界深层问题仍是后续故事的开放问题。可以正常保存，并从结束界面返回标题重新开局或读取存档。

人物还会追求求知、专业责任和自主决定的满足。过去的职业经验可以由本人说出，交流请求仍需对方同意，再由其实际答复；第一晚的共同生活只改善一部分气氛，不会自动消除对最初事故的分歧。开放日的登记、撤回条款、担保、见证、研究条件和用水安排会留下真实的署名记录。看见提案、口头答应、交付原件和实际实施是分别发生的事情，读到一份方案不能证明所有相关人物都已赞同。人物可以拒绝、提出限制、收回原先的代言或根据已见条件另拟方案。

知道某个做法，也可能在现场做不成。未学会的动作不会出现在候选中；已经知道的做法可保留第一次尝试，缺料、占用或机会消失会产生真实失败反馈，后续自动选择会降低重复尝试的优先级。本人获得相关的新观察或过了重试间隔，才重新判断。一次失败不会产生成功奖励，也不会把设想写成已经发生的事实。

## 5. 正式自动运行与 SubAgent 接管入口

**全 AI 模式**通过正式自动 MCP 入口运行，并保持连接直到完成、失败或截止时间。命令中的时长是包含构建与启动的墙钟秒数。先准备环境，再运行所需宿主；Windows 替换 Python 路径即可。

```bash
.runtime/python/bin/python mcp/game/run_environment.py --local-copy

# 真实 Godot 全 AI 运行
.runtime/python/bin/python mcp/game/run_auto.py --backend godot --duration-seconds 7200 --seed 1 --content-path assets/data/scenarios/campaign.dv --receipt .runtime/runs/five-day-godot-auto.json

# 同一 Core 的 CLI 全 AI 验证
.runtime/python/bin/python mcp/game/run_auto.py --backend cli --duration-seconds 600 --seed 1 --content-path assets/data/scenarios/campaign.dv --receipt .runtime/runs/five-day-cli-auto.json
```

脚本也接受带时区的 `--deadline`，与 `--duration-seconds` 二选一。回执中的 `status=deadline_reached` 只表示达到墙钟运行期限；`failed` 和宿主提前停止不能按流程完成计算。在本版 `observation_window` 模式中，`campaign_progress.window_completed=true` 表示已走完五日观察时间，`campaign_completed` 与该时间边界一致。前四日核心剧情、实际机制使用和第五日自主交互须另外读取真实记录核对，不能用时间完成标记代替。全 AI 运行不需要外部代理代选关键动作。

**SubAgent 接管或保留操作回执的游玩**使用持久输入客户端。每个代理开自己的连接，按最新完整观察串行操作，结束正常 `close`。

```bash
.runtime/python/bin/python -u mcp/game/input_client.py
```

在客户端中逐行发送以下 JSON；先读返回的回执路径，再继续下一项。`background_capture=false` 打开可见窗口，`true` 用于仍真实渲染的后台会话。固定 `save_slot` 才能在新连接中读取同一个槽；不要与别的代理共用槽。

```json
{"tool":"on","arguments":{"backend":"godot","seed":1,"viewer":"detective","content_path":"assets/data/scenarios/campaign.dv","background_capture":false,"save_slot":"five-day-player"}}
{"tool":"step","arguments":{"operation":{"type":"start"}}}
{"tool":"observe","arguments":{}}
```

之后可以直接操作窗口，也可以根据最新观察提交 `step`。行动 ID 和推演证据 ID 必须来自当前观察，不能从剧情文件预填未取得的事实。需要保存时发送：

```json
{"tool":"step","arguments":{"operation":{"type":"character","command":"save"}}}
{"tool":"close","arguments":{}}
```

下次使用同一 `save_slot` 重新 `on` 后，在标题页选择“读取”，或发送 `{"tool":"step","arguments":{"operation":{"type":"load"}}}`。客户端会保存原始回执与观察图；新局、搜证、推演失败与重试、言灵代价、意见采纳以及最终闭环都应以这些实际回执为证。详细协议见 [正式游戏 MCP](../mcp/game/README.md)。

## 6. 资源范围

正式游戏使用 `assets/scenes/campaign_rooms/` 的发布房间与共享家具，37 个逻辑空间对应 36 份房间场景。模型由 32 个压缩分片提供，完整包约 7.45 MB，包含 265 个 GLB，展开约 68.70 MB。四院复用已有模型；发布清单和分片清单记录所需文件与校验摘要，启动时验证一致性。候选场景库、预览、引擎、依赖缓存、连续截图、原始运行记录和验收报告不随游戏源码发布。
