# 独创躯体心智非对称解耦规范

## 商业领域现有技术局限

在成熟商业游戏引擎与仿真框架中（如 Unreal Engine 的 Pawn 与 PlayerController/AIController、Unity 的 GameObject 与 MonoBehavior 组件体系），可交互对象始终维持 单肉体-单控制器的一对一绑定假定。控制器虽可通过 Possess() / Unpossess() 切换附身目标，但在同一时间片内，一具物理实体只能由一个控制主体驱动，一个控制器也只能占用一具肉体。这一模式无法天然支撑多重人格冲突、潜意识独立运作、群体心智同步支配等复杂叙事与交互需求。

---

## 本系统独创设计

本系统在底层实体体系中，将物理交互承载与主观认知意志彻底拆解为平级且完全解耦的独立实体：物理角色实体（Character）与心智灵魂实体（Soul）。

### 非对称多对多支配拓扑

Character 与 Soul 通过双向强类型切面（FacetType.Character 与 FacetType.Soul）实现多对多映射：
- 单体多心智共存：一具物理肉体可同时挂载多个独立的 Soul 实体（例如主人格、潜意识人格、附身恶灵）。每个 Soul 维护私有的信念库、情绪状态与决策管线，在行动前夕各自评估候选意图并竞争身体支配权。
- 单心智多体支配：单个 Soul 实体可同时绑定多个 Character 物理实体，执行分布式多肉体协同动作或跨空间视界共享。

### 属性与生命周期边界切分

系统在内存与架构边界上严格划定职责：
- 肉体边界（Character）：属于世界物理树节点，持有空间坐标、随身背包收纳（Inventory，挂载在其子节点下的非 Soul 实体）、客观物理性质与行动执行器。
- 心智边界（Soul）：脱离世界物理树，不具备物理碰撞与空间位置，仅封装事实观察列表（Observations）、规则信念集合（Beliefs）、人格偏好（PreferenceDelegate）、对数情绪强度与多步决策历史。
