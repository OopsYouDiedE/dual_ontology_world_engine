# 核心引擎独立设计研究（第一阶段）

> 研究边界：本文只依据 `core_support_fetures.md` 中列出的要求进行独立设计；未读取项目其他上下文，未使用网络资料。

## 1. 研究结论

推荐采用一个“**有界、分层、因果化的事务微内核**”：世界是不可变版本上的类型化关系图；任何行动统一成为意图；规则只能读取冻结快照并提出候选效果；候选效果经过反应闭包、冲突求解、守恒与公理核验后原子提交；文学层只消费已提交的因果证明，不得反向改写事实。

内核最重要的可证明承诺是：

\[
\boxed{
\text{每个结算批次都在有限资源内，确定地提交一个满足公理的完整版本，}
\text{或安全失败并返回可验证证书。}
}
\]

这不是“所有规则必定成功”，而是“不收敛、越权、资源复制、冲突无解时绝不提交半成品”。

数学不能证明文本必然优美，但可以严格保证文学赖以成立的基础：因果可追、视角诚实、角色身份连续、代价真实、知识有限、行动与结果分离、伏笔和后果不凭空出现。审美、文风和作品特有主题仍由专用库负责。

## 2. 总体分层

| 层级 | 职责 | 禁止事项 |
|---|---|---|
| 核心微内核 | 版本、事务、实体、关系、意图、事件、资源、作用域、认知隔离、时间分支、冲突与证明 | 不认识作品名词，不运行任意 Python 规则回调 |
| 通用机制模块 | 契约、污染、语义寻址、自动能力、灵魂与身体分离、局部规则空间、能力推理、主体相变 | 不拥有特权写通道，必须编译成核心协议 |
| 专用库 | 世界规则、具体能力、平衡参数、相变结果、自然语言、视觉与叙事风格 | 不绕过权限、费用、作用域、事务和认知隔离 |
| 决策与叙事 | 从角色认知生成意图；从已提交因果图组织话语 | 不读取隐藏客观规则，不为了“更戏剧化”修改世界 |

依赖只能向下：专用库组合通用模块，通用模块编译到核心；核心不依赖任何作品答案。

## 4. 形式世界模型

世界版本定义为：

\[
V=(id,branch,parents,generation,world\_time,S,\Delta,cause,ruleset\_hash)
\]

其中 `generation` 沿因果父边严格递增，即使世界内时间回退也不会形成因果环。世界状态为：

\[
S=(F,R,Q,C,P,K)
\]

| 分量 | 含义 |
|---|---|
| \(F\) | 实体及其客观事实 |
| \(R\) | 显式关系超图 |
| \(Q\) | 资源、托管、在途资源的规范账本 |
| \(C\) | 通道租约、持续效果、义务状态 |
| \(P\) | 计划事件 |
| \(K\) | 信息载体、感知回执、记忆与信念状态；按访问能力隔离 |

任何可产生世界效力的引用必须使用：

\[
WorldRef=(branch\_id,local\_id,epoch)
\]

候选事务从单一冻结版本读取：

\[
Tx=(base,read\_facts,predicate\_reads,proposals,trace)
\]

提交条件为：

\[
head_{branch}=base
\land ReadsStillValid
\land Preconditions
\land Permissions
\land Resources
\land Axioms(S\oplus\Delta)
\]

成功时一次产生新版本；任一条件失败则保持原状态。

## 5. Python 核心骨架

Python 是实现语言，但正式规则不能是任意 Python 回调。Python 负责解释受限规则 IR、管理持久化状态和执行验证器。

```python
from dataclasses import dataclass
from decimal import Decimal
from fractions import Fraction
from typing import NewType

VersionId = NewType("VersionId", str)
BranchId = NewType("BranchId", str)
EntityId = NewType("EntityId", str)
SubjectId = NewType("SubjectId", str)
RuleId = NewType("RuleId", str)
FactId = NewType("FactId", str)

@dataclass(frozen=True, slots=True)
class WorldRef:
    branch: BranchId
    local_id: str
    epoch: int

@dataclass(frozen=True, slots=True)
class WorldVersion:
    id: VersionId
    branch: BranchId
    parents: tuple[VersionId, ...]
    generation: int
    world_time: Decimal
    state_root: str
    delta_root: str
    cause_id: str
    ruleset_hash: str
    commit_seq: int

@dataclass(frozen=True, slots=True)
class Relation:
    id: WorldRef
    kind: str
    endpoints: tuple[tuple[str, WorldRef], ...]
    scope_id: str
    valid_from: VersionId
    valid_until: VersionId | None
    provenance: FactId

@dataclass(frozen=True, slots=True)
class Intent:
    id: str
    actor: WorldRef
    action: str
    target_expression: object
    ability_source: WorldRef
    based_on: VersionId
    proof_hints: tuple[FactId, ...] = ()

@dataclass(frozen=True, slots=True)
class PredicateReadToken:
    query_kind: str
    normalized_query: bytes
    index_partition: str
    dependency_epoch: int
    negative_keys: tuple[bytes, ...]

@dataclass(frozen=True, slots=True)
class LedgerEntry:
    account: WorldRef
    resource_type: str
    quantity: Fraction
    provenance_rule: RuleId

@dataclass(frozen=True, slots=True)
class Proposal:
    id: str
    reaction_key: tuple[str, ...]
    phase: str
    read_paths: tuple[tuple[str, ...], ...]
    write_paths: tuple[tuple[str, ...], ...]
    operations: tuple[object, ...]
    provenance: str
```

关键实现约束：

- 全部正式值不可变，不把可变 `dict/list` 引用暴露给规则；
- 守恒、阈值和竞争判定使用整数、`Fraction`、定点数或统一舍入的 `Decimal`，禁止 `NaN` 和无穷；
- 映射、集合、Unicode、数值与序列化必须规范化；哈希只作索引，关键等同性仍比较规范结构；
- 版本哈希不包含 `CommitSucceeded` trace，防止版本—trace 自指；
- 核心事务路径不执行不受限 IO、模板或用户 Python；外部输出使用提交后幂等 outbox。

## 6. 单批次结算算法

```text
1. 冻结输入版本、规则集哈希、分支头与可寻址对象宇宙
2. 规范化意图，解析有限作用域，登记正/负谓词读取
3. 从当前版本事实重建权限证明
4. 展开费用、托管、通道租约、关系和相变计划
5. 对 PRE_COMMIT 规则执行有界分层反应闭包
6. 冻结 proposal 多重集；冲突解析期间不得重新触发规则
7. 构造冲突图与语义原子组，逐冲突分量解析
8. 重验作用域、证明、身份纪元、守恒、容量、基数和全部受影响公理
9. 执行可串行化 MVCC 验证并原子提交
10. 生成类型化 trace；经认知投影后产生 POST_COMMIT 下一批次意图
```

若第 5—8 步出现此前未登记的新读取依赖，必须回到对应展开阶段；禁止在最终验证时偷偷补读后继续提交。

### 6.1 反应终止

建立带正负极性的规则依赖图并求强连通分量：

- 正向单调 SCC 只能由类型系统已证明单调的 DSL 原语组成；
- 状态必须位于编码大小、宽度和高度均有界的有限格；
- 含否定、删除、撤销、覆盖的 SCC 不能在同层迭代；
- 非单调过程只能拓扑单次执行、延迟到下一批次，或提供机器可验证的良基秩。

单调闭包为：

\[
x_{n+1}=x_n\sqcup f(x_n)
\]

若格高度为 \(H\)，严格增长最多发生 \(H\) 次。需要同时冻结目标域和创建槽位，否则规则可以通过不断创建新 UUID 偷偷把格变成无限。

反应键：

\[
K=(rule,target,inputVersion,eventLineage,phase)
\]

同批次每个键最多求值一次，但它只是去重，不是单独的终止证明。

### 6.2 资源上界与安全失败

受限解释器对以下预算分别计量：CPU 指令、agenda 节点、候选补丁、创建槽位、整数位宽、集合编码字节、trace 节点、因果深度和同刻微批次数。

为失败收尾预留不可挪用预算。超限时整个候选失败；不得截断一半后提交。完全相同的 `(intent, version, ruleset_hash, budget_profile)` 不得自动无限重试。

因此燃料证明的是“内核有限步返回”，合法规则集的成功收敛则由分层、有限格或良基秩证明；两者不能混为一谈。

## 7. 核心数学不变量

### 7.1 状态与因果

| 编号 | 不变量 |
|---|---|
| S1 | 已发布旧版本永不改变 |
| S2 | 外部只能观察原版本或完整新版本，不存在部分提交 |
| S3 | 所有正式判断读取同一基版本；提交时验证全部谓词读与索引纪元 |
| S4 | `parent.generation < child.generation`，因果版本图无环 |
| S5 | 每个写入都有意图、事件、规则和证明来源 |
| S6 | 相同版本、规则集、意图和种子得到相同结果或相同失败证书 |
| S7 | 状态/trace 与外部消息采用持久化事务或 WAL + outbox 保证崩溃恢复边界 |

只做快照隔离不够。空间范围、“不存在撤销关系”、所有权语义寻址等查询必须记录谓词读令牌，否则仍会发生幻读和写偏斜。

### 7.2 身份、关系与相变

排他身份侧面由模式固定，不允许相变计划自行改成可复制：

\[
schema(f)=EXCLUSIVE
\Rightarrow
\sum_{d\in descendants}activeClaim(d,f)=1
\]

每个源身份纪元只能成功消费一次：

\[
\#CommittedTransitions(branch,subject,identityEpoch)\le1
\]

相变对每个侧面显式声明 `MOVE / COPY / DROP / DERIVE`。记忆可复制不表示身份、钱包、唯一能力或凭证可复制。关系模式还必须规定端点删除后的级联语义；超边不能因删去一个端点而被默认为仍有效的另一种关系。

相变原子性：

\[
Committed\Rightarrow \neg Active(old)\land Active(new)\land Complete(inheritance)
\]

\[
\neg Committed\Rightarrow W'=W
\]

### 7.3 资源与转换

普通转移对每类资源满足：

\[
\sum_a\Delta balance(a,r)=0
\]

允许生成或销毁时：

\[
\Delta C_r=Mint_r-Burn_r
\]

`Mint/Burn` 必须有世界规则授权、来源和配额。借用只移动当前保管账户，并另建债权；不得让双方都保留可支付余额。封印、可用性和主体持有均为派生视图，不能成为第二份权威余额。

对同一封闭转换域的化学计量矩阵 \(N\)，必须存在共同正势：

\[
p>0,\qquad \forall j,\ p^TN_j\le0
\]

如果存在 \(x\ge0\) 使 \(Nx\ge0\) 且至少一项严格增长，说明存在循环增殖漏洞。延迟产物必须现在建立唯一在途凭证：

\[
input\rightarrow inFlightClaim\rightarrow output
\]

回溯、取消和失败只能对该凭证唯一地退款、销毁或结算。

### 7.4 通道、抢占与传播

对通道 \(c\)：

\[
\sum_{\ell\in L_c}usage(\ell,c)\le capacity(c)
\]

释放必须匹配 `LeaseId`；不兼容类不能并存；抢占偏序必须无环或每步严格降秩。催化剂等不消耗但有并发限制的对象也必须申请租约。

传播环必须满足无环、良基秩下降、正耗散或有限 lineage/边访问约束之一。只使用浮点衰减不会终止；最小量子截断必须流入残留槽，不能破坏守恒。

### 7.5 权限

权限成立必须由当前分支版本推出：

\[
W_v\vdash actor\ may\ action(target,scope)
\]

证明叶子在闭包完成后重验，并绑定版本、分支、身份纪元与撤销纪元。调用者提供的 proof 只是查找提示；内核自行重建。候选效果不能成为自身权限的前提。

## 8. 短时间稳定与防震荡

### 8.1 单批次

单批次内通过冻结输入、分层依赖、单调有限格/良基秩、冻结 proposal 和一次性纯冲突解析，严格排除批内无限自激和冲突解析震荡。

### 8.2 跨批次

滞回只防小噪声，不保证在持续外源驱动下最终静止。对阈值、边界、信念和策略分别使用：

\[
enter:x\ge\theta_{up},\qquad exit:x\le\theta_{down},
\quad \theta_{down}<\theta_{up}
\]

再加入最短驻留时间、切换成本、新证据要求、待处理意图合并与最大陈旧度。三态及更多状态要检查完整转换图，不能只检查成对滞回。

任何零时间自动后继必须至少满足一项：良基秩严格下降、消耗不少于 \(\epsilon>0\) 的不可再生资源、或推进至少 \(\Delta t_{min}>0\) 的世界时间。因此观察窗口 \(T\) 内：

\[
N_{events}\le
N_{rank}+\frac{Q_{available}}{\epsilon}
+\left\lceil\frac{T}{\Delta t_{min}}\right\rceil E_{perTick}
\]

相变若最短驻留时间为 \(\tau\)：

\[
N_{phase}(T)\le1+\left\lfloor T/\tau\right\rfloor
\]

对无限外源输入不能承诺最终静止，只能承诺给定窗口中的事件数和切换频率有界。延迟动作提交前必须重验；超过最大陈旧度即取消或形成新意图。

### 8.3 决策稳定而不僵化

信念接受和否定使用双阈值；策略承诺、规范承诺和信念滞回是三种不同状态，不能共用一个锁。承诺必须有作用域、期限、撤销条件与累计反证预算。

必须同时满足：

- 噪声免疫：阈值间小扰动不反复切换；
- 有限响应：持续独立反证最终能离开接受区；
- 幂等更新：同一证据、同一版本重复输入不改变结果；
- 不刷新：重复证据不能重置承诺期限。

## 9. 认知、证据与精神状态

唯一合法知识路径为：

\[
W_v\rightarrow InformationArtifact\rightarrow Perception
\rightarrow Memory\rightarrow Interpretation/Belief
\]

不存在 `ObjectiveWorld → NPCBelief` 捷径。NPC 只接收不含客观对象引用、隐藏 ID、真实规则、执行耗时或开发者错误信息的 `EpistemicView`。

核心隔离性质为认知不干涉：

\[
Obs_a(W_1)=Obs_a(W_2)
\Rightarrow
View_a(W_1)\cong View_a(W_2)
\land \pi_a(\cdot|W_1)=\pi_a(\cdot|W_2)
\]

同构必须忽略内部客观 ID。失败回执、缓存、候选数量和耗时也属于潜在侧信道。

证据不是一条可复制的分数，而是有来源祖先图的账本。复制录像、转述谣言、失忆后重读自己的笔记都不能增加独立证据量。派生图不得自环；干预后的结果只支持带干预条件的命题，不能直接验证无干预假设。

信念从有效证据账本重算，可采用有界对数似然或区间更新，但数值饱和不能成为隐藏证据。强冲突时保留不确定区间；非公理信念在持续、充分且独立的反证下必须具有可纠正性，除非人格、污染或认知损伤以显式世界状态阻止它。

精神状态使用连续量与符号约束的混合向量，例如情绪调节、认知整合、身份连续、记忆完整、人格边界和偏好偏移。正常稳定区可采用耗散更新：

\[
X_{t+1}=\Pi_D((1-\alpha)X_t+\alpha X^{base}+G_t)
\]

若反馈依赖状态且 Lipschitz 常数为 \(L_G\)，要求：

\[
|1-\alpha|+L_G<1
\]

越过结构阈值时不得偷偷进入不稳定动力学，而应生成显式候选相变。

## 10. 文学性接口

### 10.1 可证明的文学底线

每个已提交变化生成叙事原子：

\[
N=(actor,intent,obstacle,intervention,change,cost,witness,causes)
\]

由此可严格检查：

| 底线 | 检查方式 |
|---|---|
| 因果连贯 | 每个结果引用已提交原因、使能条件、阻碍或介入；不把单纯先后写成因果 |
| 视角诚实 | POV 文本只能读取对应 `EpistemicTrace`；全知权限需显式声明 |
| 动机不倒推 | 内心动机必须来自当时的 `DecisionTrace`，不能由结果事后编造 |
| 代价真实 | 叙述中的支付、损失、债务引用正式账本或义务事实 |
| 时间诚实 | 当前叙述不读取未来 trace；回顾模式必须显式标记 |
| 行动能动性 | 决策产生统一意图，任务与叙述不能替角色直接制造结果 |
| 信息诚实 | 谎言、传闻和不可靠叙述是信息载体内容，不自动成为客观事实 |

### 10.2 决策选择

不使用单一全局“文学效用”。推荐流程：

```text
主体已知的动作语汇
→ 构成性禁令与已知显式义务
→ 按角色稳定价值偏序分层
→ 同层局部 Pareto / ε-支配
→ 满足化、切换成本与承诺检查
→ 仅在主体视角下近似等价的有限候选间使用固定种子
→ 提交统一意图，由客观层决定成功或失败
```

角色未知的客观不可能性不能在决策层过滤其尝试。主题、意象、反讽属于叙事注解，只影响如何表达和多样性诊断，不能单独迫使角色行动。

候选集在评估前冻结并有上限；价值维度必须属于版本化的角色/场景模型，装饰指标不得注入 Pareto 计算。无满足解时返回诊断和不改世界的安全表现模板，不能降低硬约束或反改事实。

### 10.3 故事与话语分离

- `Fabula`：已提交事件和因果图；
- `Discourse`：在某 POV、时间范围和叙述策略下组织表现；
- `PublicationEvent`：文本若真的进入世界成为话语、信件或广播，必须在下一批次提交普通意图。

叙事渲染是纯函数。当前批次的文学输出不得成为自身评分输入。若文本模型或模板失败，使用有限的确定性回退模板；渲染失败不能拖垮世界核心。

数学稳定但故事停滞是可能的。核心可提供只读 `StagnationAnalyzer` 检测等待环、长期无新证据、候选不变、理由重复和任务缺乏活性，但不得以“剧情需要”为理由生成弱点、冲动或新事件。

## 11. 时间分支与冲突安全

回溯创建新分支：

\[
V_{new}=Branch(V_{current},V_{base},\Pi)
\]

投影 \(\Pi\) 显式声明身体、地点、记忆、能力内部记录、计划事件、义务和资源如何继承。默认不同分支不能普通互引：

\[
branch_i\ne branch_j\Rightarrow NoOrdinaryReference(i,j)
\]

跨分支合并必须作为专用时间规则执行原子对账：唯一资产、资源、身份后继、权限重建、租约重申请、计划事件去重、债权义务和记忆继承全部核验。记忆继承不自动携带权限、资源、租约或未来兑奖权。

冲突先构图，再按连通分量解析。需要区分语义原子组、同批调度组和冲突分量。“共同失败”只影响同一语义冲突分量，不能让一个廉价外部意图把整批无关行动拖入失败。普通并发冲突采用预留、公平串行、有界重算或显式 `ConcurrentModification`；失败事务本身不是世界事件。

## 12. 失败证书与可解释性

trace 是只追加、类型化、序号严格递增的证明 DAG。至少记录意图接收、条件、权限、资源预留、触发、反应、候选、冲突、公理与提交。

失败证书至少包含：输入版本、规则集哈希、涉事规则、反应键、状态摘要、公理编号、冲突分量、预算消耗和见证。重要类型包括：

| 类型 | 见证 |
|---|---|
| `NonConvergentRuleSCC` | SCC、正负边、未下降排名或重复状态 |
| `UnresolvedConflict` | 冲突分量、不可比较偏序、缺失策略 |
| `InvariantViolation` | 公理编号、路径、反例值 |
| `PredicateReadInvalidated` | 查询、旧/新索引纪元、结果差异 |
| `IdentityEpochConsumed` | 分支、主体、纪元及已提交相变 |
| `BudgetExceeded` | 各预算消耗、剩余 agenda 与摘要 trace |
| `CrossBranchReference` | 非法跨分支引用及缺失合并规则 |

失败证书属于操作日志，不进入原事务世界。若世界中的角色需要感知故障，之后由独立、受限的系统意图提交可感知摘要。

## 13. 必须拒绝的规则

| 编号 | 拒绝条件 |
|---|---|
| R1 | 正式条件、效果或冲突使用不受限 Python 回调 |
| R2 | 作用域或权限存在未登记的负面/范围读取 |
| R3 | 同批闭包可以动态扩张出无界目标、数值、字符串、事件或证明节点 |
| R4 | 非单调 SCC 没有分层、延迟或机器可验证下降度量 |
| R5 | 资源变化绕过统一账本，或转换域不存在共同正势且无显式外部源 |
| R6 | 权限依赖同一意图尚未提交的效果，或证明分支/纪元不匹配 |
| R7 | 相变复制排他侧面，或源身份纪元已消费 |
| R8 | 时间分支对象未经显式合并规则发生普通交互 |
| R9 | 冲突结果依赖创建顺序、加载顺序、集合遍历顺序或墙钟 |
| R10 | 共同失败范围无法证明属于同一语义冲突分量 |
| R11 | NPC 决策可观察隐藏 ID、候选数量、客观错误、耗时、共享缓存或开发 trace |
| R12 | 叙事渲染能直接修改客观世界或把未来信息写入当前 POV |

## 14. 对抗性验证矩阵

| 类别 | 必测性质/案例 |
|---|---|
| 事务 | 写偏斜、空间幻读、否定关系幻读、ABA、规则热更新、CAS 活锁、掉电恢复 |
| 反应 | 门开/关互触发；护盾取消/返还/重建；新 UUID 扩域；证明 DAG 语义重复 |
| 身份 | 双相变消费；分身复制唯一能力；记忆复制冒充身份；普通关系复制旁路 |
| 资源 | 转移与相变并发复制；借用双记；延迟奖励重复；催化剂并发；转换闭环套利 |
| 时间 | 回溯复制唯一物；保留旧权限；计划事件双兑奖；撤销代价但保留收益 |
| 决策 | 阈值噪声、三态循环、延迟反馈、同步群振荡、承诺僵化、重复证据刷新承诺 |
| 认知 | 隐藏事实不干涉；失败原因投影；ID 不透明；多 POV 禁并集；时间/缓存侧信道 |
| 证据 | 复制/转述不增权；祖先环拒绝；自证预言分离；预测预登记；持续反证可纠正 |
| 文学 | 主题不能覆盖人物；未知客观禁制不阻止尝试；动机不倒推；POV 不泄漏；渲染纯函数 |
| 冲突 | 加载顺序置换不变；外部廉价意图不能零成本否决；不同冲突分量不整体回滚 |

建议大量使用性质测试与状态机生成测试，而不是只写手工范例。核心验收标准应是：对随机生成的合法规则与世界状态，任何提交都维持全部不变量；任何超界或不收敛结构都在有限资源内安全失败。

## 15. 保证边界

| 承诺 | 强度 | 前提/限制 |
|---|---|---|
| 不暴露半完成状态 | 严格 | 原子持久化与提交后 outbox |
| 旧版本不被污染 | 严格 | 深度不可变，不泄漏可变引用 |
| 单批次有限步返回 | 严格 | 受限 DSL，多维资源预算，失败收尾预留 |
| 合法单调/良基规则收敛 | 严格 | 有限冻结域，机器验证单调性或下降度量 |
| 冲突与重放不依赖遍历顺序 | 严格 | 规范化、冻结 proposal、纯解析器、固定规则集/种子 |
| 资源、身份、权限与通道不被组合绕过 | 严格 | 统一账本、身份纪元、证明重建、最终全量重验 |
| 角色不偷看客观真相 | 严格到接口层 | 类型隔离、不干涉测试；进程/硬件侧信道需额外隔离 |
| 给定短窗口内事件与切换次数有界 | 严格到模型层 | 排名/耗散/最小时间推进、驻留与队列上限 |
| 无限外源下最终静止 | 不保证 | 玩家可持续交替输入；只能约束频率和资源 |
| 任意作者规则都成功 | 不保证 | 无解冲突和非法规则应安全失败 |
| 数值永远“好玩且平衡” | 受限保证 | 核心检查守恒、势函数和界；参数质量属于专用库 |
| 文本必然有文学美感 | 不保证 | 只能严格保证文学基础与不越权 |
| 硬件、解释器或网络故障下绝不崩溃 | 不可能绝对保证 | WAL、校验、隔离进程、恢复协议降低风险 |

## 16. 推荐实施顺序

| 阶段 | 产物 | 验收门槛 |
|---|---|---|
| 0. 形式规范 | 类型、规则 IR、阶段、读写集、不变量、失败语义 | 所有核心概念有可判定边界 |
| 1. 纯内存参考核 | 不可变版本、意图、候选事务、原子提交、trace | 确定性重放与不变量性质测试通过 |
| 2. 规则验证器 | 依赖图、SCC、单调原语、良基秩、静态成本 | 非法自指与无界结构在装载期拒绝 |
| 3. 守恒与并发 | 统一账本、租约、谓词读、可串行化 MVCC | 双花、幻读、写偏斜和转换套利测试通过 |
| 4. 身份与时间 | 相变迁移、身份纪元、因果 DAG、分支继承 | 唯一物/权限/计划事件不能跨分支复制 |
| 5. 认知与决策 | 认知投影、证据祖先图、信念更新、决策 trace | 不干涉、可纠正性和防震荡测试通过 |
| 6. 叙事接口 | Fabula/Discourse、POV 渲染、停滞诊断 | 渲染纯、无未来泄漏、失败不影响世界 |
| 7. 通用模块 | 契约、污染、语义寻址、自动能力、相变模板 | 每模块声明读写集、守恒、终止、介入点和反例世界 |

第一阶段不应先追求大量具体能力，而应先把“什么规则会被拒绝”做成可执行规范。只有拒绝边界可靠，后续作品库才不会通过组合例外侵蚀核心稳定性。
