# 侦探行为规则与脑内推理

2026-09-29。现场调查给事件经过提供依据；脑内还原驱动人物选择行动的规则。**规则本身就是动机**，不添加目的标签、动机字段、问卷或新界面。沿用现有 `MindNotebook.tscn`、直接输入、词库和回放，按[初醒设计](academy_setting/first-awakening-design.md)修正规则执行。

## 自由组合与人物

人物、动词、对象和条件自由组合，不按职业限定动作，不采用“音乐家撑门”等不可拆分答案词块。纸面当前人物只是省略主语时的默认值；显式写其他人物的合法行动，也应按其主体归入规则执行。不能把编辑页当成权限。

位置、所知、工具和物态决定行动能否发生；合法但失败的行动保留为实际结果。有意义但尚未建模的组合要指出具体能力缺口，不能称为推理错误，也不能以列出缺口冒充全部完成。下方24动作能力表是既有基线，不是永久限制。人物范围目前是已建模的在场四人及门外行动主体；新增历史人物要有其初始处境，不能随便输入名字便获得凭空位置和知识。

正文直接可编辑，词库帮助插入词元、公开全部语法和别名，不预填案件解法。受限语言不冒充任意自然语言解析。新中文规则与现有多语行动句的支持范围分开记录。

## 条件规则驱动行动

普通顺序行动保留用于实际子过程；持续规则独立于任务队列，不能被排在前面的未满足条件堵住。条件只据当事人可观察的状态判断，不让远处人物从客观世界偷取知识。

现有中文条件句增加持续前缀，例如：

```text
每当厨师看见隔离门打开后，厨师关闭隔离门。
每当工程师看见热烟后，优先工程师取下木楔。
每当音乐家看见热烟后，禁止音乐家推开隔离门。
```

这里只示范语法，不是完整或必然正确的解法。动作、人物及13类观察条件仍按现有词元组合；“优先／禁止”影响实际选取，不是附加说明。相同规则可以由不同人物执行，条件和动作须属于同一个决策主体；要让另一人依据该消息行动，需要真的传递信息，不能混写主语取得全知。

持续规则在条件可见且成立时触发，条件解除后再次成立可再次触发。优先规则先于该人物普通规则与任务；禁行规则约束同一动作，不可用普通WHEN包装绕过。当前同级规则按声明顺序处理并在回放中记录规则触发；这仍是有限规则解释器，不宣称已接通Core通用规划或任意并发。

不可见是没有可用观察，不能当作条件为否的证据。规则选择之后仍走同一动作执行和Core物理结算。循环的互相触发规则必须显示未完成，不能靠达到步数上限判成功。规则的物理后果、失败与普通行动完全一致。

## 如何据此还原动机

先调查楔、门和灰迹，得到动作约束。玩家写保持观察口的行为规则，若始终不终止，回放会与合门经过冲突；补入察觉烟气后中止开放的规则，可让人物在新条件下实际改策。这组规则本身体现其对信息与风险的取舍，不再要求填写“求知”或“自保”。

同一经过可以由不同规则产生，无法区分时保留多解；同一规则可以因可用工具与占用不同而选择不同动作。通过只表示本次完整行为与当前证据相容，不证明真实内心或唯一历史。比较第二解可选，不是通关作业。外闩身份和深层动机没有依据时保留未决。

## 反馈、修改与提交

继续使用原纸面和回放反馈：表达错误、未实现能力、人物观察条件不满足、行动失败、证据冲突与尚未完成分开。不能用“动机不正确”隐藏具体因果差异。现实记录、初态假设和回放所见不混用。

改稿后旧运行立即失效，整份方案从同一历史初态重算。返回现场保留输入；提交使用当前完整结果和已调查材料，不靠模拟检查次数解锁词汇。不以动作成功、局部痕迹或已有旧检查标记代替完整解释。

## 验收与实现边界

规则运行由现有 `MindLanguage → MindPresentation → HallReplayBridge → HallCausalityRules` 链路接入；`DecisionSystem`的通用认知决策能力不能仅因Core存在就声称已接通。当前桥层仍是有限的案件动作适配，真实源码与场景README说明实际覆盖范围。

检查人物互换、跨页显式主语、规则声明顺序不堵塞行动、优先规则真实改变行为、禁行不能绕过、条件解除后再触发、远处信息不触发、互相触发循环未完成、修改旧结果失效及现场证据提交。原纸面可见控件运行要实际验证，不增加一套新界面来通过验收。

以下为已有物理动作能力基线。其中关于逐人物固定队列的旧描述应结合上述持续规则扩展阅读；未建模的取物、传话和通用条件组合依然是实际缺口。

### 主体、对象与组合原则

主体为侦探、工程师、厨师、音乐家、门外的人。职业称谓只标识人物，不能据此限制谁会移物、开门或擦地。门外的人起始位于主楼侧，其他人位于生活翼；跨门须门已开启且两道锁均未锁止。人物位置、门的侧别和物件状态才决定动作能否完成。

对象使用词汇页的场景名称与公开别名；四间宿舍必须以 R-05 至 R-08 区分同名窗与寝具。动作表中的“隔离门”“止挡座”“包纸”“传声口”均为现有可输入别名。选择人物或器物只绑定输入对象，不等于人物已经观察或理解它。

当前初醒保留五个人物的纸页组织：切换人物保留原稿；省略主语时使用当前页人物，显式主语允许写其他已建模人物，编译按实际行动者归并。句号、分号、换行和“然后”分隔该人物的局部行动；“起初／随后／接着”只帮助阅读。条件句控制本人紧接的一项行动。提交时五页从同一历史初态合并重演；执行器按固定人物次序轮询可执行的下一项，条件尚未发生的页等待其他人物改变世界状态，条件与其行动保持相邻。全部页都无法推进时，未满足的条件及后续行动显示失败。旧单一动作序列仅保留兼容入口。该调度没有模拟真实时间、持续观察和任意条件守候，也没有未公开的自然语言意图推断、职业权限或作者答案预填。

表内“自动”是当前执行器提供的细节。一般成功行动会记录主体到对象旁的抽象位置，玩家无需反复写寻路；它不证明房间内实际路径、碰撞或取物动作已完整实现。条件检查不会自动把观察者送到物件旁。失败会留下字幕和原位置，后续语句继续执行，玩家可修改草稿后从头重演。

### 13 类条件的认知语义

条件不能远程取得客观状态。当前位置看不到时，不移动、不等待、不执行紧接动作；返回“尚未在可观察的位置”反馈。在可见位置但状态不符时也略过紧接动作，后面的独立语句继续。下面是当前实际判断，不能将它描述为完整的记忆、听闻或三值信念系统。

| 条件前缀（须在前面写观察者） | 可观察位置 | 成立依据与限制 |
| --- | --- | --- |
| 看见热烟后， | 门边相关点，内外侧均可 | 若尚无热烟，推进到热烟到达事件；不会等待玩家指定的任意时间。这是唯一主动等待环境事件的条件 |
| 看见隔离门打开后， | 门边相关点，内外侧均可 | 此刻门开启 |
| 看见隔离门关闭后， | 同上 | 此刻门闭合 |
| 看见内销插入后， | 生活翼侧门边 | 此刻销已插入 |
| 看见内销拔出后， | 同上 | 此刻销不在锁止位置；初始就是拔出状态也成立，并不证明目击过拔销动作 |
| 看见外闩落下后， | 主楼侧门边，或生活翼侧检视孔旁 | 此刻闩已落座 |
| 看见外闩抬起后， | 同上 | 此刻闩未落座；不证明曾亲眼看见抬闩 |
| 看见木楔撑门后， | 生活翼侧门边 | 此刻木楔正在撑门 |
| 看见木楔撤下后， | 生活翼侧门边或包纸所在处 | 当前楔的“撤下”标记为真；重新撑门会清除此标记 |
| 看见木楔包好后， | 生活翼侧木楔／包纸所在处 | 此刻楔已包起；站在门边不能隔处知道包纸状态 |
| 看见止挡座移开后， | 生活翼侧门边 | 此刻座已移开；归位后不成立 |
| 看见地面擦拭后， | 生活翼侧门边 | 本次重演曾执行擦地；不代表痕迹与调查证据相容 |
| 看见水阀出水后， | 生活翼侧水阀、洗盆或湿布所在处 | 此刻阀打开 |

“门边”在当前桥接层是登记位点集合，不是已验收的遮挡视线或精确距离。条件观察者必须与紧接行动的主体相同，与草稿所在页面无关；执行器没有自动传讯。正式认知设计应让行动者亲见，或先通过可追溯的告知得到消息；后者仍是实现缺口。

### 可直接书写的局部组合

以下只演示表达与结果，不构成案件谜底，也不作为初次进入的预填草稿。对象须存在于当前场景词汇表。

有效、可逆的水阀组合：

```text
厨师拧开水阀。
厨师看见水阀出水后，厨师拧紧水阀。
厨师观察水阀。
```

预期依次看到出水、停水、关闭状态。这里展示“先做事、再凭当前观察决定”，不改变案件证据。

合法但方向错误的尝试：

```text
音乐家拉开隔离门。
音乐家观察隔离门。
```

音乐家初始在生活翼侧，向内拉被止口阻止；后一句仍可观察门。它属于物理失败，应在回放中呈现，不应伪装成不认识“拉开”的语法错误。

两人协作及各自观察，分别写在人物页：

```text
【工程师页】
工程师推开隔离门。
工程师看见隔离门打开后，工程师关闭隔离门。

【侦探页】
侦探走到隔离门。
侦探看见隔离门打开后，侦探观察隔离门。
```

当前历史初态两锁解除，工程师扶门期间侦探可在门边观察；工程师随后松门合拢。若改成工程师开门后马上离开，门会先合拢，侦探的开启条件不成立。这是分工和时序造成的可解释差异，不要求工程师专属开门权限。两页按固定轮询重演，不代表真实时间的并发模拟。

认知位置反例：单写“侦探看见水阀出水后，侦探拧紧水阀”时，侦探初始仍在笔记旁；即使先让厨师开阀，侦探也不能远程触发该条件。补写侦探走到水阀，才使他具备观察位置。

### 组合能力的后续设计缺口

动作表作为能力清单必须保留以下边界，不能用 Dialogue 台词假装这些规则已经运行：

| 待补能力 | 玩家要表达的判断 | 自动执行的合理范围 | 必须保留的失败与信息边界 |
| --- | --- | --- | --- |
| 通用取用／放下／递交工具 | 谁取哪件物件、交给谁、在哪使用 | 接近、伸手、携持与放置；不替玩家选择用途 | 不可凭“用湿布”生成布；被别人持有或够不到须反馈。现有24动词尚无该携持链 |
| 告知／收到具体消息 | 某人如何获知另一人看到的事 | 在可交流距离或有效回路中传递已知内容 | 受话人知识才更新；不能借观察者前缀实现全局共享 |
| 等到普通条件成立 | 因何留在某处，条件发生后做什么 | 持续观察、事件到来后继续；无须玩家写循环 | 不产生条件事件本身；当前除热烟外均为一次检查 |
| 通用双对象比对 | 拿哪些材料检查何种关系 | 已选对象的形状、痕迹等可观察项比较 | 未取得的材料不出现；当前 Compare 只是单个预建对象组记录 |
| 双人同时持续行动 | 谁扶住什么，另一个人何时腾手 | 执行持续动作并呈现占用，直至显式释放或离开 | 不是逐句瞬移；已有扶门／握柄只是局部实现，尚无通用并发任务 |
| 历史人物认知与侦探记录隔离 | 当事人依据哪次观察决定 | 记录取得来源、时刻和可见性 | 现有 observations 主要为回放文本字典，不能称已接入完整 ProjectionWorld 决策；Inspect 的现场记录不得自动成为当事人真知 |

改造优先级是先让已有动作的侧别、持续占用、观察条件与失败反馈可靠，再依据具体案件需要补能力；不为凑出更长动作表预建无场景的动词。词汇页可完整公开能力，但教学每次只介绍眼前所需的一种组合，并把操作机会交回玩家。对于“制作了相容解释”的评价，只能依据同一次完整重演及其已知证据，不能把执行成功、局部观察成立、证据相容三者合并。

在推演规则与现场辩驳中，推演引擎中的“门外的人”仅用于模拟主楼外侧施加的外闩操作；在会议研讨与终局答辩时，将室内家务生活痕迹归咎于“门外潜入的第五人”被实据判定为伪命题驳回（冷水顺拧平铺晾晒、练习纸包焦黑木楔系常住生活者的肌肉记忆，生死关头不可能由潜入者从容伪造）。
