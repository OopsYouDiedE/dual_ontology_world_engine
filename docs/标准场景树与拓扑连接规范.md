# 标准场景树与拓扑连接技术规范

## 1. 概述

在空间与世界表达体系中，场景树（Scene Tree）与连接拓扑（Connection Topology）分别承担不同的几何与空间语义职责：
* **场景树**：基于树状层次结构表达空间的实体隶属、容器包含与空间级联变换关系。
* **连接拓扑**：基于图（Graph）结构表达离散空间区域之间的邻接关系、双向或单向通路及通行代价。

两套系统保持正交与解耦，空间拓扑不挂载于场景树内部，场景树节点不直接内嵌全图遍历逻辑。

## 2. 场景树标准模型

### 2.1 树状层次定义

场景树是严格的有向无环树结构（Strict Tree），具备唯一全局根节点：
* 每一个场景树节点持有唯一的父节点引用（`Parent`）以及有序子节点集合（`Children`）。
* 节点变更父容器时执行严格的祖先环路检测，禁止将节点挂载到自身及其后代节点之下。

### 2.2 空间包含与附着语义

* **空间层级（Spatial Hierarchy）**：场景节点（Scene / Room）作为区域容器节点，内部可容纳子场景、设施、道具与角色身体实体。
* **所有权与附着（Containment & Attachment）**：道具挂载在角色实体下表达“背包携带”；装备挂载在对应槽位表达“穿戴佩戴”。
* **级联行为**：父节点的空间移动、状态激活或销毁，自动按拓扑层级深度优先级联作用于全体子节点。

## 3. 连接拓扑图模型

### 3.1 独立图数据结构

空间拓扑采用显式图模型 $G = (V, E)$ 独立存储与维护：
* **顶点集合 $V$**：顶点代表具有独立空间边界的场景实体（Scene Entity）。
* **边集合 $E$**：边代表连接两顶点的空间通路（Passage / Portal）。

### 3.2 通道（Passage）属性规范

一条标准的通道由以下独立属性构成：
* **端点引用**：有序对 $(u, v)$，表示连接的两侧场景实体。
* **单向通行代价**：$w(u, v)$ 与 $w(v, u)$，非对称通道允许两向代价不同。
* **通行守卫（Guard & Access）**：通路的通行条件谓词与当前物理阻断状态。

### 3.3 门禁与物理实体解耦

门（Door）或通行障碍物作为具体物理实体挂载在场景树中，接受物理世界的开合、锁定与破坏操作。
拓扑图中的通道边持有相关门禁实体的弱引用或监听器，在寻路与通行判定时动态查询门禁实体的通行许可状态，通道本身不作为场景树的父级或子级容器。

## 4. 跨场景迁移流程

实体执行跨场景位移的标准流程：
1. **拓扑合法性检验**：查询起点场景与目标场景在拓扑图 $G$ 中是否存在直接通路，且该通道当前处于连通状态。
2. **代价支付**：按通道设定的权重消耗移动主体的行动力或行动值。
3. **树节点重挂载**：调用 `Reparent` 将移动实体从起点场景移出，挂载至目标场景的子节点列表中。
4. **触发进出事件**：触发起点场景的离开事件与目标场景的进入事件。
