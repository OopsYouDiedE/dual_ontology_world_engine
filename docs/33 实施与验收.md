# 33 实施与验收

本文是三维换代与前两章可玩化的实施方案和验收测试。本文所列内容均为设计和验收要求，不代表已经实现。实际状态只记录在 `artifacts/acceptance-20261029/任务状态账.md`。

## 1 总目标与里程碑

总目标是从标题界面开始正式新局，在 Godot 中完成第一章并进入第二章，再完成第二章目标或明确分支。每个里程碑结束时，正式新局必须能启动并游玩到该里程碑所述范围。中途停止时，已通过的里程碑仍然构成可玩版本。

| 里程碑 | 可玩范围 | 必要任务 | 通过证据 |
|---|---|---|---|
| M0 正式开局 | 标题→新局→主角在 2F 门边醒来，可在新建筑起点区域行走，相机跟随 | 1.1～1.4、2.1～2.7、2.10、4.01、4.02、4.06、占位人物 | 正式 Godot 新局回执与画面；正式 CLI 新局同一起点 |
| M1 第一段可玩 | S01～S04：门边醒来、标准卧室、初次交谈、初次推演、开放甲区 | 2.13～2.16、第 3 组卧室物体、4.07～4.09、5 行走坐起、6 分类修复、7 交互菜单与案卷 | CLI 分段回执；Godot Agent 逐步操作回执 |
| M2 CLI 全章 | S01～S18 逐段通过，正式 CLI 新局连贯进入第二章并完成目标或明确分支 | 第 6 组全部 | CLI 分段与连贯回执 |
| M3 Godot 全路线 | 前两章空间、楼梯、走廊、公共房间全部接入；正式起点到各剧情站点实际走通 | 第 2～5 组其余任务 | Godot 路线回执与画面 |
| M4 Godot 全章 | Godot Agent 按最新观察完成 M2 的剧情范围；CLI 与 Godot 引擎自动测试报告 | 第 7、8 组 | Godot Agent 回执；两宿主自动测试报告 |
| M5 表现完善 | 曲线栏杆、KayKit 动作完善、Material 3 统一、材质和灯光统一 | 剩余视觉任务 | 同镜头前后对比的实机画面 |

M0 之前不做装饰和远期视觉。M1 之前不做曲线栏杆和书本翻页。任何里程碑都不得通过删减剧情或跳过机制提前通过。

## 2 数据来源

建筑已有尺寸沿用最终选定的布局数据。生成器只读取参数，不自行修改尺寸。出现冲突时，先查 `docs/12 房间布局.md` 与已发布 DV 空间定义，把冲突、来源和处理意见写入任务记录。无法依据文档判定的冲突上报主代理，不得猜测。

## 3 工作规则

1. 正式路径优先。研究场景、独立展示场景和单场景图片只作为调试线索，不计入验收。任务的验收只认正式新局、真实宿主与 MCP 回执。
2. 每个任务包按第 13 节格式写明。Terra 按单项任务实现。组装任务只在依赖项验收后开始。
3. 状态分为：未验收、静态检查通过、CLI 通过、Godot 通过、验收通过。验收通过要求该任务适用的全部宿主都有回执。状态账逐项记录版本、内容 hash、宿主、决策者、测试方式、前置条件、操作、结果和证据路径。
4. 每次交付后，两种宿主的构建保持成功，正式新局保持可启动。改坏正式开局的提交必须在同一任务内修复。
5. 同类物体复用组件。每个实例仍单独核对位置、朝向、站位、通路和剧情绑定。一把椅子通过只证明椅子组件可用，不替代整间讲堂的座位验收。
6. 禁止回放冒烟、快照注入、开发传送、伪造回执、一次性测试脚本、临时测试工程、合成端点和递归删除。

## 4 审核与打回

主代理审核每份汇报。汇报只包含：任务 ID、状态变化、关键回执路径、内容 hash、不超过 3 张实机图片、未覆盖范围与已知问题，正文不超过 40 行。

审核不通过时，主代理列出全部问题、修改位置和复测要求，任务退回原执行者。同一任务连续两次未通过时，主代理接管修改或重新拆分任务。

## 5 第 1 组：统一数据、组件接口与新旧方案隔离

| 任务 | 具体设计 | 验收标准 |
|---|---|---|
| 1.1 唯一建筑定义 | 每个楼层、房间、墙段、洞口、楼梯、物体具有稳定 ID。空间、初始状态、交互规则由 DV 发布。模型只引用 ID | 任一物体能追溯到唯一 DV 定义；重复 ID、缺失引用在加载前报错 |
| 1.2 坐标转换 | 设计坐标到 Godot 坐标只经过一个转换模块；统一米制、朝向、楼层标高、物体原点 | 三个不共线基准点、一个竖向高度转换正确；往返误差不超过 1 毫米 |
| 1.3 新旧内容隔离 | 新方案使用明确的内容清单。旧房间、旧铜管剧情、旧二维定位、独立展示场景不进入新方案装配 | 清单之外的资源不会被自动加载；不存在找不到新资源便退回旧实现的分支 |
| 1.4 物体接口 | 每个物体声明名称、外形包围范围、碰撞、可执行动作、站位、接触点、占用资源、状态表现 | 缺少必要字段时拒绝发布，不在运行时猜测站位 |
| 1.5 状态接口 | Core 决定锁闭、库存、人物意愿和动作结果；宿主报告移动、接触与动画完成 | 模型显示改变不直接改变世界状态；重复完成回执不重复扣物或推进剧情 |
| 1.6 验收记录 | 每项记录版本、内容 hash、宿主、测试方式、前置条件、操作、结果、证据路径 | 没有实际回执的任务保持“未验收”；静态检查、CLI、Godot 分别记录 |

统一三维物体结构：

```text
WorldObject3D                         稳定物体 ID
├─ VisualRoot                        模型或占位体
├─ CollisionRoot
│  └─ StaticBody3D / CharacterBody3D
│     └─ CollisionShape3D
├─ InteractionArea                   Area3D
│  └─ CollisionShape3D
├─ InteractionSlots
│  ├─ Approach                      接近位置
│  ├─ Stand                         最终站位
│  ├─ FaceTarget                    朝向目标
│  └─ Contact                       手、脚或工具接触点
├─ StateVisuals                     开关、库存、损坏等外观
└─ LabelAnchor                      名称显示位置
```

三维交互使用 Area3D。二维 UI 可以保留 Control。物体检测不使用 Area2D。

## 6 第 2 组：建筑基础构件生成器

生成顺序固定为：地板 → 墙体与洞口 → 天花板 → 门窗 → 楼梯 → 栏杆与扶手 → 固定设备 → 家具。每个生成器只接收参数并生成自己的构件，不负责剧情，不修改相邻构件数据。

| 任务 | 具体设计 | 可执行验收 |
|---|---|---|
| 2.1 地板面 | 根据房间多边形生成；支持凹多边形与井洞；上表面位于楼层标高 | 检查三角形朝向、退化面和越界面；沿中心、边界、洞口边缘行走，无穿落或不可见阻挡 |
| 2.2 地板厚度与侧面 | 厚度向下延伸；洞口生成内侧封边；相邻房间不叠放共面地板 | 剖面检查厚度；贴地观察无闪烁；楼下看不到错误透面 |
| 2.3 地板碰撞 | 碰撞与视觉使用同一轮廓，保留真实洞口 | 地板内采样点向下检测均命中；洞口内不命中本层地板；视觉与碰撞边界误差不超过 1 厘米 |
| 2.4 外墙 | 按墙中心线、厚度和高度生成实体；内外表面、顶部和端部完整 | 室内外检查可见面；人物不能穿墙；墙厚与定义一致 |
| 2.5 内墙与隔断 | 共享墙只有一个实体；隔断高度独立于房高；不同材质分面处理 | 相邻房间不重复生成共享墙；隔断顶部可见；两侧碰撞一致 |
| 2.6 墙角 | 直角和斜角使用明确连接规则；不依靠互相穿插掩盖接缝 | 所有转角无裂缝、重叠闪烁和凸入通道的碰撞 |
| 2.7 门洞 | 墙体直接减去门洞；尺寸包含净宽、净高与门框厚度 | 门打开后角色碰撞体能从两侧通过；墙碰撞不封住洞口 |
| 2.8 窗洞 | 独立声明窗台高度、净宽、净高、墙体进深 | 室内外观察洞口贯通；窗台、玻璃、窗框互不遮错；不可通行窗不成为寻路出口 |
| 2.9 踢脚线 | 沿墙脚生成；门洞处断开；墙角连续；简化碰撞或无碰撞 | 不横跨门口；不形成绊脚台阶；近看无接缝穿插 |
| 2.10 天花板 | 独立于楼板生成；支持楼梯井、挑空和管道洞口；可按房间隐藏 | 天花板洞口与楼板井洞一致；隐藏天花板不删除楼板或碰撞 |
| 2.11 天花板边缘 | 隐藏时处理边缘与相邻房间边界；不露出错误的墙体背面 | 相机穿过门口时没有大面积闪现；相邻房间不同时错误消失 |
| 2.12 梁与柱 | 梁柱各自声明截面、长度、位置和碰撞；低梁参与净高检查 | 必经路线满足角色净高；柱体不占据门洞、交互站位和楼梯落点 |
| 2.13 门框 | 左框、右框、上框分别生成；尺寸从门洞扣除 | 实测净宽满足通行；门扇关闭后与门框吻合 |
| 2.14 门扇 | 原点位于铰链；声明开门方向、角度、厚度和扫掠范围 | 连续开关 10 次角度无累计偏差；开门时不穿墙、不夹住角色；关闭时阻断通行 |
| 2.15 门把、锁与门闩 | 把手和门闩有独立接触点；内外操作面明确；锁状态来自 Core | 错侧不能操作内闩；缺钥匙不能开锁；动作完成后才改变门状态 |
| 2.16 门槛 | 平门槛优先；有高差必须声明并与角色跨步能力匹配 | 两侧慢走、斜走通过，不需要跳跃，不上下抖动 |
| 2.17 窗框与玻璃 | 窗框实体，玻璃单独材质；玻璃透明不代表可以通过 | 光照下能辨认窗框；人物与相机不能穿过关闭的玻璃 |
| 2.18 可开启窗 | 声明铰链、开启限位、操作位置、是否影响隔离状态 | 开关动作与 Core 状态一致；限位不被动画越过；危险环境按实际开口变化 |
| 2.19 楼梯踏步 | 根据总高、踏步数、踏面深度生成；最后一级精确接楼面 | 每级高度一致；上下楼无需跳跃；顶部和底部无悬空、卡边 |
| 2.20 楼梯运动碰撞 | 连续斜坡作为行走碰撞，真实踏步保留视觉 | 慢走、跑步、停在中段、转身均稳定；脚部不长期悬浮；斜坡不封住梯下通道 |
| 2.21 楼梯平台 | 平台与梯段、楼板共用高度；转弯平台保留通行宽度 | 两个角色能按通行规则通过；平台接缝无落差；转弯不撞扶手 |
| 2.22 楼梯净空 | 逐段计算角色头顶与楼板、梁、翼梯底的距离 | 沿完整路线采样；不用整个楼梯一个净高值代替局部检测 |
| 2.23 井洞与围护 | 楼梯井、升降井分别生成；不可通行井设置实体围护 | 正常移动路线不能跌入禁行井；可通行楼梯井不被围护封堵 |
| 2.24 屋顶与外部封闭面 | 单独管理可见性和阴影；不与室内天花板绑定 | 室内隐藏天花板时外部轮廓完整；无室外漏光缝隙 |

栏杆和扶手任务：

| 任务 | 具体设计 |
|---|---|
| 2.R1 路径定义 | 三维曲线表示栏杆基线，控制点来自平台边缘或楼梯侧边 |
| 2.R2 等弧长采样 | 按实际曲线长度分布立柱，不按曲线参数等分。最大间距 `s`，区间数为 `ceil(长度/s)`，重新平均分配 |
| 2.R3 端柱 | 起点、终点、转角、平台与斜梯交界处设置端柱；连接处不重复生成两根柱 |
| 2.R4 普通立柱 | 底部落在平台或梯侧基座，上端接到扶手；竖直立柱不随坡度倾斜 |
| 2.R5 扶手截面 | 圆形或圆角矩形截面沿曲线扫掠；截面尺寸统一 |
| 2.R6 扶手转弯 | 连续方向框架控制截面，避免扭转；急转弯采用明确弯头 |
| 2.R7 扶手端头 | 封口、回弯或接墙三选一；不留开放截面 |
| 2.R8 横杆与填充 | 沿同一路径生成，端部连接立柱；不穿过门洞和楼梯出口 |
| 2.R9 碰撞 | 连续简化围护面，不为每根细杆生成碰撞体 |
| 2.R10 验收 | 相邻立柱弧长不超过上限；扶手无断口和自交；角色沿全程贴边行走不能穿出；扶手不占据通行净宽 |

## 7 第 3 组：房间物体与交互预制件

每件物体都要有具体外形、尺寸来源、材质、摆放规则、碰撞、操作位置、动作、状态变化和失败反馈。占位体可以简化外形，但不能省略碰撞与交互结构。占位名称通过 Label3D 显示，选中时清晰显示，远处不堆满屏幕。

标准卧室物体：

| 任务 | 物体 | 设计方案 | 验收方案 |
|---|---|---|---|
| 3.01 | 单人床 | 分床架、床垫、床头；床侧设接近位、坐位、躺位和起身位；床底不作通道 | 走到床侧→坐下→躺下→起身→离开；起身位置不在墙内；取消后释放占用 |
| 3.02 | 枕头 | 独立视觉物体；头部接触点与躺姿匹配；无硬碰撞 | 躺下后头部不穿床头或悬空；不阻挡行走 |
| 3.03 | 被褥 | 初期简化网格；不用被褥掩盖身体大幅错位 | 站卧切换无明显穿插；无动作适配时保留清楚的占位表现 |
| 3.04 | 床头柜 | 柜体、台面、可选抽屉分开；操作位在柜前 | 能靠近并检视；抽屉打开不穿床；关闭后状态正确 |
| 3.05 | 书桌 | 台面、桌腿、抽屉；桌前留座椅退出距离；桌面设放置区 | 坐下后腿不穿桌；桌面物品落在支撑面；抽屉不推出墙外 |
| 3.06 | 椅子 | 座面、靠背、腿；座面高度、坐姿朝向和起身方向明确 | 骨盆接近座面；脚落地；两人不能占同一座位；起身不卡桌腿 |
| 3.07 | 衣柜 | 柜体、门扇、把手；开门扫掠区与操作区分离 | 开门不穿人物；柜内物品只在允许观察时显示；重复打开不重复产出 |
| 3.08 | 洗脸架 | 架体、水盆、壶、毛巾分别绑定；操作点在盆前 | 角色站稳操作；手部接触在盆范围内；盆不成为可站立平台 |
| 3.09 | 沙发或双人靠椅 | 每个座位独立 ID、占用状态、接近路径 | 两人可分别入座；一座被占不封锁另一座；起身路径可用 |
| 3.10 | 茶几 | 桌面、腿、放物点；不占沙发起身区 | 绕行和取物可完成；不允许隔着沙发远距离拿取 |
| 3.11 | 灯具 | 灯体、光源、开关位置分开；发光外观与真实灯光状态一致 | 开关后亮度变化；墙后无明显漏光；不改变其他房间灯光 |
| 3.12 | 书本 | 封面、书脊、书页简化；阅读内容由 DV 提供 | 阅读后产生对应观察；未阅读不自动进入案卷；合上 UI 不删除记录 |
| 3.13 | 纸张与信件 | 纸面图案仅作视觉；可读文字来自同一内容来源 | 缩放后可读；纸面与文本一致；未取得许可不能拿走 |
| 3.14 | 小型证物 | 可辨轮廓或带名称占位；独立 ID、观察点、持有状态 | 检视、拿取、放下分别记录；转入携带后不同时存在两份 |
| 3.15 | 地毯 | 薄层视觉面；无绊脚硬碰撞 | 无地面闪烁；角色高度不跳变；不覆盖必须看见的痕迹 |
| 3.16 | 窗帘 | 固定简化网格；不承担窗户密闭功能 | 不遮住交互提示；窗帘关闭不被判为窗户关闭 |
| 3.17 | 墙面画框 | 框体、画面、固定点；薄碰撞或无碰撞 | 不悬浮、不穿墙；需要检视时有独立观察点 |
| 3.18 | 门牌 | 名称来自房间数据；靠近入口且不挡门 | 从走廊能辨认房间；不泄露人物尚不知道的身份 |

公共房间与剧情物体：

| 任务 | 物体 | 必须独立设计的细节 | 验收操作 |
|---|---|---|---|
| 3.19 | 长餐桌 | 每个座位、上菜点、桌边通道、餐具区域 | 多人依次入座、取餐、离席，无重叠占座 |
| 3.20 | 餐椅与长凳 | 独立座位容量；长凳不只设一个中心坐点 | 实际坐满声明容量；每人有可用起身位置 |
| 3.21 | 餐盘、食物、送餐容器 | 份数、携带者、目的地、交接点 | 领取→携带→送达→食用全程数量守恒 |
| 3.22 | 配膳台 | 存放区、取餐区、工作人员站位 | 两侧角色不穿过台面；未完成领取不减少库存 |
| 3.23 | 炉灶与壁炉 | 炉体、火口、安全距离、操作点、热源状态 | 点火、停火、接近产生正确状态；视觉火焰不独立决定温度 |
| 3.24 | 粮柜与双闩柜 | 柜门、上下闩、倾斜状态、支撑点 | 单闩解除不能开柜；支撑成功后才允许后续操作 |
| 3.25 | 钥匙柜 | 每把钥匙独立 ID、挂点、持有人与登记 | 取出后对应挂点为空；一把钥匙不能打开所有锁 |
| 3.26 | 登记簿 | 页码、条目、记录人、修改来源 | 取物与归还记录对应实际动作；仅翻页不完成登记 |
| 3.27 | 黑板 | 原文、后加批注、擦除状态分层 | 比对时能分清来源；批注不覆盖原文事实 |
| 3.28 | 讲台 | 站位、展示位置、面向观众方向 | 展示者能到位；不要求全部听众挤到讲台前 |
| 3.29 | 讲堂桌席 | 每个座位、过道、听讲朝向 | 实际人数入座和退场可完成；不用桌席总包围盒代替椅子 |
| 3.30 | 工作台与工具 | 工具槽、加工位置、双手占用、材料输入输出 | 缺工具或材料时明确不可执行；取消不重复耗料 |
| 3.31 | 压力表与温度表 | 指针或数字、单位、观察范围、读数时间 | 近处读取产生带时间观察；旧读数不冒充实时状态 |
| 3.32 | 阀门与手轮 | 轴心、旋转范围、手部接触、操作侧 | 正确站位才能操作；动画结束后才提交阀位 |
| 3.33 | 气闸与隔离门 | 两道门分别建模；各自密闭状态、操作位 | 检查同时开启条件；错误操作不被视觉动画绕过 |
| 3.34 | 医疗床 | 病人躺位、检查侧、给药侧、转移侧 | 医者可接近；卧床者不因对话自动站起 |
| 3.35 | 药柜 | 两把锁、两名持钥者、柜内槽位 | 只开一锁时柜门仍关闭；开启不自动生成药物 |
| 3.36 | 药瓶与三剂药 | 批次、剂数、容器、携带和使用状态 | 配成量＝待转运＋柜存＋携带＋已用；重复提交不增药 |
| 3.37 | 标签与残签 | 上层标签、下层残签、胶边、批次尾码 | 检视可获取各层信息；不只显示最终结论 |
| 3.38 | 清单碎片 | 原件、缺角、拼接关系、持有人 | 未取得另一片时不显示完整文字；展示不转移所有权 |
| 3.39 | 收餐凭条 | 所在纸夹、编号、压痕、归档位置 | 寻找→取得→核对→补账分别成立；找到不等于归档 |
| 3.40 | 草图与路线图 | 完整版、裁切版、风险标注、作者说明 | 对读能发现缺失部分；图上路线不代替实际救援 |
| 3.41 | 担架或搬运用品 | 两端握点、承载位、宽度、转弯空间 | 搬运者和伤员位置一致；门口转弯不穿墙 |
| 3.42 | 警报装置 | 触发件、状态、声音范围、确认动作 | 只有实际接收警报的人更新认知；不全员瞬间知情 |
| 3.43 | 公约文本与签署工具 | 文本版本、阅读者、签署人、见证人 | 每人确认分别记录；散会不自动补签 |

标准卧室组装验收顺序：

1. 3.A1 空房：只放地板、墙、门洞、天花板。
2. 3.A2 加门窗：验收开关、进出、相机遮挡。
3. 3.A3 加床和椅子：验收站、走、坐、起、躺。
4. 3.A4 加柜和桌：验收开合、拿放、站位。
5. 3.A5 加灯和小物：验收照明、选中、阅读。
6. 3.A6 加第二个人物：验收让路、占用和交谈。
7. 3.A7 从正式开局门边进入卧室再离开，验证上述组件在正式会话内工作。

## 9 第 5 组：临时人物、动画与人物行动

临时人物采用 [KayKit Adventurers](https://kaylousberg.itch.io/kaykit-adventurers)，配合 [KayKit Character Animations](https://kaylousberg.itch.io/kaykit-character-animations)。官方页面标注 CC0，提供免费蒙皮人物、glTF 和动画。导入前核对下载包中的许可、转身与坐起片段。临时人物替换不等于用户确定的 E 方案人物换代完成。

| 任务 | 具体设计 | 验收标准 |
|---|---|---|
| 5.01 人偶导入 | 主角和 NPC 暂用同一骨架系列；以颜色、名字和少量配件区分 | 保存来源、许可、文件 hash；骨骼完整，无丢材质 |
| 5.02 身体尺度 | 统一角色高度、碰撞胶囊、脚底原点、眼睛高度 | 脚底贴地；门、床、椅与角色比例相容；不拉伸独立肢体凑比例 |
| 5.03 待机 | 自然站姿，可轻微呼吸 | 不漂移、不改变碰撞位置 |
| 5.04 行走与跑步 | 动画速度跟随真实移动速度 | 起步、减速、停止无明显滑步；动画不偷偷移动世界坐标 |
| 5.05 转身 | 小角度平滑转向；大角度用转身动作或明确占位过渡 | 不穿墙、不绕目标不断旋转 |
| 5.06 坐下与起身 | 接近椅子→对齐→坐下→坐姿→起身→离开 | 坐姿和座位接触正确；中断不永久占座 |
| 5.07 躺下与起床 | 对齐床侧和躺位；病人可保持卧姿 | 不穿床头；起床只到可通行位置 |
| 5.08 交谈 | 头部与身体适当朝向；允许坐着交谈 | 不强迫双方反复换位；目标离开时正确中断 |
| 5.09 拿放 | 区分地面、桌面、柜内高度；物体绑定到手部或容器 | 同一物体不同时在手中和桌面；取消不丢失物品 |
| 5.10 门与阀门操作 | 接触点对齐；动作缺失时用明确的短操作占位动作 | 站位和接触成立才提交完成；不能远处播放动作就开门 |
| 5.11 搬运 | 承载、双手占用、角色速度和门宽共同约束 | 搬运中不能做互斥动作；狭窄通道给出具体阻挡原因 |
| 5.12 动作队列 | 玩家指令、已承诺任务、紧急任务、个人需求分层 | 不因普通观察不断重排；取消后释放目标、座位和路径占用 |

《模拟人生4》的参考重点是交互位置约束、动作兼容和多人同步，不删除人物认知与自主意愿。参考 Maxis 的 [Concurrent Interactions](https://gdcvault.com/play/1021210/Concurrent-Interactions-in-The-Sims) 和 [Multi-Actor Behavior Sequencing](https://www.gdcvault.com/play/1020355/Multi-Actor-Behavior-Sequencing-in)。

## 10 第 6 组：CLI 调度、拒绝原因与分段剧情

已发现的问题：

- 一次 CLI 截止时间内有 156 次拒绝，其中 155 次是等待中断，1 次是沈鼎检视动作被拒绝。等待中断独立分类。
- 沈鼎检视要求双方在活动厅；回执时侦探已到门厅。补齐目标离开时的任务失效与取消反馈，不强制远程检视成功。
- 自动运行结束不等于剧情完成。报告分别记录运行结束、章节结束、关键节点完成和失败分支。

| 任务 | 具体设计 | 验收标准 |
|---|---|---|
| 6.1 动作结果分类 | 区分完成、中断、取消、条件失效、路径阻挡、人物拒绝、执行故障 | 每个未完成动作有准确类别、原因和关联目标 |
| 6.2 等待订阅 | 等待只监听相关请求、危险和目标状态 | 无关人物活动不连续打断等待；真实警报仍立即唤醒 |
| 6.3 持续任务 | 已接受任务保留进度；只在相关条件变化时重新选择 | 行走中不每步重选目标；不在两个房间间振荡 |
| 6.4 局部候选 | 按当前位置、已知目标和任务阶段筛选候选动作 | 不枚举全世界物体；不使用人物不知道的信息 |
| 6.5 离散时间推进 | CLI 推进到下一个完成、风险变化或约定事件 | 缩短计算等待，仍准确累计暴露、饥饿、治疗和截止时间 |
| 6.6 同步协作 | 多人任务分别到位、确认、占用、执行 | 缺必要参与者时不虚构完成；已到位者不反复重新赴约 |
| 6.7 性能记录 | 记录调度、候选计算、投影、分配和 GC；相同内容和情形比较 | 依据实际测量判断改善；不靠减少剧情或跳过机制提速 |

剧情按以下段落分别验收，再串接。每段情形由正式 DV 声明，走正式 CLI 入口，不临时修改运行快照。分段通过不代替新局连贯通过。

| 段落 | 物体与节点 | 正向验收 | 必测反向情况 |
|---|---|---|---|
| S01 门边醒来 | 起身点、门、门闩、鞋、灰与痕迹 | 侦探在门边醒来；观察和自我检查逐步入案卷 | 不自动获得全部证据，不从卧室旧开场启动 |
| S02 初次交谈 | 苏泠、霍铎、沈鼎、检视对象 | 分别获取个人陈述、实际检查与演示 | 陈述不变成客观事实；目标离开则取消对应检视 |
| S03 初次脑内推演 | 已取得证据、假设、比较项 | 选择假设→计算→显示相容与冲突→返回现场 | 未知事实不进入推演；推演不改真实门和人物位置 |
| S04 开放甲区 | 隔离门、门锁、已完成论证 | 满足条件后实际开门并通过 | 缺条件不放行；正确论证不等于已走到门边 |
| S05 丙区安全操作 | 压力表、隔离边界、手轮、观察窗 | 分工到位、读表、操作、复核 | 未核实安全前不能先进入再补手续 |
| S06 丁区与伤员 | 内闩、外锁、钥匙、病床、医疗记录 | 合法开启或见证救援，形成正确伤情记录 | 不能穿墙救人；不能用窗口旧路线跳过室内约束 |
| S07 认知盲区复核 | 莫兰、记录、观察对象 | 根据已知材料复核并保留主观限制 | 不把认知盲区变成全知说明 |
| S08 讲堂与诗文 | 黑板原诗、手稿、批注、展示者 | 对读来源，分别记录结论 | 批注不冒充原文；展示者必须实际在场 |
| S09 钥匙、厨房与首餐 | 登记柜、阀门、厨房、食物、餐盘 | 开放路径→取物→制作或领取→实际送餐 | 卧床人物不被默认已吃饭；不凭日期补库存 |
| S10 清单争议 | 清单、缺角、保管箱、钥匙 | 展示与对读后各人独立修正判断 | 不强制同意；没拿到缺角不显示完整内容 |
| S11 配膳差额 | 粮柜、支撑工具、餐账、床边收条 | 开柜、清点、核对去向、补账 | 找到纸条不代替实际补账 |
| S12 救援记录 | 完整草图、裁切图、伤情和转移记录 | 区分计划、隐瞒风险与实际救援 | 算式正确不等于救援已执行 |
| S13 药剂材料核验 | 旧瓶签、残签、批次簿、治疗记录 | 逐项对读，形成有限结论 | 旧疤不替代剂量记录；旧药不直接变成新药 |
| S14 配药与转运 | 材料、配制台、三剂药、双锁柜 | 实际消耗、配制、携带、入柜 | 失败重试不重复耗料或增药 |
| S15 移纸试探 | 收条、课程抄页、笔迹、餐账 | 依据稳定线索找回并归档 | 未到场无机会就不能移纸；移纸不等于偷粮 |
| S16 第四夜处置 | 警报、隔离门、泄压装置、主阀、温度表 | 接警→集合→隔离→泄压→复位→复核 | 中途撤退、误操作、缺人、药不足均真实结算 |
| S17 给药与归寝 | 药柜、携带容器、病人、寝室门窗 | 领药→送达→给药→归寝→封闭复测 | 给药不瞬移；完成一项救援不免除余夜风险 |
| S18 第五日与公约 | 测量点、文本、签名、床边见证 | 复测通路→到场或床边沟通→分别确认 | 天亮不自动安全；散会不补签；拒签有真实原因 |

每段测试正常顺序、合理换序、缺前置、重复操作、中途取消、参与者离开和资源不足。危险与时间边界测试只加入相关段落。

|---|---|---|

| 7.09 物品栏 | 名称、数量、持有人、用途、交接动作 | UI 数量与 Core 一致；不能从 UI 复制物品 |
| 7.10 地图 | 已知房间、实际走过路线、未知状态和当前目标 | 不泄露未探索布局或实时锁状态 |
| 7.11 协作安排 | 参与者、任务、地点、已接受/拒绝/未收到 | 发出邀请不等于接受；到场状态与实际位置一致 |
| 7.12 警报界面 | 危险类型、已知来源、撤退或处理入口 | 不暂停真实危险结算；弹窗不遮住逃生操作 |
| 7.13 文本对读 | 左右材料、对应编号、差异标记、来源 | 缺失材料不自动补全；颜色之外还有文字或符号 |
| 7.14 公约界面 | 当前版本、每条内容、本人意见、签署状态 | 修改文本使旧确认按规则失效；不能代签 |
| 7.15 设置 | 字号、音量、字幕、鼠标灵敏度、镜头距离、减少动态效果 | 立即生效并保存；改设置不丢失当前任务 |
| 7.16 错误与阻挡反馈 | 具体原因，例如“门锁着”“目标已离开”“缺少材料” | 不统一显示“拒绝”而无可理解原因 |
