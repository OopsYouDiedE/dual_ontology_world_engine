# 核心特性规范

## 1. 文档目的

核心引擎负责提供统一的数据接口，可以预期的世界结构，能够被多种不同机制使用的元素，以及用来构建新机制的工具。核心引擎包含实体，3D空间表示，路线规划，决策树，规则解释器，代价评估等基本表达工具，以及可以被未来所接入的模块利用的功能。

## 2. 定义
实体：指物理场景中实际存在的物体。其被一套简单的驱动规则所决定动作。这套简单驱动规则并不由实体本身维护，也不应放到实体内部处理。注意，如果实体被收纳或者是隐藏，那么实体的Parent将不是场景，而是父节点。实体包含如下参数：
- 父节点（如果不是场景，就是持有者）
- 相对3D位置
- 名称
- 特征tag

角色：角色是一个能够被灵魂驱动的特殊物理实体，可以向灵魂传递观察，也可以执行灵魂所传达的决策。

灵魂：在本项目中，灵魂才是真正代表生命和意识的个体。其包含了人的思想，认知和遵循规则。
注意，本项目中，角色和灵魂并非一一绑定关系。

规则：在本项目中，规则特指能够被编译，并具有固定路径的文本，必须严格符合本引擎要求的语言规范进行书写。一个合格的规则应该包括：
- 生效条件
- 执行动作
- 发行担保（也就是特征tag）
可选包括：
- （ 用来辅助评估后果的文本）

言灵：在本项目中，只要能够强制发生作用的文本就是言灵。言灵必须包括：
- 执行动作
- 契约代价
- 触发条件（可选）

其中契约代价立刻支付，这是签约时付出的代价。执行动作指的是该契约生效时触发的动作。触发条件可以是一个或者若干不包含发行担保的规则。
异常造成的实际规则也是言灵。

空间：在本项目中，空间由若干个互相连接或者不连接的块组成。这些块之间只相当于节点，相互连接是线。在块内部，空间中物体和该块具有相对三位空间位置。

结算回合：本项目内部具有主结算回合，按照固定顺序对效果，角色和动作进行结算。允许在一个回合内嵌套若干子回合，这个特殊规则是为规则怪谈等需要快速反应的机制设计的。注意，单回合内发生事件不得分离结算。

决策树：本项目中，角色选择决策高度依赖于决策树。互相矛盾的规则也会通过决策树作用在角色选择上。决策树内包含了通过排列组合计算出的常见动作组合（必须是有效动作）

代价估算：本项目中，为防止玩家可以轻易套利，必须建立一套代价估算体系，该体系要求任何实体不能通过循环使用代价套利。
## 3.推进方式
本核心采用循环行动值进行推进。方法为，当本回合行动结算完成后，添加下一次行动的行动值。
行动值越小，下回合行动就越接近。相同行动值的行动，按照加入该行动值槽位的先后顺序排序。引擎会在没有行动值为零的行动时，对所有行动同时扣减一次最小的行动值并进行下一次行动。对于同时为零的行动，按照次槽位，从槽位值最小者开始执行。

## 4.玩家体验
玩家体验应该更类似于回合制游戏。也就是说玩家的任何行动都会等到回合结束一起结算。然后接下来，首先需要开始立刻设计我们自己的游戏了。
