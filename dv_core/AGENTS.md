# DV 模块维护

本目录继承仓库根 [AGENTS.md](../AGENTS.md)，用户当前指令优先。这里只维护工程流程、现行接口与验证边界；人物、剧情、世界设定和玩法只依据 [设计规范](../docs/design-standard.md)。历史任务的次数、时限、机器环境、候选实验和失效路径从 Git 历史追溯，不作为新任务的自动执行授权。

CLI 的 status/options 不推进会话；next 单步推进 Prepare 或 formal-model Complete，act 只消费当前人工候选并推进到下一人工边界。自主控制使用显式 `--controller ai`，不由启动自动循环。CLI 与游戏共享 SmartReplay；记录回放不创建正式会话。入口及封存规则见 [cli/README.md](cli/README.md)。Core AI 测试按用户批准的要求和指标执行，工程构建不替代该批准。

CLI的TerminalModel仅为观察者投影和只读回放的显示模型；房间/连接来自本人map_knowledge，不从执行者或开发Inspect补真值。ANSI与SVG由同一单元画布生成；--preview必须在创建会话前返回，明确标注UI示例，不能触发自主调度。回放重启清空显示缓存，不用历史帧恢复或分叉会话。截图导出工具归mcp/verification，并在tools.json登记；预览、必要构建和Core AI验收分别报告。

CLI空间视图上方为房间分组列表，下方为通道逐条端点列表。不能从列表相邻推导连接；本人只归入实际所属房间。缩放命令仅调整显示密度，不推进会话或改变终端字号，所有内容仍完整换行保留。界面不添加说明段落或教程；预览保持短状态标识，完整来源留在证据元数据。预览房间数/位置参数不能注入正式状态。

[README.md](README.md) 维护实际目录、入口和状态；[DESIGN.md](DESIGN.md) 维护当前架构与语义合同；[compiler/README.md](compiler/README.md) 维护编译器及平台 ABI；[host_bridge/README.md](host_bridge/README.md) 维护宿主边界；[SYNTAX.md](SYNTAX.md) 区分执行子集与完整语法方案，现行语法入口为 [docs/syntax.md](../docs/syntax.md)。修改语法、内置操作、声明字段、接口、目录或构建命令时，同轮修正对应文档与本文件，不把未接线提案写成已实现能力。

各 DV 模块是现役源码，不是导出副本。20–60 使用表层语法，40/50 可混用自然段落、法则/行动句式与算法函数，10 保留 S 表达式启动源，70 混合表层与旧报告函数。旧源码字符串中的路径可能是历史来源标识，清理导航不改写旧事件或来源字符串。只读检查和 oracle 保持与生产入口隔离；源码清理按实际构建、编辑器、资源生成和诊断消费者判断，不能仅凭未进入普通游戏判为废件。

新增剧情正文优先使用叙述/台词原文块，纯法则和适用的行动使用领域句式，具体合同以 SYNTAX 为准。保留原文、列表条目顺序、条件/效果结构、稳定标识和既有来源；不为自然外观补设故事或把作者事实当作人物所知。复杂算法继续使用函数，不借自然段落恢复旧 .story 解析器。迁移后按实际构造值和源位置核对，代码生成成功不代替行为验收。

## 工作顺序与验证

1. 开始前检查分支、工作区和用户当前授权，保留已有改动。并行工作使用明确文件范围或独立检出，不互相覆盖；主代理整合公共接口与设计规范。
2. 先集中完成本批源码、声明、公共接线及文档，再静态审读。原任务要求暂停构建、探针或会话时继续遵守，不从历史任务命令推定新授权。
3. 生成物只能从源通过工具重建，不手改。路径变更同时核对相对 include、编辑器组、MSBuild、宿主配置及生成器；不另开旧 Core、解释器或第二条会话执行路径。
4. 必要工程排错与当前明确要求的实际会话分别执行。构建、语法、配置闭包、固定点与中性容器检查只证明对应工程事实，不能宣称人物行为、剧情、画面或性能完成验收。
5. 禁止流程回归及从其他入口间接调用已退役流程；不以断言数量、通过率或“全绿”评价项目。依据实际行为、玩家可见结果、来源和具体问题报告，未执行或未覆盖保持未知。
6. 正式会话前冻结全部实际源码与配置；运行期间也不修改本目录文档或插件。不同源码、审计策略、运行时配置、控制方式及插桩窗口分列，不把来源不同的记录拼成同条件比较。正式实机/逻辑性能测量串行，避免资源争抢。
7. 新证据独占创建，保留失败、超时、未刷新尾部与 `.partial`；不补造时刻、输入、来源或成功回执。恢复诊断和全新开局分别报告。阶段成果继续使用该任务的 `artifacts/<task-name>/` 目录，历史基线与原始证据只按用户明确范围处理。

一级只运行无窗口正式 DV 逻辑会话，不启动 Godot，不要求 UI 回放或三级几何检查。三级仅在用户明确要求最终效果时按根文件规则执行；默认引擎侦探，独立盲玩需要明确要求。独立证据审查不读取项目设计内容；主代理负责设计判断。工具默认超时不替代当前任务授权，不能自动运行历史多配置矩阵或延长窗口。

实际推进、有效关键检视、正确作答被接受、实际章节交接与完整封存分别记录。到达时域、位置改变、候选出现、计算完成或正常退出不能替代剧情达成。禁止预置答案、注入状态、扩大预算、跳过实际执行或改计时口径制造提速；确需机制或条件变更时单独记录原因、差异与独立审查，并区分新基线。逻辑运行器标明 `formal-model`，不能作为 Godot 现场证据。

## 构建与编辑器合同

```powershell
dotnet build dv_core/LanguageCore.sln -c Release --disable-build-servers -p:NuGetAudit=false
python mcp/build/build_session.py --partition --out dv_core/host_bridge/obj/dv
python mcp/editor_lsp/check_dv.py --format json dv_core/modules/30-session.dv
python mcp/editor_lsp/dv_lsp.py
```

实际逻辑会话入口为 `python mcp/verification/run_debug.py --out artifacts/partial-bootstrap-core/<新目录> --timeout <本轮授权秒数>`，默认源码为 `dv_core/checks/65-debug-runner.dv`。需要阶段恢复或插桩时按该任务范围显式选择，不能由普通清理自行追加。

`mcp/build/dv_toolchain.py` 统一解析从行首开始的相对 `#include`：依赖先于引用者，同一路径只加载一次，循环与缺失文件报告位置，引用行保留空行。缩进正文中的 `#include` 必须原样保留；只规范 CRLF/CR，不拆分 U+2028 等文字字符。各模块的 define/称谓和源位置边界独立。裸编译器 `--module` 接收单模块源及导入接口；`--check/--emit` 保留组合源与范围接口。C0→C1→C2→C3 使用 `10-compiler.dv`、seed 与 Runtime，自举缓存按来源指纹区分，并核对 C2/C3 生成源固定点。

`dv-check.json` 将编译器、生产和只读检查分组。生产组必须先于 include 生产的检查组，编辑 20–60 不带入 oracle；70 单独选择检查闭包。`check_dv.py` 只调用真实 C3 的 `--check`，不执行内容。`dv_lsp.py` 处理未保存缓冲区与过期诊断；VS Code、VS2022 和 Godot 客户端不各自实现语义分析。生成程序集、复制的服务端与安装包分别放在 obj/bin、客户端生成目录和 artifacts/releases，不把这些输出当作第二份源码。

## 权威、认知与内容边界

叙述/台词、法则/行动、公式、fn/axiom 与具名输出 function 必须共用同一函数检查与后端；输出变量不可用默认值绕过明确赋值检查。自然句式仍构造三值命题和有序效果，本人前提、权威前提、grants、source_refs 分列；声明和表述不产生事实或执行。主客观一键绑定只创建身份对应和未知 perceived 对象，事实与采纳继续经正式来源取得。`dv_evaluate` 的 verify/run 共用同一前提、效果和后置条件求值，verify 不追加历史或支付；候选只能在当前版本重新求值后执行，不作为免核验提交票据。

有限域 enumerate/branch_bound 必须共用模型、候选前缀、预算与独立证书核验。区间剪枝可以减少实际逐项求值，不扩大原预算可覆盖范围；covered_candidates、charged_work 与诊断计算次数分别报告。新证书版本须从原模型重建覆盖界，旧证书兼容须显式保留。时间分析 complete 只证明声明受支持，不替代非时钟依赖稳定性和增量/级联检查；unknown、近似值和未完整搜索不能冒充已证明结算。

原生 DV 声明是内容与法则的权威源；不能将旧段落、world 巨树或 JSON 字符串改后缀冒充语言迁移。20/30 与平台 ABI 保持通用，专案内容位于40/50/60，检查中的专案 oracle 独立于主体。

本人认识、他人模型、预测与权威物理世界分开；理解、采纳、论证、行动及其来源分别保留。`infer`、`predict`、`enforce` 采用范围不能混用。实际观察与听闻才更新认识，预测不能预写观察、他人同意、规范表态、答案或实际行动结果。收到信息与采信信息分别处理；姓名、问题、规章和其他正文按本人真实收据显示。

所有主体及人工玩家共用正式资格、费用与判答。`completed_actions` 仅由成功 Complete 追加，与包含失败尝试的 `used` 分开。本人接受回执与公共最高结论独立，规划不能用他人的作答代替本人交接。内容定时开放机会，交谈、协作、取用与签署仍由正式行动产生；章节扩展保留原世界、主体、配额余额、账本、队列与事件，不重新初始化会话。

现场失败与成功限制：一次性及默认不重复行动按 `completed_actions` 限制成功次数，`used` 继续保存全部尝试并照常结算费用与行动配额。人工控制的真实 Godot 拒绝回执，仅在明确失去热点接触或具有完整运动 job 证明的现场受阻时，向 `actor.manual_contact_retries` 写入按行动标识保存的 `{failure_class, action_event}`；同一行动后续 Complete 覆盖该项，成功清除。该字段随主体保存、恢复与扩章，不进入本人认识或公共观察；仅临时 `manual_input` 视图允许显式人工重试绕过相同拒绝签名，所有其他准入与正式执行照常重核。自主主体保留相同本人输入下的拒绝签名保护；缺资源、缺绑定、身份或站点证明错误、formal-model 回执及 DV 权威前提拒绝不生成此重试凭据。

规划声明：Prepare 保留内容声明的 `plan_depth`、`lookahead_limit`、`fast_approximation` 与 `positive_move_root_stop`，每轮工作预算仍来自原 `planning_limit`，不因自主控制而统一改为一层近似或另设配额。独立的 idle 固定点证明不因此移除；展开不足如实报告预算停止。恢复内容声明的认知差异属于控制与规划条件修正，须与此前强制近似条件分列，不作同条件速度结论，也不自动提高既有预算。

行动树中的非 transit 任务沿用 `node.tasks` 的路径内去重合同：已出现的任务标识必须在准入和评分前排除，不能先把同一未知观察机会再次计分、写入候选或更新 best 后才阻止后继入队。同一路径中的候选在入队时继续保持任务唯一性，真实会话中的可重复行动资格不因此删除；移动边的合法重访、个人选择价值与未知观察保持原合同。该修正不提高预算/深度、不重排行动、不改费用，也不指定内容路线；与此前含重复计分的窗口分列验证。

重演准入：具有假设目录的 replay 必须至少有一个候选满足本人的 topic、basis 与 available_when；准入、人工候选和正式 Complete 复用同一条件，人工仍另核对 manual_available_when。是否存在候选只按完整 mind 及外部目录、问题引用、话题绑定与真实收闻输入做纯值复用，不执行模型、不计作付费推演；Complete 仍按当前本人状态重新核对每个候选。没有假设目录而声明 factor_constraints 的因子专用重演保留原付费检查路径。费用、预算、证书、问题开放和观察条件保持，personal_choice 的价值不能让空候选模型重演绕过准入。

连续过门的人工取消重试仅接受 `source-cancel-v1` 源侧证明：WorldView 采真实安全停止回执，Main 独立匹配该次 Prepared 的请求、主体、行动、序号、源/目标房与地图后规范化，DV 再匹配原始回执、外层行动事件及证明。当前只支持 `released`、非站点跨房移动、无跨图 transitions、两个有限数构成且精确相同的执行开始/实际停止坐标；源几何仅 `interior` 或 `source-side-doorway`。请求时坐标另存，不能冒充执行开始点；中途移动后返回不在本子集内。此分类只写绑定本次拒绝签名的 `manual_contact_retries`，供新人工输入重试；保留失败、费用、used、原逻辑地点与自主拒绝签名，不添加完成或目标观察，不自动重派。旧记录缺少完整证明时不追认取消重试资格。

## 正式动作与空间接口

生活翼合图后，60 的宿主绑定统一投影到 `living_floor`，仍保留 `zone_*:*` 与 `living_hall:*` 执行房间、原逻辑地点及站点 ID。各区隔离门开闭独立投影为同图屏障资格，不以观察者已在同一张地图为由开放其他寝区；世界与人物认识不随合图改写。

唯一动作链为 `60-game.dv` → `30-session.dv` Prepare → 宿主实际执行/世界法则回执 → Complete。DV 负责选择、报价、权威效果、观察、传播与结算；Godot Main → WorldView 执行空间与碰撞。界面呈现结束本身不另起 Prepare，等待回执时不重复分派意图。

同房间 WASD/鼠标接近由宿主真实寻路与碰撞执行，不提交 DV、不扣 DV 时间或行动步数；热点交互与跨房间仍走共同链。`dvs_player_options` 只返回本人准入候选，60 附加 kind/interaction 与逻辑站点、人物身份，不返回隐藏值。`dvs_select_player` 再核对资格；人工 `manual_only` 只在临时只读 `manual_input` 视图开放，不写回自主人物。

Session 以不可变 DV 值与版本号维护状态。HostSnapshot/HostIntent 直接返回 .NET 只读值图，Godot 主线程物化 Variant；StateDelta 按观察者和版本发布变化的顶层字段与新增事件。静态目录只发送一次，执行者投影仅包含执行所需字段。JSON 接口保留给文本客户端，不进入正式 Godot 热路径。Trace 只读；Close 幂等；Save 取最近已完成的提交点，在途意图留在轨迹中。接口细节见 host_bridge README。

Core 发布中立 actor/map/room/site/station 身份、位置标题和逻辑时刻。Godot 场景路径、sprite、动画帧、站点视觉映射和 HUD 布局只由宿主的呈现契约绑定。逻辑地图、房间与行动站点继续属于正式执行合同；移动视觉资源不改写其标识或领域规则。

逻辑地点、当前地图执行房间和 `travel.station` 分别声明。回执核对主体、动作事件、站点、地图/房间、实际终点与到达误差；缺资源或绑定返回真实失败。现场接触成功后才发布相关观察，初次锚点与移动目的地分开。源侧门道可以支持出发房间核对，不能冒充目标房间到达；物理开启与授权放行独立。场景、坐标、资源和 `execution_snapshot` 不写入人物认识。

配置只能在会话打开前设置，控制模式不在在途行动中切换。人工等待状态保存在同一会话，等待选择后恢复不重复认知；空候选沿原 idle/轮转，不制造空菜单。人工轻量认知与阅读时提前处理 NPC 属于控制/调度机制差异，AI 与 NPC 继续共同认知，不能作为同条件纯计算提速。

## 调度、预算与依赖复用

`scheduled_action` 保存动作、start、due、成本模型和必要来源；排队等待者不重复认知或选择，到期后按当前权威世界报价并由同一 Complete 结算。`scheduled_start` 避免重复扣费，回执时间须与排队声明一致；不静默重排、倒拨时钟或重复加世界已等待时间。同一时刻按循环主体次序处理，队列与 `pending_heard` 随保存、扩章和恢复保留。

`pending_heard` 只保存真实听到的话语与当时声道证据，到期才理解；不重判已结束声道或让等待者偷偷运行理解模型。真实 Complete 以 execution.time 推进本人时钟，仅对已声明 clock_ref/bindings 生成执行回执观察；未知或未绑定时钟保持未知，不全员同步认识。

同一时刻空闲主体仅在本人修订或待理解收闻真实变化时再次决策；选择后的 `decision_revision` 防止自唤醒。跨时刻休眠或认知缓存须以完整依赖及真实固定点为依据，无法证明稳定时回原求值；不能把一次无候选、收闻长度或单个时钟当作全脑稳定证据。复用记录指向真实来源，不冒充本轮重新认知。

环境等待分析已采纳前提的时钟边界，保留一分钟采样格、实际 due 与一次成功后的 once 挂起；未知条件、增量或级联仍逐分钟结算，不按规则名称猜测一次性身份。`plan_budget/planning_limit` 限本次行动树，dependency_budget 与付费重演余额单独计工作；等待者不重置或运行搜索。改变层数、配额、费用、内容、审计策略或控制方式须作为条件变化单列。

规划与来源的完整合同见 [DESIGN.md](DESIGN.md)。新缓存必须列清输入、失效、返回值所有权和正式消费者；不能对有执行、采信、事件或资源副作用的过程使用纯值备忘。索引命中仍核对完整资格、claim、after、basis 与来源顺序。未知反事实保持未知，切片吻合不自动建立完整解释。

## 复制、审计与落盘

`dvs_owned_state_update` 仅在线性会话外壳转交中新建顶层记录与字段对，调用者放弃前态；保留未知字段、pending、initial 与输入控制，不修改既有字段对象。world/mind、预测分支与事件快照维持独立复制合同。`dvs_speech_owned` 仅用于正式 Complete 的线性替换；通用调用仍独立复制。私有法则/观察/采用表构建器先复制输入、依原序验证，失败丢弃暂存，成功后发布，不接受既有共享状态为独占输入。

平台冻结/复制、重复键、首错、数值相等与缓存失效合同见 [compiler/README.md](compiler/README.md)。公开事件经不可变快照边界，不能借独占构建器恢复可变历史。C# 不绕过 ABI 修改 `Items` 返回值；CLR 数组只在宿主证据编码边界支持，不加入 DV 值域。

新原始事件、快照、存档、实际输入、正文投影与计时使用校验二进制 `.dvdag/.dvsave/.dvlog`。JSON/JSONL/gzip 不用于新运行轨迹落盘；JSON 仅用于进程内接口、编译配置和小型工程汇总，旧记录只读兼容。保留全部原字段、顺序、来源、精确 Rational 与同文字符串区别；DAG 节点定义先于引用，事件、checkpoint、final、seal 与 `.partial` 边界完整。

SmartReplay 共用 `dv-replay-v2` 帧合同，保留 snapshot、原始 input、presentation、身体/UI 上下文及语义事件。回放时钟按内容节拍压缩现实静默，原始输入时间与 seq/state_version/action_event 关联仍留在帧数据中。实际坐标只来自已记录身体或实际回执，旧日志按逻辑位置重建并明确来源；只读投影不创建会话、执行动作或授予观察。Godot 回放使用独立场景，正式会话不接收回放输入。

检查报告的 `domain_evaluation_complete` 以真实完成领域分析为准。未进入时记录明确 reason，负面领域结论仍报告分析已完成；`main_causal_supported` 保持独立。原始证据完整和检查进程正常退出本身不填写领域完成标志。

`rt_json_write` 拒绝新文件记录；`rt_json_print` 在记录器开启后写二进制投影，解析/字符串交换仍为平台功能。`WriteTrace/WriteSave` 独占写 partial 并在完整封存后发布，恢复文件必须验证 seal；失败保留原字节，不自动重试或覆盖。阶段存档只能来自正式实际执行，恢复核对完整源码、配置及提交身份，不改历史来源。

完整审计与普通游玩分开。`R.AuditMode` 按 AsyncLocal 作用域隔离，Session 打开时确定策略并随存档保留。精简模式仅裁剪已明确允许的事件大字段，正式推理需要的 inference、observation/listener_parse、factor_prune 历史仍保留；不能关闭消费者或把缺失伪装为完整证据。读取器、关闭与恢复合同见 [host_bridge/README.md](host_bridge/README.md)。

run_debug 在构建前封存实际依赖、编译器、Runtime 与工具指纹，运行前复核；构建期间修改来源必须停止，不运行混合版本。原始 DAG 持续保存，批量投影未刷新尾部与完整封存分别记录。`rt_phase` / `phase_progress` 只读报告阶段，不能充当 DV 时间、事件或行动完成。

可选 `--profile` 只对诊断生成物插桩，保留已完成调用的采样和采样覆盖范围；插桩与原生运行分列。GC、Tiered 等运行时配置记录实际环境，不据微负载、分配下降或逻辑吞吐外推 Godot 帧率和整局收益。保存、恢复、固定点、别名与工程诊断事实均不能代替本轮实际游戏结论。


## 人工假设与可读重演

人工重演通过原动作 ID 与 hypothesis_id 的纯数据封装进入同一 Prepare/Complete；DV 重核本人候选来源、问题和可用条件，单次只执行本人选定假设的模型；有来源约束剪枝及竞争候选覆盖证明沿用原计费，不扩大预算。自主批量重演与人工单选分列。内容层提供公开变量、取值标签与开放条件；未选值不得自动填为正确答案，V6 未开放时仅以明确标注的陌生关系初始假设重演。

可读比较只投影内容白名单中本人实际取得且仍有效的感知，对比相容、矛盾与未知分别表述。保留 model_event、source_refs 与 observation_action_ids，不把 actionN 冒充观察审计事件。不得输出原始内部谓词、权威值或未观察结果；既有无标签记录保守省略。地点 HUD 只命名当前观察者自身所在地点。

## 分区编译与开发接口

20/30 分模块编译到 `base/obj/dv/modules/*.g.cs`，构成 DVKernel；35–60 分模块编译到 `host_bridge/obj/dv/modules/*.g.cs`，构成 DVProgram。单模块 `--module` 只导入依赖的函数与名义类型接口，源码偏移从零开始；正文、导出接口和编译器版本各自参与对应缓存失效。小型 DVKernel.cs / DVProgram.cs 只承载 partial 类声明。MSBuild 在生成步骤后纳入模块文件，输入不变时保留时间戳。MCP/LSP 后台预热复用同一自举锁；调试65与检查70独立生成，均不编入正式宿主。

`--dv-dev` 明确开启开发会话。Inspector 可以并排查看权威世界与指定心智；tp/time 记录开发事件。时间推进沿实际队列和世界时间边界结算，保留 Prepare/Complete 的正式结果。开发记录单独标识，人物认知仍来自既有观察。Godot 在开发变更后重建保留实体。
