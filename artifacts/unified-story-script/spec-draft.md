# 统一剧本语言（草案 v0）

两章共用同一种作者源格式，扩展名 `.story`。设计目标只有一个：策划与作者不读代码也能读懂、修改全部剧情、人物、动作、倾向与物件规则。

草案状态：未实现，未改任何运行代码。样例内容取自现有第一章 `ch1_awakening.py` 与第二章 `chapter_02.world`，文字尽量原样保留。

## 1. 原则

1. **一章一个文件，一种语法。** 取代第一章的 Python 元组表和第二章的装饰器加字典。
2. **像剧本和设定集，不像代码。** 中文关键字，缩进表示层级，没有括号、引号包装、逗号续行。
3. **四类内容各有固定位置**：剧情（场面）、人物可用动作与决策倾向（人物）、物件行为（物件）、地点（地点）。同一事实只写一次。
4. **只声明，不求值。** 条件和效果只能用本文列出的短语，编译器遇到未知短语直接报错，并指出行号。
5. **编译到现有 IR。** 新前端把 `.story` 译成 `world_script.py` 已产出的 JSON IR，再由现有 C# 运行时消费，运行时不改。
6. **机制仍归 Core。** 脚本只能请求 Core 已有的类型化行动和检查，不能新增机制，也不能直接改 Essence 或物证。

## 2. 文件结构

```
章节：<章名>
前置章节：<章 id，没有则写“无”>

地点……
人物……
物件……
场面……
文案……（界面提示文字）
```

块以关键字顶格开头，块内缩进 4 格。`#` 开头为注释。`〔……〕` 为旁白或动作说明，不是人物发言。

## 3. 各块的写法

### 3.1 地点

```
地点 备餐间
    编号：pantry
    说明：水槽、碗柜、灶台。
    相邻：活动厅
```

### 3.2 人物：身份、可用动作、决策倾向

```
人物 沈鼎
    编号：shen
    别名：厨师、主厨
    所在：活动厅
    欲望：安稳，护住身边的人
    体质：魁梧，速度 0.9
    本事：做饭 3，力气 1
    看重：中央做饭 3，病人优先 1，按人头 1，封存名录库 1
    偏见：卢西安 -1
    日常：
        早晨 取水          重要 4
        中午、傍晚 做饭    重要 4  合欲望
        中午、傍晚 领口粮  重要 3
    可做：夹滤布，确认夹牢，检查捕集灰，盆侧观察出水
    倾向：
        被侦探询问时：
            若 侦探 信任 ≥ 0：愿意作证
            否则：拒绝
        被请求时：
            若 请求「持柄」且 尚未读过特例：拒绝，理由「特例没读，不能动手」
```

要点：

- **可做** 是该人物能执行的动作清单，动作的具体定义在 3.4 的“动作”块，不在人物里重复。
- **倾向** 只描述决策分支：什么情境、什么条件、选什么、给什么理由。台词写在“回应”里（见 3.5）。
- **日常** 即习惯表，列：时段、行动、重要度，可选“合欲望”。

### 3.3 物件：用途、前置条件、效果

```
物件 酵种罐
    编号：E10
    位置：备餐间 碗柜上
    外观：罐里的酵种还活着，冒着细泡。罐壁上一层摞一层干结的旧面痕，数不清。
    属于：沈鼎
    可以：
        查看
            谁：任何人
            结果：记下「酵种罐」
        触物回忆
            谁：沈鼎
            前提：已查看
            说：沈鼎：这罐子，不是昨天才养的。
            结果：沈鼎 想起「酵种罐」
        协助辨认
            谁：沈鼎
            说：沈鼎：是我喂的。……这罐子，不是昨天才养的。
```

- **谁** 限定可用者：`任何人`、人物名、`侦探以外`。不写则任何人。
- **前提** 用 3.6 的短语。前提不满足时，写 `否则说：……`，给玩家看的拒绝反馈也在脚本里。
- **结果** 用 3.7 的短语，只能调用 Core 已有的类型化行动。

### 3.4 动作（可复用）

多个人物或物件共用的动作单独定义一次：

```
动作 夹滤布
    岗位：C
    谁：沈鼎
    前提：特例已读
    结果：滤布 被夹住
    失败说：先把滤布夹牢，再谈确认。
```

### 3.5 场面：剧情、触发、对白、选项

```
场面 初遇
    触发：阶段 漫游，侦探 进入 活动厅，仅一次

    沈鼎：又醒一个。过来站，别在门口杵着。
    沈鼎：我姓沈，沈鼎。做菜的。上一份工在远洋货轮上掌勺，再上一份在岭南行会。
    霍铎：……霍铎。钳工。萨克森，船厂。
    〔沈鼎去了备餐间。水声，壶声。过了一会儿，他端着托盘回来。〕
    苏泠：……你怎么知道我不加糖？
    沈鼎：顺手。

    选择：
        - 我也是。
            沈鼎：那就是一样的毛病。
        - 先说我的名字。
            侦探：{侦探名}。……做侦探的。
    若 已核验报偿：
        沈鼎：钱我验过了，成色足。
    否则：
        沈鼎：先把话说清。

    之后：进入阶段 调查
```

- 对白行：`人物：台词`。多人物的立场、表情以 `沈鼎（暖）：……` 标注。
- `{侦探名}` 为变量插值，来源为玩家输入或世界状态。
- 走位与演出：`〔沈鼎 走到 备餐间，朝向 北〕`，沿用现有 `story_beat` 轨道语义。
- `之后：` 只能进入阶段、触发另一场面或提交 Core 行动。阶段是脚本声明的名称，不是 C# 字符串字面量。

### 3.6 条件短语（白名单）

| 写法 | 含义 |
| --- | --- |
| `已查看 <物件>`、`已核验报偿` | 会话内玩家行为记录 |
| `<人物> 知道 <事实>` | 该人物的认知，不等于世界事实 |
| `<人物> 信任 <人物> ≥ n` | 关系数值 |
| `<物件> 被夹住`、`在 <地点>` | 世界状态 |
| `阶段 <名>`、`第 n 天 <时段>` | 进度与时间 |
| `并且`、`或者`、`并非` | 组合 |

### 3.7 结果短语（白名单）

`记下 <物件>`、`<人物> 想起 <物件>`、`<人物> 前往 <地点>`、`取得 <物件>`、`提交 <Core 行动>`、`解锁 <物件>`、`进入阶段 <名>`。需要新短语时先在本草案增补，再改编译器。

### 3.8 文案

界面提示、结局卡片等玩家可见文字放“文案”块，GDScript 只按键名读取：

```
文案
    结局卡·标题：门的这一侧 · 完
    结局卡·正文：门开了。门外是起居厅。
    饿了：你饿得发虚。这个下午做不了要紧的事。
```

### 3.9 初始世界：属性、切面、认知（人物与物件通用）

人物和物件都是 Core 的 Essence，所以同一套“初始”写法对两者都适用。一个实体最多有四组初始声明，全部可省略：

| 关键字 | 对应 Core | 含义 |
| --- | --- | --- |
| `属性` | `StateProperty` | 数值状态，及哪些别人看得见 |
| `切面` | `Spatial`、`Lock`、`Passage`、`Surface`、`Procedure`、`Rule`、`Corruption`、`TemporaryState` 等 Property | 这个实体具备的功能面，每种切面一个子块 |
| `认知` | 该人物 `SoulEssence` 的 `ProjectionWorld` | 开场时他脑子里已经有什么、凭什么来源、信到什么程度 |
| `倾向` | 决策与回应规则 | 见 3.2，条件里可以引用上面的属性和认知 |

```
人物 沈鼎
    编号：shen
    身体：魁梧，速度 0.9
    属性：
        信任·侦探 0          # 数值状态，名称即 Tag
        饥饿 0               可见
        配合 1
    切面：
        所在：活动厅
        持有：（空）
        物证外观：             # Surface，同一人在不同场合的外在表现
            穿围裙时 → 手上有面粉
    认知：
        知道 酵种罐   是 自己的   来源 亲历
        知道 活动厅   存在         来源 亲见
        不知道 侦探 是谁
        误信 铜口 是「东家的人」   来源 听说   # 可错的认知也能写，与真相分开
        关系：认识 霍铎、苏泠；不认识 侦探
    倾向：……
```

```
物件 隔离门
    编号：iso_door
    位置：门厅
    属性：
        开度 0
    切面：
        锁：
            状态：上锁
            钥匙：无              # 无钥匙，只能从外侧开
        通路：
            连通：门厅 ⇄ 活动厅
            条件：外闩已升起
        过程：                    # Procedure，对应一个 Core 效果
            拔内闩：内闩 → 拔出
        规则：                    # Rule，可被认知和阅读
            「夜间不得开门」  限 侦探以外
        表面：
            内侧：插闩落在闩槽里
            外侧：另有一道横闩，从这一侧拉不动
    认知：                         # 物件没有心灵，没有此块
```

写法约定：

- `属性` 的每行是 `名称 初值`，行尾写 `可见` 表示该数值能被他人观察到（对应 `Observable`），不写则只有本人和世界知道。
- `切面` 下每个子块名就是 Core 的一种 Property。编译器只接受已存在的种类，未知种类报错。要新增切面种类，先在 Core 里加，再增补本草案。
- `认知` 每条是一个投影：`知道／不知道／误信 <对象> <判断>  来源 <亲历|亲见|听说|推断|回忆|被篡改>`。来源对应 `ObservationSource`。`误信` 写入的是错误内容，真相仍在对象本身，二者不混。
- `认知` 里的 `关系` 对应 `RelationTag`，如认识、合作、拥有钥匙。
- 引用对象一律用声明过的名称或编号，引用不存在的对象编译失败。
- 初始值会进入开场的 `WorldRuntime`。运行中的变化仍由 Core 和章节会话负责，脚本不能写“运行中途直接改属性”，只能通过 3.7 的结果短语请求 Core 行动。

**倾向如何引用这些初始声明。** 条件短语可以读 `属性`、`切面` 状态和 `认知`：

```
    倾向：
        被侦探请求「开门」时：
            若 沈鼎 知道 铜口 是「东家的人」 且 信任·侦探 < 1：拒绝，理由「东家没发话」
            若 隔离门 锁 上锁 ：拒绝，理由「门打不开」
            否则：答应
```

编译期检查：条件里引用的属性、切面、认知必须在某处声明过，否则报错，避免拼写错误悄悄变成“永远不成立”。

## 5. 不进脚本的内容

- 几何、碰撞、动画、输入、实时循环，归 Godot 宿主。
- 规则求值、行动值、认知投射、案件推演算法，归 `csharp/` Core。脚本只提供数据和条件，不提供算法。
- 素材坐标（`SITE_BOXES`、`ReplayStage` 的房间坐标）归地图布局数据，不进剧本。
