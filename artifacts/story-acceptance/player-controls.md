# 独立玩家操作简表

本表只说明通用界面操作。游戏中的判断和选择必须依据本局真实 CLI 窗口截图；不读取源码、设计、轨迹文件、存档内容、历史报告或其他人物的视角。

## 启动边界

使用已构建的正式 CLI，启动参数为：

```text
--tui --controller llm --viewer detective --map subjective --no-scores
```

组织者负责指定已构建程序路径、窗口尺寸及本轮证据路径。新局不使用 `--restore`、`--replay`、`--dev` 或 `--command`。`llm` 表示由外部玩家输入本人选择，其他人物仍由引擎决定。CLI 是正式逻辑执行入口，不包含 Godot 物理操作。

只向已启动窗口输入下列命令；每条命令按 Enter 提交，等待出现新画面及输入提示后再继续。不批量预写行动，不依据界面外的信息填入标识或答案。

| 命令 | 用途 |
| --- | --- |
| `status` / `options` | 刷新当前状态或候选；不推进下一行动。 |
| `actions next` / `actions prev` | 翻候选页，编号仍是完整候选列表的编号。 |
| `actions all` / `actions compact` | 展开或收拢候选。 |
| `page next` / `page prev` / `page N` | 翻正文与地图页；N 为正整数。 |
| `history latest` / `history recent` | 查看最新事件或近期正文。 |
| `zoom fit` / `zoom in` / `zoom out` | 改变显示密度。 |
| `focus N` | 聚焦当前画面上的第 N 项；先核对文字及编号。 |
| `confirm` | 确认当前聚焦项。 |
| `cancel` | 取消尚未提交的聚焦。不能撤回已经执行或排程的行动。 |
| `act N` | 将聚焦与确认合为一条命令。 |
| `next` | 没有聚焦时请求下一正式步骤；若引擎已有待执行行动则先聚焦。已有聚焦时确认它。 |
| `quit` | 正常关闭，并等待封存完成。 |

本人等待输入时，需要自行选择候选；`next` 不替本人决定。其他人物的行动由引擎选择，玩家用 `next` 让正式调度继续。一次 `next` 不会自动执行所有后续工作。屏幕显示“已排程”只表示选择进入队列；后续仍需推进，实际结果以执行后的可见正文为准。若提示选项失效，重新读取当前候选再选。

保持启动时的本人主观视角。本次独立玩家协议不使用 `map`、`view`、`views`、`inspect`、`tp`、`time`、`scores on`、`advance`、`perf`，不切换或恢复会话。窗口页脚中的通用命令提示不改变这一范围。

读取不完整、窗口文字被遮挡、命令失败、会话停止或预算耗尽时，如实记录当时状态；不把“已聚焦”“已排程”或关闭当作行动完成或剧情完成。
