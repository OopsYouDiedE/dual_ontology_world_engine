# D02：跨章旧规则竞争诊断

状态：DETECTION_ONLY。只读生产源码，未修改生产、规范、既有测试预期或 S18。调查基线 HEAD 为 `7489db56a714724eb7cb735958dd879dc662d238`。这是一份源码与中性机制诊断，不是硬隔离后的结果。

## 结论

旧规则压过新偏好的直接原因是**候选规则没有失效条件，因此在同一个内部世界中继续参与全局竞争**。本章专用习惯规则包含恒真条件和常驻已定状态加分；跨章传递的是活对象引用。若这些旧规则仍在接受状态，后章的 `Assess → Pick → Submit` 不会按章节或 `Job` 过滤它们。竞争发生在候选形成与规则适用性层，再由既有加分公式放大；没有证据支持以“决策缓存未刷新”为主因。

这里被称为 `Habits.Clear` 的实现并不是删除全部习惯或记忆：`Habits` 是一个承载规则的 `Projection`，交接时通过 `ObservationInput { Rules = [] }` 替换该投影的当前规则数组。该动作保留投影、其他认知状态与历史；它是宿主对本章规则生命周期的直接裁定，不能把这个裁定本身当作合理内容的证明。

本轮正式 Core 中性实验成功构建并运行，0 警告、0 错误，生成 20 条原始 JSONL。实验表明：无需提高新权重，只补显式的阶段或未完成条件，就能停止过期候选；承载投影存在性为 `False` 并不自动撤销规则，目标现实消失或目标已经达成也不会自动删除无条件候选。

## 额外评分路径：请求与偏好同效果时社交分被丢弃

`DecisionSystem.cs:25` 先把规则候选加入列表，并令其 `Social=0`；`35` 只有效果尚未存在时才加入请求候选和 `attitude.Score`。因此一个已被规则提出的等价动作，即使请求获得接受，也不会把请求社交分并入该候选，并继续以规则投影作为 `Basis`。中性行 19–20 精确复现这一点。

这可以独立造成“添加新偏好反而使接受请求更难胜出”，但本轮没有证据证明跨章旧规则事故一定经过此分支。不能据此自行更改分数聚合或请求去重语义；应由主代理对照设计判断是否需要修正，以及多个请求的来源/响应状态应如何保存。后章 `Pick` 的同分 Event 优先也无法补偿已经丢失的社交分和 Event 依据。

## 既有原语可以怎样修正，以及什么尚未证实

1. **首选在规则定义中补准确的适用条件。** 使用已有 `Condition.All` 组合阶段概念的 `Exists`、主体的 `At`、目标的 `Exists` 和目标未完成的 `Not Tagged`。所有提出旧候选或给旧候选加分的规则都应共享必要范围，避免只包裹一条加分规则而另一条恒真规则仍提出候选。本实验保留原权重即可停止过期竞争。具体适用范围和何时失效只能由用户要求与设计规范确定，本 Agent 未读取设计，不替主代理选定。
2. **阶段存在性须作为显式谓词使用。** 给旧承载投影或对象改 `Existence=False`，只有规则真的引用 `Condition.Exists` 才会影响该规则；不能给决策器新增“承载投影 False 则所有规则自动失效”的通用语义。目标存在不等于目标未满足，二者也不等于本阶段允许做。
3. **通过正式认知输入更新条件所需状态。** `At` 与标签守卫使用主观投影；宿主位置变化仅 `Sync` 不够，应通过已有感知或合理的内省输入进入主体认知。缺失标签返回 `Unknown`；`Not Unknown` 仍 Unknown。使用未完成守卫时需要正式已知的初始状态，不能把信息缺失直接视为未完成。已完成事件只有 Success，不会自动更新任意目标标签。
4. **`Rules` 替换和接受状态更新已经可用，但需明确内容依据。** 内省 `Rules=[]` 是正式 API；按设计撤销规则接受状态也可通过 `r with { Acceptance = ... }` 再提交规则数组。前者删除当前规范，后者表示主体不再接受；它们不能随意代替“暂时不适用”。`Forget` 会清理引用与历史，范围更大，不宜为了停止候选而使用。
5. **管理已提交动作应使用既有取消/交接前排空。** `SimulationSession.Cancel/Deactivate` 已存在；本章交接先检查运行动作、停止生态，能避免残留动作继续运行。只是更新规则不会取消已有意图。`ActionIntent.Requirements`/`Effect.Require` 的执行检查是现实检查，不负责重新排序候选；纯心智概念没有现实映射时不能无差别放进执行前提。
6. **没有证明 Core 缺少规则范围表达能力。** 本轮确认的条件、规则接受状态、数组更新、认知输入与取消能力都足以表达中性修正。F01 目录确认通用候选桥支持已知存在、位置、整数状态比较和逻辑组合，但不支持直接任意规则声明/规则生命周期写入。可以先用既有已知状态/位置条件表达候选范围；若当前旧规则尚不能由作者端数据声明，需记录作者/编译适配缺口，不把它直接归为 Core 语义缺口。具体生命周期仍由主代理核对设计。
