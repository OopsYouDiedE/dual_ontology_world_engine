# D04 候选合同审批材料

状态：全部为建议，尚未审批、未实施、未转成预期或黄金。本文只依据已读机制接口与中性反例；主任务须对照设计作取舍。

## 需要先确定的用途边界

建议将“主体基于已知条件作反事实规划”和“引擎用真实历史作因果审计”设为不同调用用途。前者不能得到主体未获知的现实字段；后者可以由引擎权威方重建真实历史，但结果不得自动作为主体知识。

当前第二章完整现实快照可服务哪种用途、是否继续保留、主体应当看到何种可观察反馈，须由主任务审查。这里不提出案件答案、角色信念值或内容判断。

## C-D04-01：主体输入与模型来源

候选输入合同：`SubjectiveSnapshot`（主体 ID、认知版本、稳定投影 ID、已知事实与来源、规则、模型版本）+ `HypothesisDelta` + `SearchBudget` + 随机种子/状态。主体入口不接收源 WorldRuntime、源 Essence、完整现实 NightSnapshot 或 CaseActual。

模型生成应只依赖共享机制和已公开的数据；如果调用者以隐藏现实事实删减假设，必须归入权威审计用途。仅凭 Reasoner 的 ProjectionWorld 参数不足以保证上游没有泄漏。

候选验收性质：可见历史、模型与种子保持相同，只改变未获知的现实字段时，主体候选、权重与下一步规划不变。该性质是否作为正式合同须审批；当前中性实验用于发现边界，不是批准它。

## C-D04-02：分支隔离与假设范围

候选合同：分支修改、模拟观察和模拟推断只作用于独立分支；源现实与源认知不变。所有投影/AST/关系引用必须映射到分支，不得靠共享可变 Projection 偷传源世界引用。

`HypothesisDelta` 应显式区分认知假设与处境假设。认知假设改主体已知状态或规则接受，不直接预写具体行动；处境假设改分支现实而非源现实。二者的合法字段需要由调用者和模型声明，不能由本轮诊断自行规定。

核心已有世界边界验证和 Observation 接口，可作为实现基础；当前没有已验证的统一 Core Fork/CounterfactualSession 合同。是否在既有模型上添加通用能力或由宿主先隔离，仍待架构审批。

## C-D04-03：搜索停止合同

候选结果拆分为“认知结论”和“计算停止原因”：保留候选/置信度/建议行动，同时返回明确 `StopReason`，例如 IterationBudget、DepthBudget、NoAvailableActions、InvalidInput、Contradicted。是否添加 Completed 状态及其定义须先决定；建议它描述检查覆盖完成，不能仅凭选出 Prediction 就表示答案已确定。

预算字段应说明由谁消费、消费了多少、剩余多少。ActionBudget 若由宿主限制，应明示该职责；若由 Plan 限制，应在进入搜索和生成建议行动时统一生效。零预算、零深度、无可用行动以及无候选应产生各自可辨认的结果，不靠 null Action 推断。

根候选数得出的 Confidence 可保留，但须明确它不是搜索完成度；预算耗尽仍可返回暂定建议，却不能隐去耗尽原因。

## C-D04-04：历史认知版本与重演

候选合同：追加式认知事件配合不可变 checkpoint，记录稳定投影 ID、版本和完整输入差异，覆盖 Name/Kind/Existence/Parent/Tags/Relations/DeniedRelations/Rules/Procedure/Forget、来源与时间。关系和 AST 以稳定 ID 表达；遗忘记录事件，不删除审计日志。

可保留面向当前角色的易用 History，但历史重演需要独立不可变记录，不能用事件 Target 的当前对象状态替代过去状态。批观察需定义原子版本；同一版本查询必须始终产生相同认知快照。

规划续演还需模型版本、公开进度、已完成动作、可见文本、反馈与随机数状态。审批时需决定重演目标是“恢复过去主体状态后重新规划”，还是“精确续演过去随机过程”；这两者需要的持久化字段不同。

## C-D04-05：已知证据值与缓存

候选合同：比较对象是主体已保存的证据值及其版本/来源，`known` 只作为权限或覆盖集合。真实痕迹值可留给权威审计，不直接替代主体观察。

推断缓存至少按认知版本、模型版本与合法假设输入失效。仅按已知条目/地点集合缓存不足以处理证据纠正、规则更新和旧观察。比较宜基于结构化事实，不依赖渲染文本作为事实相等性。
