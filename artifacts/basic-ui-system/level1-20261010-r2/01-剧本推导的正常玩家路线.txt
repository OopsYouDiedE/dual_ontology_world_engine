01 · 剧本推导的正常玩家路线（一级验收第二轮）
================================================================

【说明】
1. 本文件只依据作者源与源码推导，未运行 Godot、PlayerTranscript 或任何构建；未读设计规范，未参看 02 与 artifacts 下其他文件。
   依据：
   - 剧本入口 godot_csharp/scenes/Awakening/Script/chapter_01.story 与 story/ 下各片段（第一章 story/第一章/…，第二章 story/续篇/…）；
   - 编译生成物 generated_awakening_content.json、generated_awakening_dialogue.json、generated_awakening_layout.json、
     godot_csharp/scenes/Chapter2/Script/generated_chapter_02.json；
   - 源码：GameSession.cs；Chapter1Session.cs / Chapter1SessionFlows.cs / Chapter1Strategies.cs / Chapter1Interaction.cs /
     Chapter1Script.cs / Chapter1Flows.cs / Chapter1Clock.cs / Chapter1Dialogue.cs；Night/MorningStrategies.cs、MorningWorld.cs；
     Chapter2InteractionSession.cs / Chapter2SessionFlows.cs / Chapter2SocialMenu.cs / Chapter2Processes.cs / GameLoop.cs / Demon.cs /
     Council.cs / Chapter2SessionView.cs / Chapter2Narrative.cs；
   - 路线夹具 godot_csharp/scenes/Shared/check/Fixtures/player-transcript.json（chapter1-route、continuation-start、continuation-days、
     answers、priority-choices、council-choices、chapter1-choices、sentence-form-values、inspection-exclude-kinds）；
   - 执行器 godot_csharp/tools/PlayerTranscript/Program.cs（只读其映射：Input 打印“【操作 NNNN】标签”；lines 逐句“说话人：正文”；
     card/candidates/form/ending 打印“【卡片】/【可选陈述】/【作答】/【终局】标题”及 prompt/intro/source/facts/outcome、
     items/notes/rows、header.question/instructions、“可选：选项”；自动选择打印“【选择】标签”；aside 打印正文；
     replay_play 打印 caption 与各帧 label；stage prop 打印“【物品】名：状态”；state 只在变化时打印“【当前文字】”“【场上物品】”
     “【重演手稿文字】”“【重演反馈】”；样式标签 [b][color] 等被剥除）。
2. 体例：每段先写路线步骤与执行器发出的正式输入，再写玩家可见内容；行尾“〔源：…〕”标出处（文件:场面/键/行号 id）。
   运行时才能决定的内容写成“〔动态，待 02 核对：Dxx〕”，只写可能分支与判定依据，不编造结果；动态项编号汇总在文末。
3. 对白在第一章逐句成一个 lines 事件（CompiledDialogueRuntime.Next 每次只出一句，选项挂在其前一句上），
   第二章作者场面按连续台词成段输出（Chapter2Narrative.Drain）。说话人“侦探”“侦探（心声）”在第一章由 LinesEvent
   换成玩家名“侦探”（夹具 text-001 填名为“侦探”），第二章作者场面保持原说话人。
4. 时间：第一章钟从 480（08:00）起，场面首次演出按“剧情时长”结算（未列者默认 2 分钟，talk_/help_ 按交谈/协助 0 分钟），
   试验 17、声路 24、重演 29、走动（换房）2；自由现场每 0.1 秒 tick 计 0.1 分钟。下面给出的分钟数均为估算，只用于判断
   定时流程（600/660/720/780）大致落在哪一步，实际以 02 为准。
