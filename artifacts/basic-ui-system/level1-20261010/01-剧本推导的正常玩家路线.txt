二、路线定义
  路线取自 godot_csharp/scenes/Shared/check/Fixtures/player-transcript.json：
  - chapter1-route：start → view_ready → 侦探站到 (480,300)（活动厅）→ tick → 依次到 E12、E1(试验)、E2(试验)、E3(试验)、
    E4/E5/E6/E7(“help”，各等 200 tick)、E8j(试验)、E9(“help”，等 200 tick) → 按 [0,0,0,0,0,1] 重演 → 站到 (500,130) →
    预选菜单项 answer → 与 E8 铜口交互作答。
  - continuation-start：navigate continue → view_ready。
  - continuation-days：第 2～5 日（玩家第 1～4 日）的 inspect / ask / action(stay|class) / move / interact-kind(bed)。
  - 菜单取舍（Program.cs Pick，第 173～193 行附近）：
      第一章：卡片若有预设动作（desiredCard）选含“:动作”的项，否则选“返回现场”(close)；
              其余菜单先找 chapter1-choices 的 id（"detective"、"close"），找不到就选第一个可用项。
      第二章：priority-choices（chapter2:lesson_precise）→ 询问时选 ask → 有“暂且不答”(pause)就选 → 有 yes 就选 →
              council-choices（proposal:0、archive:0、support:0）→ close/confirm/cancel → 第一项。
      表单：报名填“侦探”（text-001）；声路表单填 sentence=0、spot=foyer；答辩依次用 answers：
            (me,E3)、(V3_0,E8)、(V4_0,E7)、(trust,E9)。
  - inspect：前往该地图并按剧本顺序检视全部交互点，排除种类 bed/watch/meal/tube。
  - ask：取快照 people 中 place 等于当前地点且未睡的人，按 P 枚举顺序取前 N 个（同一日同一时段不重复问同一人），
    逐个“交谈→问问 X 知道些什么→（回应）→ 菜单再出现时选‘没什么了’”。

三、标注方式
  - 每段正文后用【源】标出处：story 片段路径（相对 godot_csharp/scenes/Awakening/Script/story/）:行号 [行 ID]；
    C# 用 相对 godot_csharp/scenes/ 的路径:行号。
  - 说话人照剧本原文；报名后侦探名为“侦探”，故“侦探：”“侦探（心声）：”的显示名不变（Chapter1SessionFlows.cs:78-80）。
  - 【选项】列出菜单全部可选项，【选】为路线所选。
  - 【卡片】按 Program 观察顺序：标题 → 来源(source) → 事实(facts) → 备注(notes) → 可选项。
  - 运行时才决定、源码不能定死的内容一律标【动态，待 02 核对 Dxx】，写出可能分支与判定依据，不虚构结果。
  - 【推断】：源码可推得、但依赖作业调度次序等细节的内容，给出推断依据。
  - 钟点：第一章游戏钟只随场面与行动走（剧情时长.story:1-36；Chapter1Clock.cs），文中给出“推算钟”，不含动态场面加时。
