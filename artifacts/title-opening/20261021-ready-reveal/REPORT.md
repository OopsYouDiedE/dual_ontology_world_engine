# 卷首加载与揭页：实现和二级 UI 观察

日期：2026-10-21。项目：`C:\Users\iii\Desktop\dual_ontology_world_engine`。初始分支：`ui/desk-physical-reference-20261020`。提交分支：`ui/title-ready-reveal-20261021`。

## 交付行为

点击“开始阅读”立即启动正式会话准备，当前封面继续显示真实准备阶段。宿主在封面下安装地图、同图人物、已请求的立绘、视野、灯光、初始镜头与 HUD，等待处理帧、物理帧和实际绘制完成，随后一次揭页进入现场。原“开始阅读 → 案卷正在展开”占位页已移除。标题续读接入同一准备与揭页入口；游戏内视图替换保留原有遮罩。

加载与揭页期间由标题、宿主和 UI 共同持有输入锁，重复点击、确认及返回不能重复开局或穿透到现场。减少动态模式采用相同就绪门限，只省略揭页运动。已安装会话后的准备失败停止派发并保留标题错误说明；安装前书签校验失败可回到原书页。

揭页直接使用现有桌面视口纹理，透明区域露出已绘制的生产现场。生产路径不做 CPU 图像回读。最后一批修正等待内层书页纹理传到桌面视口，再冻结源图像；纸背采样不再把离屏卷边的纹理压成单列。

接口与运行入口见 [卷首到现场的加载与揭页](../../../docs/title-opening.md)。

## 装配阻塞与地图源修正

前三轮真实开场暴露了同图人物缺失。失败诊断中的生活翼有 16 人、13 个身体，缺失 `gu`、`moran`、`margaret`；甲、丙、丁三区的厅各容纳 4 人，却各只有 3 个合法且全部已占用的 Stand，没有可用同室 Spawn。这一结果来自 `normal-03-diagnostic/opening-ui.dvlog` 的失败时只读装配记录；并非据等待时间推测。

源配方增加厅的 `stand_capacity = 4`。生成器保留原 16 个 Stand 的顺序和坐标，只补齐不足的合法候选；甲、丙、丁三个源场景各新增一个 `s16`，组合生活翼同步三点。乙区场景未改。窄发布前校验原标记，生成后复核去掉 Stand 节点的场景剩余字节一致，重复生成没有变化，记录见 `map-publish-check.json`。没有更改家具、碰撞、门道或人物初始房间。

同时按原有初始装配合同让新身体使用显式 `initial_anchor`，避免把移动目的地 `anchor` 当作共同出生坐标；这个合同修正本身没有解决前三轮缺员，缺员的直接修复是上述站位容量。

## 最终观察：source-after-07

实际入口为生产 Main 下的 `tools/capture_start_reveal.gd`，使用 Godot 4.6.1 .NET、Vulkan Forward+。工具通过真实投影鼠标打开凡例、返回封面、点击开始，并在加载同帧发送重复点击、Enter、Esc 和右键。之后不选择世界动作或对白答案。

## 范围与限制

- 观察范围为封面、凡例往返、加载、揭页及第一个可输入现场，没有提交世界动作，没有做剧情通关、独立盲玩、完整对白或实际书签恢复验收。
- 约 80 ms 的截图采样可能有归档背压缺帧，不能证明采样间完全没有闪帧。预览按实际采样时间生成，末帧额外停留 1 秒以便观看，不是逐帧原始录像。
- normal-06 退出仍有 7 个 Texture RID 和 ObjectDB 警告；reduced-02 的控制台保留 7 个 Texture RID 警告。本轮不宣称退出资源零警告。

- 当前工作区还包含其他任务对输入资格、随身操作、背景音乐、初始室内候选及素材的改动。Main、WorldView、UISystem 的这些额外改动在运行上下文中保留；本次使用原始快照与我方版本的精确补丁提交，未整文件暂存这些外部差异，也未更改其代码。
