# 自然书写的中性工程检查

本目录只检查真实 DV 编译器、正文值、声明结构及通用 Core 数据边界，不导入章节、会话或 oracle，也不运行游戏流程。所有检查使用冻结的源码重新自举 C0 → C1 → C2 → C3，并核对 C2/C3 生成源固定点；正例通过真实 C3 生成 C#、构建并执行，负例核对实际编译器诊断及映射回原文件的行、UTF-16 列。

在仓库根目录运行，确保 .NET SDK 和 Python 可用：

```sh
python artifacts/natural-authoring-20261021/checks/run_checks.py --out artifacts/natural-authoring-20261021/engineering-01 --timeout 180
```

`--out` 必须是尚不存在的目录。每次运行封存实际输入、工具和检查文件，并保留编译器生成物、每条命令、原始 stdout/stderr、各场景结果和失败；运行期间输入改变会停止该批。修复后应使用新输出目录，不覆盖失败记录。

`--only 场景名 ...` 可对具体未解决问题进行限定复核，结果会记录选择范围；默认执行本目录全部场景。负例也附带中性的 `(main true)`，以免可执行入口缺失掩盖待检查的函数体错误；负例不会执行。AGENTS 作为启动时的流程快照保留，其副本持续校验，工作目录的后续文档修订不属于该批编译输入。

`behavior.dv` 检查叙述和台词原值、文件内称谓、自然法则与既有 `dv_axiom` 结构的一致性、三值组合与否定、不同 facet、混合表达式、验证和执行边界、行动字段及输入的独立复制。文本模块包含代码样式文字、引号、原样引用指令、反斜杠、非 BMP 字符、U+2028、内部空行和额外缩进；另外覆盖 CRLF 和源文件末尾无换行。台词中的空白行按现行合同分隔条目，叙述中的内部空白行保留，末尾空分隔行不进入正文。

`negative/` 检查缺失与重复分句、未知分句、两种前提或效果写法混用、裸布尔条件、未绑定符号、重名声明、空正文和未闭中文引号。诊断在正文含非 BMP 字符或跨文件引用时仍须定位到原始来源。

`legacy-compatibility.dv` 检查叙述、台词、法则、行动、称谓仍可作为既有公式名，叙述和台词仍可作为局部变量与普通调用语句；同一来源中的自然声明，以及同一函数中的同名局部变量与原文返回，须能同时成立。

`summary.json` 逐项记录实际结果，`COMPLETE` 或 `INCOMPLETE` 只表示本批工程检查状态。结果不能证明人物决策、剧情达成、实际游戏操作或帧率。
