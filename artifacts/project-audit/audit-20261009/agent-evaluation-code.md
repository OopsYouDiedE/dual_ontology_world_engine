## Outcome

There are **6 default `verify.py` steps** (core build, Scope regression, host build, Awakening flow, Chapter2 flow, state gallery). At HEAD the default suite is not evidenced as passing: newest retained run is `artifacts/project-audit/verify-logs/20261009-014828-757756-8676/`, before the 10/09 HEAD commit. Its Scope step reports 24 checks passing, but Awakening flow reports failure at opening and repeated `Nil` access to `host.ui` / `host.field`; the wrapper is designed to detect `SCRIPT ERROR` and stop. There are **12 standalone C# check projects** (10 Godot-host plus two Core), **several standalone Godot/UI checks**, and **6 Python test files plus two simulation scripts**; they are not comprehensively run by `verify.py`.

The in-tree flow checks are automated fixtures with broad state manipulation and simulated/replayed input. They are useful mechanism regressions, not user-experience evidence. `flow_check.gd` explicitly sets progress and uses debug jump/replay/action helpers; `chapter2/check_flow.gd` does likewise for continuation. In contrast, `playtest_session.gd` plus `blind_playtest.py` take live operator inputs; the summarizer validates/derives trace facts and is not itself a game check. Transcript capture replays an existing engine transcript into the UI, so it verifies mapping/display and cannot substitute for actual player input.
