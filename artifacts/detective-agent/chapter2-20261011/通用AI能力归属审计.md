# 通用 AI 能力归属审计

本报告审计正式运行入口，不以文件名或类名推断能力是否已经覆盖所有人物。基线为 `1403465243def4fdc21d148d97208d70ca362b70`。用户已批准下述 Core 迁移；效率优化没有修改 `.story`。文中的原入口描述属于迁移前审计，迁移后的接线与剩余边界单列如下。

## 结论

确有应当共享却分别接线的能力：失败后的方法调整、已观察经历的记忆、依问题寻找信息、目标与候选方法的评估、受到新观察后的重新决策。通用推理器已经在 Core；主要缺口是不同 AI 入口没有共同消费它及相关反馈。

将整份 `PlayerController.cs` 或 `DetectivePlanning.cs` 移入 Core 不能解决这个问题。前者包含玩家界面、表单和坐标协议，后者包含章节案例模型。应提取与主体认知有关的通用策略机制，并让玩家席位、日常 NPC、反应 NPC 与第二章 NPC 都接入；几何、界面和章节事实仍由宿主、剧本提供。

## 判定依据

[设计规范](../../../docs/design-standard.md) 第五部分要求失败进入本人认知并改变下一次选择；第六部分要求方法库全员共用、每人一份推理器、只读取本人认知，人物策略不能写成固定行动队列。设计同时保留角色技能差异：推理深度由角色参数决定，信念重演与多步规划只有侦探会，其他人只做一步排除与证言折算。共享机制不能变成向所有人物广播线索或赋予相同技能。

## `.story` 中哪些内容属于误放或合理声明

`第一章/模拟侦探.story` 含 `iterations`、`exploration`、`discount`、`repeat_penalty`、随机种子和测量行动上限。这些是旧模拟驱动的算法配置，放在章节剧情源里使“换章”和“调算法”混在一起。建议迁到该驱动的配置；若后续确立通用搜索器，再使用共享算法配置。它们目前不控制正式 FullTest，调这些参数不能修复正式虚拟侦探的重复行为。

`生态/人物/01_侦探.story` 的推理深度、预算与偏好属于角色能力和个性声明，可以保留。此次效率修正不改变这些权重。通用的“识别失败、准确记录已走位置、区分坐标空间、保留方向评分差异”不应依赖给侦探提高偏好才能成立。

剧本中的具体行动、可用技能、物件、证物命题、人物目标与对白是内容数据，应继续由 `.story` 声明。某种方法由角色技能禁用，不等于算法被错误私有化。

## 本轮已经实现的共享宿主修正

- `AgentLocate → GameSession → PlayerCandidateSession` 将当前真实位置与不含地图源 ID 的坐标空间身份交给控制器。
- 只有实际观察到的位置会记成走过；请求落点不再冒充已经抵达的位置。
- 同空间执行移动后没有位移，会形成失败经验并降低后续重试评分；此行为不要求角色声明“偏好新选择”。
- 已见地点、走位与交互经历按空间隔离；对应材料的主观证明状态变化允许重看相关交互，不因无关新材料重置其他调查，也不会忘掉已有走位经历。
- 朝已见目标的评分保留远近差异，消除原评分上限导致的同分平台。
- 宿主只记忆实际看见的通行地面与地点，并提供沿记忆路线绕障碍的短路标；返回当前问题需要的地点时，不让过去走过该走廊成为不断累积的阻力。精确碰撞与地图网格继续属于宿主，不迁入 Core。
- 路标只代表接近目标的手段，信息价值与目标的实际调查经历绑定；更换路标不等于新的调查。目标的新颖性、耗尽与必要返回不能分别由每个界面输入决定，这也是后续 Core 主体经历接口应表达的通用边界。

这些导航修正对使用同一玩家席位的任意角色有效。日常 NPC、世界反应与第二章 NPC 共用下述主体经历和评分机制；像素导航不属于 Core，不能宣称所有角色已获得玩家界面的全部操作。

首次正式效率试跑在 113.650 秒停止：侦探已持有可作答的证据，但朝目标直线移动仍在障碍旁重复。该失败说明仅增加反馈与改方向评分不足以解决绕路；路线记忆与短路标是在此后补入，结果另行记录，不能以此前中性合同通过宣称游玩效率已提升。

后续 efficiency-r02 在 168.527 秒停止。细网格路线已能走出此前的窄路卡点，但把路标当作目标调查的计分又导致往返；本轮据此修正手段与目标的经历绑定。失败日志与截图封存，不以动作变少直接判定效率提升。

## 已批准并实施的 Core 迁移

用户明确批准“主体行动经验与决策反馈”这一层，实施范围如下：

1. 提供通用、版本化的主体行动经历类型，以主体已获知的行动、目标和上下文识别尝试；权威事件经合法观察投映后才交给主体。不能让推理器查询源世界。
2. 将失败、无进展和成功区分，按同一上下文的经历产生可解释的重试成本；新观察证明条件改变时允许复查。不要把“直到明天禁止”写成 Core 默认，也不要因无关新线索重置全部失败。
3. 提供纯候选评估组合接口，统一个人规则、已知信息需求与行动经验的评分；候选通过原有 `DecisionSystem` 禁令与实际执行裁决，角色技能及推理预算仍由参数约束。
4. 宿主分别接入玩家席位、世界反应、第一章日常与第二章 NPC；坐标、碰撞、可见候选、表单和取消演出仍由宿主负责。单独移动文件而不接入口不算完成迁移。

迁移验证使用相互隔离的中性主体：同样失败后能改选、未见条件不能从远处获知、条件实际改变后可复查、失败不记成成功、无关新知识不清空空间经历，低预算人物也可一步判断，高预算人物保留深度优势。同时复跑各正式入口，明确每条入口实际获得的能力。

Core 新增 `SubjectiveDecision.cs`：版本化经历、纯评分组合、方向价值和重评条件；`ActionLearning` 从本人认知生成方法与情境键，显式接收真实反馈，保留原禁令并按既有预算读取主观查询。失败、无进展、取消分别记录；无关的新观察不重置相关对象的经历，相关已知状态变化产生可复查的新情境。经历逐条作为 Introspection 节点保存，避免每次在历史中复制全部记忆；`Capture` 可导出合并后的版本化记忆，现有认知和运行时保存协议继续承载。

迁移不代表审计中的全部架构建议已实施。`AcquiredPropositions` 的语义采集仍主要接在第一章玩家；其他人物继续使用各自正式感知/证言适配，尚未统一成同一语义投递 API。旧 `DetectivePlanner` 的章节搜索模型及 `.story` 中旧模拟器算法配置未迁移；它们不参与正式 FullTest，本轮没有通过改剧本调效率。Core 原有 `SimulationSession.Decide/Activate` 兼容入口仍使用原 `DecisionSystem`，新学习 API 由调用者显式接入；正式宿主上述入口已接入，不能把共享 API 可用表述为所有外部调用自动升级。其他角色仍使用浅层预算，未获得侦探专属重演或多步规划能力。

## 验证范围

源码审计与机制回归不代替独立盲玩，也不代表其他人物的完整行为体验已经合格。实际效率测量、失败轮次与第二章完成状态另见本目录 `report.md` 及连续实机证据。

## 门槛与折返复核后的归属

门槛原始几何区域与真实入室回执的接线、当前可见地面采样、公开候选的已见路线距离、人物菜单身份和动作等待期间的候选替代均属于宿主边界。修正适用于使用共享玩家席位的任意角色，无需给侦探单独提高 `.story` 权重；路线成本使用 Core 已有 `SubjectiveDecision.Cost`，重开相关尝试使用 Core 已有 `ReconsiderAttempts`，没有新增 Core 评分分支。

公共面板与人物话题也必须由宿主提供不同用途：前者以 `purpose=panel` 按空间和公开入口记忆，后者按交谈对象记忆。不能因为二者同为 `menu` 输入就共享全部范围，也不能由 Core 根据具体面板文案猜测归属。用途声明和令牌属于宿主，范围正确的尝试经历仍使用已有 Core 记忆机制；该修正同样适用于任意玩家席位角色。

选择接近人物也不能等同于已经调查：移动目标可能在玩家抵达旧位置前离开视野。玩家席位现在等待本次真实场地接触回执，未接触只记失败，不消耗信息来源的调查尝试。失败路线使用既有 Core `DecisionExperienceKeyV1.Context` 保存选择时本人及已见目标的坐标格，真实调查次数仍按空间和目标稳定保存；已见位置变化只切换路线条件，不刷新实际调查历史。此处是共享宿主漏接了已有 Core 反馈和条件合同，补 map/site、所选 token 与公开几何 Context 的适配即可；不需要在 Core 写入某个人物的移动路线，也不需要降低剧本中的重复惩罚来掩盖假完成。

该复核还修正了宿主在同一决策内重复请求等价证明造成的预算耗尽，以及使用默认 JSON 导致 AST 身份丢失的问题。当前适配器复用 Core `Ast.Equivalent`，缓存范围仅是本轮本人、无证据限制的等价请求；带指定证据的求证和假设预测仍走各自合同。若要让所有 Core 调用者自动获得证明缓存，应在独立迁移中明确主体、快照、条件、证据限制、假设与资源预算语义，不能直接把该 UI 缓存搬进去。这是后续可以共享的优化建议，本轮没有实施或宣称所有 NPC 已获得同一缓存。

正式窗口额外显示部分视觉区域没有逻辑房间身份；其归属需内容确认，不能让通用决策器发明新的空间或把空入室键当作全部场景的门槛证据。具体截图、失败与修复范围见 `房间与折返复核.md`。

r09 的实际评分进一步说明，成本正确与否取决于宿主是否描述了真正所发输入。`approach` 只走短路标，原元数据却给出最终目标的整段距离，使同一剩余路程在每段选择时重复成为惩罚。现在短路标只传本段已见沿途长度，直接 `interact` 仍传完整接近距离；Core 的成本组合合同无需改变。该适配对共享玩家席位生效，其他调用者须自行保证候选成本与实际输入一致，不能把它表述为所有外部 Agent 自动获得了几何估算。

剩余声路卡点还涉及 `Chapter1Script.SoundTestThinkable` 的具体证物进度门槛。这属于现有专用内容因果，不能把具体编号与开放顺序当作应下发所有 AI 的通用能力。通用的矛盾发现、选取能补前提的方法、执行反馈值得独立审查，但本轮没有改该门槛，也没有仅凭未通关认定 Core 存在缺陷。内容条件后续应从剧本读取，而非继续扩充专用 C# 硬编码。

最终 r10 只改短路标成本后，正式侦探取得所需前提并完成第一章，实际进入第二章。该结果与中性反事实共同支持宿主成本适配影响了推进，不能据此把本轮证明缓存或几何规划描述为所有 Core 调用者已自动获得的能力。第二章后段仍有区域往返；角色目标与探索候选的价值如何组合，还需要独立分析，尚不能把未完成归因于 Core 或宣称全体 AI 的体验已合格。
