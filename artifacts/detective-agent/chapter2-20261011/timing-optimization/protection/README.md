# 关键节点耗时优化保护合同

本任务冻结现有工作区的运行源码与声明，包含已有未提交修改，不以 Git HEAD 的旧版本冒充当前行为。基线覆盖 Core、Godot 宿主、剧本与生成物、碰撞与输入、时钟、测量入口、设计规范及维护规则；关键节点定义另行纳入。

`manifest.json` 首次封存后提交，运行入口使用提交中的文件为锚点；不提供自动重新封存选项。运行前与结束时比较实际字节，新增源码同样检查。源码变化时停止启动；期间变化时保留原始记录并写入 INVALID.json，不能作为同条件优化结果。

这是一套可审计的运行阻断与版本保护，不是防管理员篡改的安全隔离。绕开入口运行、修改入口再重置基线、覆盖旧证据均违反本任务合同。后续确需修改保护文件，应先记录具体差异、修改理由及独立审查，保留原基线，另立新基线并说明比较边界。

允许优化的是主体用实际已知信息作出行动、真实导航执行与通用计算性能；禁止改变题目正确条件、知识获得前提、剧情日程、倍速、时间统计、自动选择答案、强制入门、传送或直接完成流程。不可通过删减采集与渲染来制造更快结果。

固定运行条件：全新会话、引擎侦探、seed=0、四倍速、对白等待0.6游戏秒、截图间隔10现实秒、无公开进展限制60现实秒。首轮延长观察预算至600现实秒，前180秒与 r24 对照；延长预算本身不算改善。

节点必须有真实检视/执行/被接受的认知或答案结果。内部只读进度用于精确界定采样区间，实际显示与输入用于交叉核对；尚未形成或缺少结论记录分别标明。不得把候选出现、计算完成、位置或菜单当成正确推演。
