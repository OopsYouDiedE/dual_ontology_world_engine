# 移动效率的旧机制诊断

结论：旧方向评分会把相对最远候选缩短至少 128 像素的移动全部压到同一上限；提高正的论证或求知权重不会解除这个平台。旧公开观察没有实际站位字段，旧控制器在选中目标后、提交与到达之前，把目标格直接记为已经走过。修改 `.story` 的权重无法修复这些信息与记忆机制缺口。

## 证据边界

本报告是静态诊断，未运行旧控制器、构建程序或启动 Godot。中断前读过旧工作区源码，但没有封存当时的完整文件；因此使用 Git HEAD `b44aecedd885c0d421cffc44c95ee58a1eaf1802` 的源码作为可复核旧基线，不把它冒充中断前的精确工作区快照。该基线与当时所读源码具有相同的旧方向公式、观察字段和目标写入 `_walked` 语句；历史键的其他改动不在本报告的运行结论范围内。

原始证据为 [Git 基线源码](git-head-PlayerController.cs)、[当前源码快照](current-PlayerController.cs)、[差异原文](PlayerController.diff) 和 [采集清单](capture-manifest.json)。Git 原始输出直接按字节保存，源码在本次采集期间保持不变；清单记录时间、命令、退出码和 SHA-256。未读取项目设计文件。只读过适用 AGENTS.md、机制源码、控制器编译器和明确标为中性的控制器夹具。

## 旧公式为何会同分

旧基线 `PlayerController.cs:379–380` 根据是否有可以回答问题的已观察机会，选择论证权重或求知权重，并计算：

```text
floor(clamp((D − d) / 64 × w, 0, 2w))
```

其中 D 是当前移动候选中离已知目标最远的距离，d 是当前候选离已知目标的距离；两者都来自候选落点。对正权重 w，只要 D−d ≥128，就有奖励=2w。上限与斜率同时乘以 w，所以饱和阈值与 w 无关。

下表是直接代入公式的数学结果，并非运行控制器所得。取 D=1024：

| 候选距目标 d | w=1 | w=7 | w=13 | w=1000 |
| ---: | ---: | ---: | ---: | ---: |
| 0 | 2 | 14 | 26 | 2000 |
| 256 | 2 | 14 | 26 | 2000 |
| 768 | 2 | 14 | 26 | 2000 |
| 896 | 2 | 14 | 26 | 2000 |
| 960 | 1 | 7 | 13 | 1000 |
| 1024 | 0 | 0 | 0 | 0 |

距目标 0、256、768、896 的候选因此失去方向分差。提高权重只放大共同上限；设为 0 会消除方向奖励。截断到整数还会使未饱和的微小差别消失，提高权重可能缓解这一种精度损失，但无法解决饱和平台。

旧基线 `478–480` 在总分相等时使用独立伪随机流选择。只有当其他作者偏好、重访惩罚、未走地面奖励等也不能区分候选时，上述平台才会成为实际总分同分；不能据公式单独声称所有移动都会反复，也不能据本报告给出真实重复频率或游玩时长。

## 实际位置与选择目标混在历史中的缺口

旧基线 `50–51` 的 `PublicPlayerObservation` 只含回合、对白、文字、候选、完成状态。候选 `Location` 在 `45–48`，是候选坐标，不能证明玩家已经到达。旧 `Observe` 处理 `state` 时只抽取 HUD 标题与时间（`611–615`），`638` 构造观察时也没有实际位置。

旧基线 `489` 在 `Decide` 内对选中的移动直接执行 `_walked.Add(floor(target/64))`。这个更新发生在返回选择之前，没有提交、碰撞或到达回执条件。随后 `348–354` 把这个集合用作“已经走过”的距离依据。因此未执行、受阻或未完成的目标也会参与下一次未走地面估值；这是静态调用顺序结论，未在真实场景中复现受阻动作。

作者规则可以调整输入类别偏好、公开标签过滤、禁止/放行及推理预算。`story_controller.py` 的可编译字段没有实际到达位置、失败回执、距离归一化或访问记忆更新协议。给某些公开标签额外偏好可能改变个别选择，但无法补入不存在的实际站位，也无法把目标历史变成走过历史；这些应由共享机制承担。

从技术边界看，有界论证与信息价值算法已经位于共享 Core 的 `SubjectiveReasoning.cs`；`.story` 声明的是角色预算和偏好。导航评分、访问记忆及界面观察桥接位于共享宿主 `SubjectivePlayerController`，当前不能据这些源码宣称每种 NPC 的自主决策入口都使用它。本报告没有通过修改剧本为某个角色增加能力，也不对角色设计作判断。

## 当前改动的静态对照

采集到的当前源码已新增 `PlayerFieldState(Space, Position)` 和观察 `Field`；在读取实际现场位置时记入 `_walked`，选中移动只留下 `_pendingMove`。下次实际位置未改变时登记 `_stalled` 并加入惩罚；历史与已观察场点按空间区分。方向奖励改为除以候选距离范围 `max(1,D−nearest)`，避免固定 128 像素阈值把大量候选提前压平。

这说明当前修改正在填补旧缺口，不构成运行通过结论。新公式仍转整数，有限权重仍可能让距离接近的候选同分，不能宣称所有同分都已消失。宿主是否持续提交正确的实际位置、受阻反馈是否可靠、真实重复与效率是否改善，需由本轮独立运行证据判断。
