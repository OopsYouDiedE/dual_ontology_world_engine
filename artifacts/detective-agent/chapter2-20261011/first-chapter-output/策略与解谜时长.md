## 实际采用的策略

人物声明来自 `godot_csharp/scenes/Awakening/Script/story/生态/人物/01_侦探.story`：欲望是弄清自己为何在此；姿态是求知与谨慎尝试；声明的方法类别为 `check、listen、rest`。

本轮实际执行器是 `SubjectivePlayerController`，由正式宿主启用玩家席位；读取上述人物的操控声明，逐步对当前公开候选评分。`第一章/模拟侦探.story` 中另一套搜索参数不作为本轮执行算法的参数。

| 人物操控偏好 | 权重 |
| --- | ---: |
| 未看过的内容 | 8 |
| 未尝试的选择 | 6 |
| 检视/交互 | 3 |
| 菜单选择 | 2 |
| 走位 | 1 |

人物声明的推理预算为深度 8、展开上限 32768、假设上限 128，论证权重 16、求知权重 8。此次随机种子为 0。

运行中还根据本人获得的材料调整选择：

1. 遇到未解问题，先找已看见且可能补足缺失材料的人或物；没有已知线索时，检视尚未调查的地方并探索视野边界。
2. 偏好未走过的地面；同一动作没有带来新接受材料时，重复尝试会被扣分。获得新材料或新问题后，可以重新考虑以前做过的动作。
3. 有完整的、本人接受的论证，并有可出示证物时，优先回到实际见过的答题地点。
4. 答题时选择有论证支持的陈述，再选择确实参与该论证的证物；达不到提交条件时继续调查或暂缓作答。
5. 重演表单会比较可见选项所形成的假设；表单中的假设选择不等于已经证实的结论。
6. 同分候选按本轮种子决定。点击与按键仍经正式场景、碰撞、交互条件和回执执行。

日志中的 `seek_current_question_material`、`look_beyond_seen_for_open_question`、`return_with_personal_answer` 等字段分别对应上述求知、探索和返回作答行为；完整 TXT 保留了每次选择当时的原始依据，没有把通用策略改写成预定正确路线。
