# 问答检验协议（主持人与主代理）

受测版本：2026-09-25早期电气修订后的 first-awakening-design.md 前半部；历史退稿不在范围。

两个低成本代理均不继承主对话。提问者只读 player-brief.md；主持人可读完整答案，按玩家动作释放观察。双方使用 collaboration.send_message 连续对话，最多12轮，每轮1—3个具体问题；轮次不足以完成时可请主代理延长，不以超时判不可解。

主持人须逐轮保存问题、原样回答、证据出处、未能回答的原因。不得编造补强证据，不得直接给作者推断、人物动机、导师/恶魔身份或预计误导方向。未设计的问题回答“现稿未定义该操作的观察结果”，作为缺口，不假扮游戏内台词。允许展示设计里已有事实、逐步相遇四人、查看可达房间。新人物甲乙丙不记得昨夜。

主代理预登记目标：
- 必须能够回答：所处场所的用途及判断边界；人与场所的关系；门及物品的可支持先后；哪些问题暂时不能知道。
- 期望自然误导：初期陌生感与闭门引出“被带来/被关押”假设，后来物证使提问者主动修正为曾居住与参与局部处理的可能；这是概率性判断改变，不强求唯一真相。
- 不应发生：笔记让人猜出隐藏导师；广播代答场所；不明力量被直接命名；晚期作者答案混入主持人回答。
- 误导是否发生由提问者在答案揭晓前的记录判定。未发生就如实失败，不提示他先猜错。答案知情的复核不再称盲测。

完成时：提问者在不读谜底的前提下独立提交结论、未解问题、信心变化和可疑信息泄露。主持人另存作者侧答复覆盖审计。文字代理结果不代表人类乐趣、游玩时长或实机验收。

## 用户要求重启后的规则

已先完成文稿修改，再尝试启动两名全新上下文的Luna代理。实际只成功创建 fresh_keeper，fresh_questioner 被工具以 agent thread limit reached 拒绝；停止旧代理没有释放创建额度。当前尚未重新开测，以下是预定规则，不是已完成记录。主持人只用 observation-cards.md 给现场回答，用 answer-key.md 私下核对历史与误导目标；提问者只读 player-brief.md，不读旧记录。旧问答保留，新记录追加在同一任务目录与同一逐轮记录中，不另建轮次目录。新测试期间冻结稿件，缺口与误导未发生均直接记录，不能边测边改证据。

主持人不得主动显示远处物件匹配、地点性质或历史因果；跨地点配对需玩家真的取物比对。完整环境查看必须列出当前房间已定义的可见物件，包括传话装置。同一次询问只答一次；可给简洁观察，不为“没有逐字对白”拒绝明确设定支持的回答。最多12轮，确有未完调查可申请延长。最后提问者先提交未揭晓答案的结论，主持人随后做独立审计。主代理在检验进行中只检查协议执行，不把目标或答案发给提问者。
