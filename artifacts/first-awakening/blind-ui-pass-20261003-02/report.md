**进展与亮点**：
- 前约 80% 推进顺畅。
- 空载试柄推出“需要两人协作”；双槽归还匣解释了白片；上游捕集片推翻了“看错水路”的假说，“预测与现场对照”的反馈最出彩。
- 质询铜口拿到移物单（E16）那段对话质量很高。
- 去留写得克制、自愿。像素美术与光照质量高。
- “继续 ▸ / 结束 ■”的区分有用；“Tab 换目标”提示好用。

**问题**：
1. 【阻断】材料到 5/7 后，不知道缺哪两项，也不知道“交接因果推演”在哪里。答辩的拒绝提示指向一个从没露过面的系统。
2. 在厨房北门洞与南口停住后，点地面、按住 WASD 都不动；点厨房内部地面才脱困。键盘移动在大多数场合看起来没有反应。
3. 归还匣提前点“领取白片”，界面直接显示内部错误码 `take_white:ConditionFailed`。
4. 不少看起来可以互动的物件点了没反应（炉灶、碗柜、工具箱、告示牌等）；点 A 物件常常打开 B 物件的页面；底部提示的目标与鼠标所指不一致。
5. 证物目录命名不统一（“五号房”与 E 编号混用），顺序按记录先后，还露出 `E09.deep`、`E09.completion` 这类内部后缀。
6. 答辩页：标签与下拉没有垂直对齐；下拉展开时盖住当前摘要；“开态一定违规？”这类缩写要猜意思；“未补”一行折行后挤在底部。
7. 受流盆、凭证柜页面仍有按钮要滚动才看得到。
8. 对话里没有立绘的说话人只显示一个字的首字卡，显得空。
9. 检视链路“物件页 → 检视 → 证物页 → 返回”仍嫌长；重启没有存档。
10. 答辩下拉里的绝对化选项（“全场细节都已证明”等）一眼可排除；术语密度高。

## 二、主代理复核

| 问题 | 复核结论 | 状态 |
| --- | --- | --- |
| 键盘移动无效 | **测试驱动的缺陷，不是游戏的。** `playtest_session.gd` 用 `Viewport.push_input` 注入按键，事件能送到，但不会更新 `Input` 的按住状态；游戏移动读取的是 `Input.is_physical_key_pressed`，所以两轮盲玩中按住 WASD 从未生效。已改为 `Input.parse_input_event`。时长字段改为 `ms`/`seconds`/`frames`，未知字段直接报错。 | 已修复（驱动） |
| 门洞停住 | 新增 `check/navigation_check.gd`：用侦探的实际碰撞体沿网格路线逐段扫过，4,322 条路线 0 处冲突，静态几何与网格一致。卡点更可能来自动态物体，或来自本轮新加的“连续 4 次重算无进展即放弃”（它会让人停下，不再顶墙）。上一项驱动缺陷使代理无法用键盘脱困，放大了这个问题。 | 待继续排查（实机走位复现未完成） |

| 目录命名、顺序、内部后缀 | 属实。 | 待改 |
