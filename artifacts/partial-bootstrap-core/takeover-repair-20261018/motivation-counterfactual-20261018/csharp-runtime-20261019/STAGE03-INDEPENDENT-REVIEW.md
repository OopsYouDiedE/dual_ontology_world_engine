## 静态结论

本次差异未发现具体数值语义缺陷。该结论只覆盖源码审读，不建立速度改善、正式会话行为或游戏验收结论。

- `SmallNumbers` 在既有三个盒之后初始化。长度1026对应整数-1至1024，索引为数值加1；循环内仅装箱有限整数，不调用自身或其他缓存。`SmallIntegers` 用同样索引构造规范分数，构造器只作分母检查、符号和最大公约数处理，不回调 `From` 或 R，未发现初始化循环。
- `BoxNumber` 先作范围判断，再执行int转换，转换对象只可能在-1至1024之间；随后相等检查拒绝小数。缓存中的整数均由double精确表示。越界、非整数和微小值沿直接装箱路径保存原位值。
- 负零通过 `DoubleToInt64Bits(value) == 0` 被排除，运算与 `floor` 所生成的负零仍保留符号位。正零、-1、1沿用已有盒。NaN/无穷不会落入缓存；已改写的算术仍在 `BoxNumber` 前调用原 `Num`，`floor` 也仍先验证输入有限。
- 算术保留左操作数先于右操作数的 `Num`/`From` 求值顺序，结果有限检查仍在运算之后。`lt` 保留原分支和比较求值，再选择布尔盒；`not` 先调用原 `Bool`。谓词自身原来的真假条件和短路关系保持不变。原来的错误类型与消息生成处没有改动。
- `Rational.From(double)` 在任何缓存命中前保留 `R.Num(d)` 校验。缓存范围只含可精确表示的有限整数，其旧 `ToString("R")` 再解析结果同样为整数/1。负零在原有理数路径已规范为0/1，此处返回缓存0/1不丢失有理数可表达的信息。范围外有限数、分数、指数文本、非法文本及非文本对象保持原解析/报错路径。
- 缓存数组为私有静态字段；double及bool装箱对象在现有安全ABI中无写入口。`Rational` 为sealed record，两个BigInteger属性只有getter，算术返回新对象，未见更新缓存实例的路径。快照/结构相等与序列化读取数值或分子分母；共享标量身份不改变其既有值比较。`ReferenceEquals` 的标量快速分支只新增相同值的提前命中。
