## 结论

在分配成功的正常执行范围，未发现值、别名、通常表达式求值顺序或显式语言费用的确定性阻塞。改动集中于已知长度的 List 构造；没有扩大 DV 值域、改变 FrozenList、使用静态共享结果或引入容量相关语言规则。可以进入主代理授权的集中中性 before/after、编译固定点与后续正式验证；本审查未执行它们。

必须保留一个资源失败边界：字面量预置容量会把整个后备数组分配移到第一个元素表达式求值之前，而原空 List 在首次 Add 时才分配。资源耗尽下，OOM 与某元素自身错误/副作用的先后可能不同。不能声称包括内存耗尽在内的所有异常次序完全不变；不建议为消除此边界恢复无容量构造，否则失去本次优化本身。

## sf_emit_array

compiler.dv:441–446 将输出开头由 `new List<object> {` 改成 `new List<object>(N) {`。N 来自编译器 AST payload 的 rt_count，而不是执行时元素内容或启发式估计。原循环按同一 i 顺序执行同一 emit，原分隔符与闭括号保持。新字符串构造没有执行待生成程序的元素表达式。

C# 集合初始化器仍按元素顺序求值并 Add；前一元素完成后才处理后一元素，元素抛错后不求值后续项。同一子对象在多个元素中出现时保持原引用。map/record 字面量沿已有 array 节点生成，其 dv_pair 调用顺序和重复 key 顺序也保持。

N 是底层 Count 的非负 int，转成有限 double 后仍精确，rt_show 的 invariant roundtrip 输出在可达 int 范围是合法非负十进制容量常量；没有按文本长度、字段值或用户声明预算确定容量。N=0 输出 `new List<object>(0) {}`，与原空根一样仍为新 List 对象、零元素、可变。N=1/2/3 比原默认首次扩到4精确；N大于4可避免增长与复制。每个 literal 仍分配独立根，不共享单例空 List。

只修改 array 字面量，不修改 sf_emit_comprehension；后者仍使用运行时不定长度结果 List。没有从源集合 Count 预估过滤后的数量，也不为分支结果或迭代器提前执行求值。

容量构造分配时机的变化除了OOM顺序，也会改变GC频率、分配指标与现实耗时；它们是工程测量对象，不是值语义或游戏预算。

## dv_pair / dv_single / dv_list3

三个 helper 的参数在进入函数前已按现有 emit_call 形态求值。新函数体分别返回 `[a,b]`、`[a]`、`[a,b,c]`，只把已经求好的参数依次存入新 List，不额外求值、克隆、冻结或类型转换。

原 dv_pair/single 在新空根上执行 rt_push；Runtime.push 的 Invalidate 在未登记的新根上找不到 MutableState，只返回，没有建立 child parent 链或进行世界费用结算。新 initializer 的 Add 因此没有跳过原本必要的别名/缓存维护。根逃逸到函数外之前，没有其他代码得到该根；参数对象不能提前引用这一个尚未创建的根。

同一个参数列表多次传入，旧、新都把它的引用存入结果，而不是深复制；通过参数或结果修改该 child 的既有共享行为保持。两个 helper 调用仍返回不同根。冻结参数保持冻结对象引用，后续经可变owner读取的解冻合同仍交给 R.at/record_find；helper 不在此预先解冻。

dv_list3 原先调用 dv_pair(a,b) 再 push(c)，新版本直接创建三项根。返回项、顺序和参数别名保持；诊断构建中 dv_pair 的调用次数、dv_list3 的包含/独占耗时会变化，这是源码函数边界改变的直接结果。不能拿 --profile 的调用数逐字相同作为等价要求，也不能将减少该调用视为修改显式语言计费。

## 费用与自举

Runtime.list/push 没有自动按 List 操作数扣工作预算；当前 compiler emit_call 直接生成 F_/R.调用，没有在这些 helper 前后附加隐式预算计数。core/70-reasoning-cost.dv 的 proof/action 费用来自显式内容和合同，本候选没有修改这些数值、判定或接口。因此从源码未见省掉 push 导致少扣游戏预算的接线。实际费用/账本仍应由本轮正式证据核对，不能仅凭此审读宣称全会话等价。

编译器自身仍为同一 DV 启动语法，native arity、类型检查和 seed 不需因 List 构造容量而增加执行能力。sf_emit_array 的函数逻辑变更会改变自举生成的编译器 C# 文本，不能要求候选与旧编译器生成字节相同；需要候选自己的 C0→C1→C2→C3 固定点保持，并由源重新生成 Session。原旧产物及对应原始日志保留，不能直接编辑生成 C# 伪造固定点。

新增 helper 数组节点走已有 surface array 类型检查与 C#发射路径，不增加新的语言语法；array N 的容量参数由编译器发射，不属于用户可执行的 rt_ ABI。关于构造容量的工程说明应在编译器与Core容器参考中同步维护。

## 建议集中核对的最小中性范围（暂未执行）

- 字面量长度0、1、2、3、4、5及一个较大有限长度：完整值、顺序、独立根、后续push/replace；工程容量差异单列为预期优化，不要求List.Capacity与旧值相同。
- 元素用中性记录副作用序列和连续错误：前后求值顺序、第一处通常错误、后续未执行；不以强行耗尽内存构造运行验收。
- dv_pair/single/list3 接收同一可变child、两个不同child、冻结child、数值/文本/bool混合；分别改子对象及根，核对别名和不额外复制；两个独立调用根不相同。
- 含重复key、嵌套记录/列表的字面量，检查字段顺序、record_find末项及with/with_many原语义；单独检查comprehension行为未变。
- before/after保留原stdout/stderr与完整中性输出，普通生成与候选固定点分别记录；性能样本和语义输出分开，摘要计算放计时外。profile调用归属变化独立说明，不混为账本费用差异。
