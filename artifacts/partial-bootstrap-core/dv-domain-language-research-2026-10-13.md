# DV 认知切片与动作概率语言研究

DV 的领域中心应是带主体和来源的认知切片、信息到达后的个人理解，以及依据这些认识产生的行动分布。通用函数、循环和记录负责实现算法；领域书写层直接表达这些对象之间的关系，并由编译与运行合同核验。仅增加领域关键字、中文别名或更易读的括号，不能完成这一定位。

本文依据用户本轮提出的语言特征和现有设计/源码研究候选方案。用户已明确先比较动作分数到概率的可选规则，不预定公式。本文是建议，不把候选语法或模型变成已认可的运行规则，不修改剧情、公理、参数或正式会话。

## 现有机制与语法之间的缺口

| 现有依据 | 实际机制 | 语法需要显式表达的关系 |
| --- | --- | --- |
| `core/00-data.dv:113` 的 dv_slice | 切片携带世界、信息域、主体、版本、物体、切面和字段 | 本人的哪一份切片、哪一版本、哪些字段；不是裸记录 |
| `core/20-observation.dv:74,89,144` | 授权观察投影、提交变化投影、本人观察更新 | 权威状态、获准暴露材料、实际感知和认知更新分开 |
| `verification/session/20-speech.dv:106,124` | 内容只提供 cue；解释桥、来源、前提、作用域核验和采纳阈值来自本人 | 同一材料与不同本人认识组成不同解释过程 |
| 同文件的 dvs_speech_model_prediction / dvs_speech | 私有听者模型预测与实际听者接收分列；真实可闻条件限制更新 | 预测对方理解不访问对方真实心智，也不写入对方 |
| `core/50-response.dv:94,107` | 本人价值变化、关系/状态、付出和不确定性产生评分；合法候选中选最高分，平分保持声明顺序 | 分数、概率分布、选择结果和真实执行分别呈现 |
| `docs/design-standard.md` 的 DV 补充 | 通道损失、未知/冲突、解释与采纳、规范与价值、预测与实际执行有明确边界 | 语法不得为了简洁丢掉这些边界 |

当前回应实现不是概率抽样。把它迁成动作分布属于行为模型变更，应另行确定选择规则和参数，并建立区分于旧实现的证据；不能把这一步称为纯语法改写。

## 相近语言与架构的比较

### ACT R 与 Soar

ACT-R 是认知架构及其模型书写体系，区分记忆中的 chunk、通过模块 buffer 当前可用的 chunk，以及 production 对这些内容的操作。buffer 中的内容是复制出来的块，修改它不直接修改原块。这提供了“存储的材料”与“当前可供处理的材料”分开的直接参考。[ACT-R 官方手册](https://act-r.psy.cmu.edu/actr7.x/reference-manual.pdf)

Soar 把候选 operator 的 numeric-indifferent 偏好与选择策略联系起来，提供 Boltzmann、epsilon-greedy、按数值偏置等选择设置。其文档把 softmax 与 Boltzmann 列为不同策略，不能按名称直接假定公式相同。[Soar 架构](https://soar.eecs.umich.edu/soar_manual/02_TheSoarArchitecture/)、[Soar 选择策略](https://soar.eecs.umich.edu/reference/cli/cmd_decide/)

DV 可借鉴：存储切片、当前取用切片与外来提供材料分型；可选行动先形成候选与偏好，再进入显式选择器。DV 不直接采用其固定模块、检索公式、噪声参数或奖励学习机制；采用任何检索/激活模型仍须独立说明，不能用认知架构的名称替项目机制提供心理有效性证明。

### AgentSpeak 与 Jason

Jason 在信念旁保留 `source(ag)`、`source(percept)`、`source(self)` 等来源注解，来源可参与计划触发和匹配。语言使信念来源直接可见，而不是将其藏在日志里。[Jason 来源注解](https://jason-lang.github.io/jason/tech/annotations.html)

DV 可借鉴：依据和主体归属进入可匹配、可检查的语义对象；来源不能只是可任意填写的备注。DV 还需要保存事件链、认知版本、有效时间、依赖组和可撤销状态。来源为某说话者只表示材料的来处，不证明内容成立。

### WebPPL 与 RSA

WebPPL 的 condition、observe、factor 在推断中分别用于约束或调整执行的概率权重；factor 加入的是对数概率分数。这展示了随机选择、条件约束和加权推断成为语言操作的方式。[WebPPL 条件化](https://webppl.readthedocs.io/en/master/inference/conditioning.html)

RSA 是语用模型框架，不是独立语言。其 WebPPL 示例把听者先验、内容语义、说话者效用与听者对说话者的推断组合起来，使用指数归一化表达近似理性的选择。同一内容的解释因听者模型而变，是这里最贴近 DV 的参考。[RSA 原作者教程](https://www.problang.org/chapters/01-introduction.html)

DV 可借鉴：理解模型必须显式依赖本人既有材料和规则；说话者以本人持有的听者模型预测效果。不能直接继承教程中的布尔字面真值、有限对象例子、共享意义或合作目标作为 DV 的默认条件。DV 的 Unknown、冲突、错误采纳、渠道损失、意图差异与有限预算必须保留。理解本身可以是确定的规则过程，也可以是分布；不因动作采用概率选择就强制所有理解随机化。

### ProbLog

ProbLog 的概率事实/概率规则、annotated disjunction，以及 evidence/query，使规则推演与概率查询在源码中共同出现。[ProbLog 官方教程](https://dtai.cs.kuleuven.be/problog/tutorial/basic/02_bayes.html)

DV 可借鉴：规则、证据和查询的关系直接书写。不能将“0.8 支持某命题”“0.8 的动作选择概率”“0.8 的事件发生概率”合并成同一个注解。证据权重、来源信度和命题置信度也不自动满足独立概率事实的语义。

### RDDL

RDDL 明确区分状态、动作、观察和中间变量，并用条件概率函数描述转移；观察变量用于部分可观察过程。[RDDL 官方维护项目文档](https://pyrddlgym.readthedocs.io/en/latest/rddl.html)

DV 可借鉴：真实变化与可观测产物分开声明，观察不是直接读取全部世界状态。RDDL 的观察变量本身不能代替 DV 的来源、本人记忆、解释桥及可撤销采纳；也不能把外部环境的条件模型自动交给主体当作已知世界规律。

### Gen 与动态认识逻辑

Gen 以带地址的随机选择和 execution trace 组织概率程序，轨迹保存输入、选择和返回值，便于检查与更新。[Gen 官方接口](https://www.gen.dev/docs/stable/ref/core/gfi/)

DV 可借鉴随机决策的稳定身份、显式随机源和可追溯结果，但 Gen 的概率分数不是 DV 的价值分数或认识置信度。一个种子也不够完整重放：须同时固定候选排序、选择器/随机算法版本及消耗顺序。

SMCDEL 是动态认识逻辑模型检查器，可参考其把主体可区分信息与信息事件的改变作为明确对象的方向。[SMCDEL 官方仓库](https://github.com/jrclogic/SMCDEL)

DV 不据此宣布已有完整 DEL/S5 语义，不采用“知道必然为真”替换人物的可错信念。它是信息边界参考，不是动作评分或实际语言理解模型。

## 建议的语义核心

认知材料沿以下关系流动；箭头表示独立操作/结果，不代表必然执行完全部阶段：

```text
来源持有或获准暴露的切片
  → 提供材料 Offer
  → 实际传递与感知 Percept
  → 本人记忆/规则参与的 Interpretation
  → 保留、采纳、拒绝或撤回
  → 本人更新后的认知快照
  → 候选行动与合法性/能力核验
  → 分项 Score
  → ActionDistribution
  → Intention
  → 准备与真实执行 Receipt
  → 可被有关主体实际感知的新材料
```

“被提供用来认知的切片”至少有两种来源：世界在授权观察范围暴露的切片，以及另一主体选择表达/展示的切片。它们都必须保留来源与可达条件，后者可能表达错误信念。不能把两者统一解释成客观事实输入。

建议的小核心合同：

| 对象 | 必须保留 | 禁止的隐式转换 |
| --- | --- | --- |
| StoredSlice | 本人、本地对象/切面、认知版本、有效时间、依据/冲突 | 存储不保证本次已取用 |
| WorkingSlice | 从本人存储取用的来源、当前上下文与预算收据 | 不因取用获得更高真值 |
| OfferedSlice | 提供者、来源、目标接收范围、表达的内容/切面 | 不等于实际送达或接收者信念 |
| Percept | 实际接收者、传递/观察收据、保留与丢失材料、本地引用 | 不恢复未收到的内容，不跨主体复制引用 |
| Interpretation | 本人快照、实际输入、使用的存储切片/规则、解释及作用域 | 不自动采纳，不等于客观真相 |
| Adoption | 本人采纳方式、依据、置信、前后版本与撤回依赖 | 不给物理世界赋真，不自动成为执行许可 |
| Score | 同一主体/快照的候选、分项、未知项、评价策略与预算 | 不自动成为 Probability 或 Truth |
| ActionDistribution | 合法候选集合、选择器版本/参数、归一化概率 | 不自动抽样，不等于行动成功概率 |
| Intention / Receipt | 选择和实际执行分别记录，执行时重新核验状态 | 意图不表示已执行，也不更新他人认识 |
| ModeledMind | 建模者、被建模者、来源/假设、版本、使用预算 | 不读取目标的真实心智，不提交目标更新 |

这些是候选语义对象，不要求最终源码逐项填写所有元数据。由上下文和真实收据导出的字段可以省写，但展开后的核心项必须齐全，诊断仍能回到作者的源码。

主体归属、跨阶段禁止转换、操作能力及值的种类适合静态检查；动态主体身份、快照/令牌是否过期、真实可闻/碰撞和预算余额仍须运行时核验。不能仅凭 `Slice<Subjective>` 宣称已经证明来自同一个人的同一版本。

## 建议的书写形态

领域层先围绕上下文、切片关系和决策声明提供语法；算法层继续保留普通函数与循环。不要给每个现有库函数都造一个关键字。

以下是可读结构草图，名称/操作尚未成为正式文法，库引用均为通用占位，不是实际可编译程序：

```dv
interpretation local_reading {
    input: actual_percept;
    within: listener_snapshot;
    memory: relevant_personal_slices;
    rules: personally_adopted_rules;
    scope: input_scope;
    budget: personal_reasoning_budget;
}

decision response {
    within: actor_snapshot;
    candidates: personally_available_actions;
    eligible: legal_and_executable_candidates;
    score: adopted_value_policy;
    distribution: adopted_choice_policy;
    random: session_random_source;
    budget: personal_decision_budget;
}
```

两个声明必须有新的语义检查含义：interpretation 不允许输入未实际取得的切片，也不允许读取他人真实脑内状态；decision 不允许跨本人版本拼分，合法性先于归一化，分布和随机抽样结果分列。它们可展开为可审计的小核心操作，不只是给普通函数换拼写。

更简洁的表层候选可以用 `within subject at snapshot { ... }` 固定词法上下文，再以 `slice ... from ...`、`interpret ... using ...` 和 `choose ... according to ...` 表达关系。上下文必须由显式参数绑定；它不是隐藏的“当前人物”全局变量。最终是否采用声明块还是关系式写法，应以同一语义核心的可读性和诊断对照决定，不同时维护两套运行含义。

提供/送达、解释/采纳、分布/抽样、预测/执行需要不同的效果合同。作用域桥也必须是本人已有规则或显式假设的结果，不能因为表层省略字段就在内核中自动补上。保留存储的原材料、暂未采纳解释和已采纳认识的区别。

## 同一内容为何产生不同理解

建议理解合同写成：

```text
Meaning = Interpret(
    实际收到的材料,
    本人当时的存储切片与实际取用结果,
    本人已采纳的解释/推演规则,
    本人持有的说话者模型与来源,
    当前问题与时间/指代/作用域,
    明确的认知预算
)
```

相同内容与相同实际输入不保证相同解释；不同记忆、局部引用、规则或预算可能产生不同结果。反过来，不同主体也可以形成相同解释，不应硬编码人物类别或强制差异。若主张记忆检索/注意力会限制理解，应单独声明和记录该模型；首轮可以采用明确的有限取用规则，不凭“像人脑”自动引入随机遗忘或激活公式。

理解后的采纳/保留由另一合同决定。说话者预测使用其本人持有的听者模型，不访问实际听者快照；真实听者稍后以自己实际收到的材料和本人记忆运行。预测错误是允许记录的结果，不由实际结果回填先前预测。

没有可依据的解释桥时，结果可为缺依据/未知/请求澄清，不能由 oracle 补齐。发生范围跨越、冲突或错误采纳时保留过程，不能使用作者真相在编译阶段纠正。

## 动作分数到概率的候选

先确定合法且本人能提出的候选集合 F，再计算同一快照内的分数 s(a)。客观执行门禁由受权限控制的执行侧核验；不能把仅权威知道的禁止原因泄漏给主体。未知门禁如何处理须有显式策略，不把 Unknown 自动当作已证实的许可或拒绝。

| 选择规则 | 分布形态 | 长处 | 需要处理 |
| --- | --- | --- | --- |
| 最高分 argmax | 概率集中于最大值；平分规则明确 | 可保留现有确定行为作迁移对照 | 无法表现一般的概率选择；现实现平分为先声明者 |
| 指数归一化 Boltzmann/softmax | p(a) ∝ exp(s(a)/T)，T > 0 | 可用负分，连续表达相对倾向 | 分数单位/尺度与 T 必须一起明确；所有有限分候选有正概率 |
| 非负权重归一化 | p(a) = w(a)/sum w，w >= 0 | 权重语义简单，可以显式为零 | 原分数可为负，转换规则不能临时平移；全零须明确处理 |
| epsilon-greedy | 最大值选择与合法候选探索的混合 | 容易表达探索 | 通常较难表达非最大候选间的分数差异；不自动等于人物犹豫模型 |

Soar 展示了选择器显式化的可行性，RSA 展示了指数归一化与效用的连接；这支持提供可选择的机制，不支持未经标定就确定本项目公式。[Soar 选择策略](https://soar.eecs.umich.edu/reference/cli/cmd_decide/)、[RSA 选择模型](https://www.problang.org/chapters/01-introduction.html)

建议原生类型区分 Score、ActionProbability、PropositionConfidence、Likelihood、SourceReliability、EvidenceWeight、Cost 和 Priority。禁止将 0.8 的动作概率解释为命题成立的八成把握，也禁止将评分直接代入概率位置。世界的随机转移、主体对世界的不确定性和动作抽样是三个不同随机对象。

首轮可把 choice_policy 作为声明，要求返回正规化分布与明细，不把任何公式硬编码为所有人物的天性。最大值策略也能作为集中分布保留，与概率策略共用记录接口。候选重复、非有限分数、空候选、全零权重、参数无效均明确诊断；非法动作的支持集概率严格为零，巨大负分不能代替硬门禁。softmax 使用减去最大分数的稳定计算，不改变数学分布。

动作身份、候选顺序、评分组成、选择器/参数版本、分布、随机源状态/抽取值和选出意图均记录。新增候选会改变归一化分布，必须核对候选是本人如何产生的；不能只比较分数。采样不自动成功，执行仍须新鲜状态、碰撞/可达性、代价和权限核验。允许连续两次相同动作，也不能为制造剧情变体强制换选。

## 最大化特征而控制语言规模

值得原生化的是反复出现且存在越界/混淆风险的关系：主体与版本绑定、切片获取/投影、带来源解释、可撤销采纳、评分到分布、抽样到意图、预测到真实执行的边界。具体心理权重、检索算法、推断器、选择公式和优化仍以普通 DV 实现，通过受检合同接入。

这使作者主要写“谁用什么认识理解什么、依据什么选择什么”，而编译器作者仍能用 DV 写词法分析、容器和搜索算法。所有声明进入同一绑定/类型/能力检查和后端，自举要求保持；不要建立一个隐藏 C# 求解器，也不要将内容实例搬入通用 core。

`define` 保留为中文书写工具。中文可以表达领域关系，但不能补出领域语义；英文与中文应展开到同一核心合同。

## 建议的下一阶段

1. 先确定 StoredSlice、OfferedSlice、Percept、Interpretation、Adoption、Score、ActionDistribution 的最小合同和禁止转换，记录类型与运行时各自检查什么。
2. 以通用匿名案例比较两种表层写法：同一材料/不同本人记忆；提供但未送达；解释但未采纳；说话者模型预测错误；相同分数/不同选择策略。每个例子先固定现有规则与认知前提，不生成新剧情答案。
3. 对选定写法补完整文法、来源映射和错误诊断，再实现 DV 前端。不要先全面迁移编译器和 core 后才发现领域合同还在漂移。
4. 概率策略作为独立机制变更，经选定公式和参数合同后运行真实程序；纯语法迁移保持原最高分行为。两者证据分开，不能用新概率机制与旧版作同语义比较。

本轮仅审视源码、设计及原作者/维护者资料，产出研究建议；未修改可执行源码，未做运行测量或一级/二级/三级验收，也未执行流程回归。第 12 节的易读写法仍是候选表层基础，不能代表这里提出的领域语义已经实现。
