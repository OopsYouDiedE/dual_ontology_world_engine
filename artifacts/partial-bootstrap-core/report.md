# DuelView（DV）：语言设计与独立自举原型

日期：2026-10-12。分支：`codex/partial-bootstrap-core`。新实现目录：`language_core/`。

## 结论与用户要求

路线可行。现有 Core 的规则 AST、主体隔离、证据加权和有界行动搜索可以改写为语言模块，启动内核先由 C# 提供。本轮已实际实现自身语言解释器，并用它载入自身源码和推演模块；正式新 Core 的推演接口经过这些语言实现执行。

用户已将最终条件明确为：编译器及全部推演核心均用本语言实现，并由自身编译器生成 C# 或其他目标语言代码。名称维持 **DuelView（DV）**，活动语言源码后缀已统一为 `.dv`。当前首版没有 DV→C# 编译器，也不是旧 Core 的完整迁移，不能以解释自举宣称这项最终条件已经全部实现。完整清单、差异和缺口见 `language_core/README.md`；尤其仍欠自托管解析/类型检查/IR/后端、旧规划收益模型、候选上下文枚举、学习/社交全合同、完整执行时序与保存、以及现役游戏接入。

用户后续明确了方向：以多主体视界、可错信念和带证据权重的推断为目标，不将它定位为 Lean 证明器。心智模型表达与语言自举分开：前者在本人已持有的模型中预测；后者由本语言实现解释器和推断算法。Lean、Kripke、PPL、主观逻辑或半环不能仅凭类比成为实现已经符合这些数学体系的证明。

## 实现边界

C# 启动层保留数值、列表、词法闭包、基本 cell、函数调用和预算。native table 不包含推断器、案例求解、规则评分、规划器或旧 Core 入口。没有第三方包与旧 Core/Godot 项目引用。

`bootstrap` 中实际写出了三值条件、Rule 模式、合一、ground Horn 求解、候选/置信度更新、有界条件推导、行动预测与奖励回传、社交分数和尝试记忆。`InferenceProgram` 先通过语言自己的解释器载入这些模块，`WorldCore.Evaluate/Assess/Infer/Prove/Reason/Plan` 通过所载入函数运行。不是将 `.owl` 外壳转调一个隐藏的 C# Reasoner。

权威身份、真实可达性、观察的原子提交、不可变快照、类型化合同与最终事务提交仍由 C# 管理。`Prepare` 的主观禁令核验、纯准备算法和触及对象分析在语言侧；宿主检查实际控制、可达性与版本并提交。准备成功尚未等于已提交，认知或权威版本变化使未提交 token 失效。

本轮只支持数值、关系、条件和序列效果。未支持的 wait、lease、act、say、think 等语法直接拒绝。C# 读取器与 AST 编解码未自托管，必须继续迁移以达到用户的编译器自举要求；当前仍须如实称为部分解释自举。

## 正式语言结构与 AST

`language_core/DESIGN.md` 是目标规范，给出通用函数/数据/类型结构、显式视界、命题/规则/证据/效果、类型化 AST、具体解析树、能力边界、目标无关 IR 和多后端合同。其正式类型化语法尚未实现，不能把文档中的 defn/type/module 当作当前 seed 的可运行语法。

编译器自举链为 C# 启动 C0 → DV 源码编译器 C1 → 同源再编译 C2 → 同源再编译 C3，固定源码/选项/ABI 后比较 Compiler2.cs 与 Compiler3.cs，再核对实际语义与诊断。外部 C# 工具链可保留，DV 的前端和 C# 代码生成本身必须由 DV 实现；生成物不手改。

按用户补充，借鉴 Lean 的基本声明、定义环境、elaboration 和小语义核分层。世界法则、本人推演规则与行动优先策略分为不同 AST 声明与运行环境合同：策略影响选择，推演规则产生带依据结论，世界法则描述真实状态转移。内核最终也用 DV 编写；概率依据和行动轨迹各自核验，不统称为 Lean 式形式证明。

## 当前证据

早期冻结运行目录为 `engineering-20261012-r1/`，使用历史 `.owl` 命名。修正前的独立审查为 `independent-review-r1.md`；`r1-executable-source.zip` 保存与 r1 指纹一致的可执行源码，未伪造旧文档快照。旧原始输出不覆盖。

当前冻结运行目录为 `engineering-20261012-dv-r2/`，存放运行前源码 SHA-256、原始 stdout/stderr、实际调用命令及程序集 SHA-256；执行结束记录源码未发生变化。构建结束后才运行机制演示。之前出现的构建、列表定界和自解释指令预算错误保存在 `engineering-initial.txt`，DV 修复期间的具体定界错误保存为 `engineering-dv-initial.txt`。

`dv-r2-source.zip` 保存与 r2 指纹一致的全部语言源码原始字节，包含工具生成文件的原始换行，避免 Git 文本规范化被误认为测试期间改动。独立复评另封存相同指纹的运行 DLL。源码/程序集快照只能用于该轮具体机制，不自动代表旧 Core、正式编译器或游戏。

实际输出支持以下有限结论：

- 自身语言载入词法闭包程序后输出 13，与 seed 输出一致；取出新载入的解释器再调用，实际算出 42。两个不同闭包的身份和类型现在均为 `(false false)`。
- 同一 testimony 在信任为 3 的视界中使选项置信度为 `0.7777777777777778`，不信任视界为 `0.5`。正式 C# 入口经自解释模块得到中性 testimony 的 `0.6666666666666666`。
- 本人对命题的值为 false，其明确声明的他人模型为 true；模型缺失时为 unknown，假设模型仍保留 hypothetical 与本地来源标记。
- 两步语言规划预测 change → set，回传分为 12；原始认知数据仍保留 progress=0。正式规划接口也未改写权威 stock=3。
- 已接受 Infer 规则能给出 true 与实际 rule basis；显式假设有 hypothetical 标记；不足深度得到 unknown/depth。
- 未观察标签为 Unknown；权威 ID 被主体引用边界拒绝。主体仍相信 stock=9 时，权威资源不足会拒绝 spend 3。
- 先 set 100 后 spend 101 的阶段因资源失败，权威 stock 保留 2。竞争 token 返回 stale-world，重复消费返回 already-committed，认知变化返回 stale-cognition。
- 远距 require 只返回 out-of-reach；false conditional 不执行不可达的 body。一个认识 facet 的普通写入能提交到共同实体；未改 alias 不再阻塞它。
- 更强的已接受 ban 在正式提交前返回 forbidden；同权重 Permit 只解除禁令，未额外提高 prefer 的分数。
- 同一 stock=3 的实体经 object/facet 各 spend 2 返回 resource，权威 stock 仍为 3；经两个别名各 change 1 累积到 5。显式 object 禁令经 facet 执行返回 forbidden。
- 未观察 when 条件与相对数值均未展开成确定后继，正式 Plan 输出 no-action，并保留 unknown-condition 与 unknown-state，score=0。快照与权威 stock 未改。
- 同一不可达位置的 exists present/absent 均输出 out-of-reach；没有通过 missing-object 区分它们。
- 规划 expansions=1 包含共享初始状态，输出 selected depth=1、compared depth=1、expanded=1、complete-layer-budget；不能用父状态计数冒称候选边数的总预算。

这些结果证明相应机制确实发生，不是全游戏合格、人物改善、形式化证明或完整 seed/self 等价证明。所有置信度数据是通用机制示例，没有实际角色、章节、题目或预写答案。

## 已修复的初审问题与局限

初审发现自解释闭包原来用普通列表表示，导致类型/身份差异并暴露环境；已改为不透明函数包装，并加入原反例。正式 Prepare 原来不检查主体 Forbid；已通过同一语言规则评价补核验，并实际记录 stronger ban 的拒绝。未改别名状态原来会触发冲突；目前只合并有变化的结果，普通单 facet 写入已实测。远距 authority guard 与认知版本 token 的边界亦有具体复测输出。

r1 独立审查进一步发现：两个别名有独立阶段资源导致重复支出和累积丢失、显式禁令可以绕行、未知 when 被当作 false、远距存在性失败原因泄露和首层预算未计。当前修正为：宿主建立实体到本地规范引用的唯一映射，DV canonical-nouns 与 prepare 在同一阶段资源上演算；规则前提仍在本人视界评价，真实禁令的效果引用在提交边界规范化。访问检查先于对外存在性失败，Unknown 预测返回具体原因。预算计父状态且包含初始状态，选中路径与完成比较层分列。上述同输入结果由 r2 记录支持，独立复评另行保存。

自解释解释器存在明显指令开销。最初两步规划在 20,000,000 指令预算下停止，当前声明 100,000,000 上限；这是新语言自身的工程预算，不是更改正式游戏时间、保护基线或剧情规则。推导与规划语义预算另设，不能混为宿主指令或游戏耗时。

归一化的现有来源因子没有一般条件似然的模型，因此未把它冒称为贝叶斯。独立 `bayes-update` 示例有显式 prior/likelihood，输出 0.1/0.9；相关证据、概率解释重叠、Dempster–Shafer/Jøsang 全算法和完整 Kripke 可达语义未实现。Horn 目前限制 ground clauses，变量合一存在但变量子句求解尚未接入。

规划是迁移原型，当前正向奖励按动作结构去重，尚不是旧 Core 的完整目标与信息身份账本；成本、未知分支细节、真实已见方法库、观察上下文转移和全套学习接口还须迁移，不能直接替换现役共同决策。

## 工程、机制与游戏分别评价

工程：独立解决方案能构建，错误已记录并修复；没有旧 Core 或 Godot 引用。

机制：上述语言与事务行为有 r2 冻结证据。初审、r1 缺陷审查与 r2 修正复评分别保留，不将修改前问题当成修改后结论。独立复评结论以 `independent-review-dv-r2.md` 的实际范围为准。

r2 的新上下文审查在本轮指定输入范围内没有再复现上述实质失败；冻结源码和生产 DLL 的前后指纹一致。额外隔离观察中，object=7/facet=2 的主观认识在真实累计 change 后仍保留各自值，权威 stock 从 3 到 5；两个主体的同名本地句柄不共享认识更新，不能借用对方身体执行。该结论仅适用于报告中的具体输入，不扩大为所有别名、线程、存档或未知分支的完备正确性。

设计核对：本人认识与权威状态分离、预测不回写、规范规则与推知规则分离、禁止具体剧情进引擎，是主代理对照现行设计采取的边界。现役全员共同调查、方法库、章节内容和人物动机没有接入新 Core，不能依据原型宣布这些设计已满足。

验收级别：仅工程排错与语言机制验证。一级三份全程记录、二级 Godot UI、三级正式引擎侦探/盲玩均未执行；没有游戏表现或游玩时长结论，未运行任何 flow 系列或统一流程回归。
