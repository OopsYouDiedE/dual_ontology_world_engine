# R18 批量采用法则提案独立静态审查

日期：2026-10-15。只读核对现役 dv_adopt、dv_with/dv_with_many/dv_clone 以及 c2_install_actor_laws 的完整构造顺序。未读取设计或私有规划，未修改源码、构建或运行会话。本报告审查尚未实施的提案，不推定当前正式会话已接受答案或完成交接。

## 结论

通用 `dv_adopt_many(world, entries)` 在限定条件下可保持逐条采用的最终结构结果、法则顺序、修订号与持久复制隔离，同时避免为每条法则重拷整个增长中的 world。c2_install_actor_laws 当前不读取逐步 result 的内容或 revision，不发布中间事件或调用外部回调；声明构造只依赖输入 domain、actor 和固定原生表，适合保持原顺序后批采用。

它是安装实现优化，不应改变资格、公理、来源、内容、判定、预算或正式行动。实际收益仍须未来独立实现和测量，当前会话继续冻结。

## 必须保留的采用合同

按 entries 顺序，对每项保留原 dv_adopt 的验证顺序：

1. dv_unit(confidence)。
2. physical 世界要求 confidence=1。
3. basis 非空。
4. law.name 不在旧 adoptions，也不在已通过的本批前项中；不得覆盖、静默忽略或合并重复法则。
5. physical 只允许 enforce；mind 只允许 predict/infer/norm，其他 domain 拒绝。

条目内容保留 law、mode、confidence、basis 和 active=true。不要趁批处理增加默认 mode、置信值或缺省来源，也不删除既有法则、改变版本或自动去重。

全部成功后 revision 必须为旧值加实际条目数，并保持旧法则顺序、新法则原追加顺序和其他 world 字段的值。空批应直接返回原 world，匹配零次逐条采用，不额外修改修订号或分配语义。

## 失败语义

现役 c2_install_actor_laws 的中间 result 仅为函数局部值；任一采用失败时不会返回半安装 world。批 API 同样必须在失败时不修改输入 world/adoptions，不能把通过前缀提前发布为真实状态，不能吞掉错误后继续。

对已经构造好的同一 entries，逐项验证可保留采用检查的首错及错误类型。批内重复须在遇到该项时按原重复错误处理，不能改成预扫描整批重复并抢在前项的置信/来源错误之前报告。

另有构造顺序边界：调用者先构造完整列表，再执行批验证，会将后项法则构造提前到前项采用检查之前。如果某个后项构造自身会抛错，可能改变失败时最先观察到的错误。本审查没有运行全部构造，不能声称任意非法输入下首错顺序完全等价。若要求这种更强合同，须保持构造阶段的检查顺序，或限定证明当前声明构造在所支持输入上纯且有效；不得仅凭批 API 内的验证顺序作出更强宣称。

## 复制与别名

独立复制旧 adoptions 后在私有构造容器追加，再用原 dv_with_many 构造返回 world，能够保留 world/mind 与预测分支隔离。最终输出不得与输入 world、输入法则或 basis 的可写子树形成新的共享；保留既有独立复制路径，不使用 owned-state helper 组装通用 world。

最终 dv_with_many 仍会复制更新后的 adoptions，因此“先复制 adoptions、最后再独立复制 world”不等于总共只发生一次树复制。可准确描述为消除逐条反复复制，而不夸大为零复制或全程单次复制。旧历史、对象与来源必须完整保留。

## 预算与边界

dv_adopt 本身不改变主体规划、推演工作预算或行动费用；批 API 也不应引入此类修改。修订号 +count 不能改成 +1，不应给所有法则重写为同一新版本。

本次只考虑 c2_install_actor_laws 的静态安装，不自动推广到执行、重新考虑采用、事件交织或依赖前序 world 的构造循环。它不能把真实采用行为或观察传播合并成一次省略中间效果的动作。

## 实施后最低核对

需审查确切差异：每个分支和循环的条目、顺序、law.name/version、mode/confidence/basis 完整一致；验证旧重复与批内重复、空批和拒绝输入不改原 world；验证 revision 与独立复制。必要工程核对不得使用流程回归或通过计数作为游戏效果结论。正式会话另立来源及程序集指纹，真实回执和章节呈现仍按实际记录判断。
