# DV 正式宿主四倍速侦探与独立盲测比较

2026-10-14，分支 `codex/partial-bootstrap-core`，游戏源码提交 `a2a3118d459b6ff5939df88cba9fd77e3373bc59`。本轮是用户明确要求的三级测试尝试，结论为未通关、未完成三级验收。一级与二级未单独执行。未修改 Core、内容、判题、认知前提或行动费用，也未运行流程回归。

正式游戏确实使用 DV 核心。`godot_csharp/DualOntologyWorldEngine.csproj` 引用 `language_core/Session/DuelView.Session.csproj`；正式 `Main.tscn → Main.gd → GameEngine → DvSession` 调用生成的 `F_dvg_open/prepare/complete`，移动仍由正式 WorldView 执行。构建输出的依赖清单只有现役 Session 依赖；游戏目录和本轮 Session 产出的 DLL 均为 SHA-256 `88bad15f92d056a476e96ff1adc6125b13c718cc9a52c7f1ccb018613d7d9de3`。逐文件生成来源指纹与当前 DV 源一致，详见 `core-preflight.json`。构建是接线与工程证据，不能替代游戏验收。

首次默认渲染启动发生原生 signal 11，保留 `godot.stderr.log`。受限环境兼容渲染启动没有取得可操作窗口；这些都不算游玩。之后使用正式 Godot 4.6.1 .NET、兼容渲染和 Dummy 音频，在屏幕外且不获取焦点的实例中渲染。停止桌面方案前，盲玩代理只查询过窗口，没有发送游戏键鼠输入；新方案只经 `Input.parse_input_event` 发送游戏内部事件，未使用系统键鼠。

所有有效运行均实际设置 `Engine.time_scale=4`，逐秒采样记录该值。它加速 Godot 物理、计时与呈现，异步 DV 计算不会因此快四倍；DV 游戏钟依据实际动作结算，不能按现实秒乘四换算。没有调整推理预算、游戏费用或预置答案。

现实秒从各实例创建 Main 后开始，包含标题等待与 Agent 看图、思考、工具往返。侦探组首次游戏快照约 4.052 秒，盲组约 36.226 秒；盲组还等待人工继续对白。两组速度差因此不能解释为推理效率差，不能用“前90秒游戏时间更多”评价侦探优于玩家。运行错开；盲组期间曾进行首轮记录解析与压缩，进一步限制性能比较。本轮只比较具体行为、反馈和最终停止位置，不做性能优劣结论。

初版 `detective-x4` 也独立跑了90秒，但继续对白过快，只保留为工程试运行。原始记录及 `capture-initial.gd.txt` 保留；补跑改为首次对白先等待、自动继续间隔至少1.5现实秒。没有把两轮拼成一局，也没有把呈现节奏变更当同条件提速。盲组不使用自动继续分支，补跑只改变侦探组对白阅读节奏。

盲玩代理是全新上下文，只获得启动方法、通用输入协议和自己的截图。它在未输入移动的情况下，先后看到角色出现在大厅和门旁，已明确将这些记为自动行动。106.378秒截图显示“查看门内的插闩和门外的横闩。”，继续后没有得到具体发现正文。E与直接点击没有打开检视菜单；D保持后释放，217.808秒截图位置仍未改变；R与Tab也没有打开相应内容。最终239.923秒截图仍为9:09门旁画面。完整独立记录见 `blind/independent-player-report.txt`。

关键节点依据设计要求的现场证据、正确推演、作答接受和实际章节交接分别判断。门边位置变化和这句检视行动表述只是辅助事件：本轮没有足够证据认定它完成了关键检视；未记录正确推演达成；正确作答被接受和实际章节交接均未在本窗口发生。不能给这些节点填零秒，也不能把门旁截图当第一章完成。

主代理核查源码发现当前 `GameEngine.Dispatch` 只处理 `start/view_ready/dv_next/dv_complete`，`DvSession.Prepare()` 没有玩家选动作参数；快照也始终是 `player_control:false`。因此当前正式宿主没有完成独立玩家动作接入。Enter可以正常开始并继续对白，原始输入流也记录了盲玩者其他按键与点击，但这些记录不等于世界接受了其调查意图。截图本身不足以定位原因；与源码合看，可以确认不能将本轮自动侦探轨迹包装成独立盲玩通关。

进一步核对发现，这些独立运行封存的完整 DV `session.json` 原字节 SHA-256 均为 `957a8846f4766de043d6dd6be82ca7209d2c4713f47881b2be7eca7f737fcc4a`：底层正式事件轨迹完全相同，界面输入流和现实阅读等待不同。这里没有用一次运行复制成另一轮；各轮从新的 Main 与 OpenCampaign 开始，独立关闭封存。这个结果进一步说明盲玩输入没有改变本轮 DV 行动轨迹，不能作为两套独立决策策略的速度比较。

正式会话原始 trace 报告 `no-admissible-action-or-budget`。这是会话合并停止原因，不能据此断言只是预算不足或只是没有候选。停滞后未显示给玩家可执行的恢复路径或明确结束说明。另有“未命名物品”的可见对象记录，以及侦探组退出时 ObjectDB/resource 残留诊断，均保留，不以退出码或构建结果掩盖。

独立公开证据审查者未读取设计、源码、存档或私有规划。其实际查看盲组106.378、156.377、181.524、217.808、239.923秒截图，并补看侦探组40.317秒完整对白截图：两组提示一致、文字清晰；均没有检视发现、正确作答、交接或通关证据。人物行程不能归于盲玩者的自主选择。
