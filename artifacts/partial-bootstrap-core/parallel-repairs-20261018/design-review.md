# 附件核实与设计边界（2026-10-18）

来源：本轮用户附件 pasted-text-1.txt；现役源码与 docs/design-standard.md。附件分析是待核实的意见，不作为既有实现或设计的证明。此前未跟踪的 artifacts、报告与测试输出保留，不纳入本轮修改。

## 主代理设计核对

- 设计规范第五部分的章末是第五日07:30–09:30的议事，议事结束后落幕。7200是现有工程时域，不是剧情完成条件。新增第五日下午休整目标不属于修复既有接线；本轮不以空等待补齐时域。
- 第二章人物各自的动机、技能、时间机会及目标可以在原生内容中声明。按人物声明内容不自动等于引擎硬编码；应分别核对共同资格、本人认识、真实执行和后果。附件提出的完全沙盒化不属于现行设计要求。
- 现有第二章扩展保留原主体剩余行动配额；planning_limit已经是每次搜索的上限，而非附件假定的五日累计320次。不能据附件假设补充预算。
- 室内关门、闭窗、隔离与震后缝隙渗入有定性设计依据，但没有每个房间的初始门窗状态、震后实际破损及渗漏发生条件。源码保持这些输入未知；c2_room_actions为空，close_room构造器未接入，shelter/seepage虽有enforce采纳但没有完整生产输入链。不能把这条链宣称已实现，亦不能自行将未知改成安全或危险。
- 真话合同、共鸣估值与侵蚀记忆裁切有对应机制，但静态存在不代表所有发言、取回和侵蚀分支已在本轮正式会话发生。附件“高度符合”“严密落地”结论需要按实际证据缩小范围。

## 附件建议的实施原则

失败去重使用本人相关输入，失败观察使用显式现场授权，不从客观拒绝条件读取未知答案。等待修复读取本人声明窗口，不读取他人私有目标。保留完整事件快照与精确序列化；缩小证据不是性能修复。独立审计保留自己的重算路径，避免让判定直接调用被判定算法。

本轮先集中完成修改、工程排错与静态审读，随后冻结源码，执行一次最多180现实秒的一级formal-model会话。任何停止、超时、未覆盖分支与证据不完整分别记录；不启动Godot，不执行流程回归。

## 本轮追加授权与落地边界

用户答复“自行根据实际剧情，设计第二章收尾”。主代理据此在设计规范第五部分原流程表及新增3.1中明确：全签才构成完整公约；6330窗口截止只闭会，保留缺签与未决；闭会后低鸣/余震持续于收尾现场，人物通过真实现场检视取得，不能把历史标记冒称瞬时听闻。闭会的系统摘要读取真实状态，不进入任何主体认识；不新造午夜休整、不加配额。室内初态与渗漏输入仍未知，未扩展为新房间剧情。

工程落地包括closed/ended分离、独立环境信号、两会场真实检视、成功签名后的本人观察、逐段本人已知路线与只读摘要。宿主snapshot提供摘要字段，正式调试停止记录也带摘要；本轮没有实现或验收Godot章末结算卡的具体渲染。新增设计与实现身份分列，实际覆盖以新会话证据为准。
