# DV 接线与内容审查进度

本轮尚未完成第一、二章迁移，也未替换游戏宿主的旧 Core。当前 DV 第一章仍是独立逻辑会话，不能称为完整章节或 Godot 游戏验收。旧 Core 和旧剧情仍有现役引用，因此尚未执行最终删除。

## 已改动的机制

- 编译器增加不执行内容的检查入口，按编译组解析多个文件，保留各自的 define 作用域和错误位置。
- Visual Studio 2022 客户端通过公共 LSP 服务检查未保存编辑；Godot 插件通过同一编译器检查保存的 DV 文件。客户端不另写语言语义。
- 开场话语不再通过 public_grants 把隐藏事实重复写成亲眼观察；听者沿实际聆听、证言、理解和接纳链取得内容。发言执行同时核对发言者本人的字面支持。
- 章节问题名与进度字段从 session 移到内容声明。
- 推演按本人已采纳法则中的位置条件建立分派索引。候选输出仍全部遮蔽，索引输入和被排除条件写入轨迹，分派及实际预测分别计费。无法建立索引时展开原始规则组。
- 本人字段引用比较解析省略的主体标记，显式属于另一个主体的引用仍不相等；来源核验、论证来源和只读核对器采用同一引用含义。
- 重复推知以法则和输出字段替换旧来源，不再把新事件编号当作独立依据。支持份额与来源可靠度分开，置信度不超过所选内容最强来源的可靠度。
- 第一章候选排除声明补入普通推知法则版本。证书仍须重放实际推知并追溯本人的观察回执，没有预置被排除的候选。

## 阻止替换的实际缺口

1. 第一章尚缺完整醒来、相遇、报偿核验、反证后的维护行为、收尾和章节交接。现有三个同伴的专业回复不等于完整剧情。
2. `c1_touch_recall` 仍在一次触物行动中直接取得回忆，尚未表达设计中的闪回、是否继续握住、代价知情和实际取回结算。请求回忆的动作也不能代替同伴真正作出选择与发言。
3. 第二章尚无原生 DV 完整实现；分批相识、物资消耗、个人规则采纳及执行、夜间风险、名录库协作和公约交接均不能用静态状态或摘要替代。
4. 正式 DV 会话仍缺面向游戏宿主的行动准备、现场执行、完成回执与连续保存接口。尚未接入真实输入、碰撞、地图和 UI。
5. 语言方案中的完整能力类型、单位推导、通用证明和目标无关 IR 尚未实现。当前检查器的工程可用性不能代表这些语言特性已经完成。

因此，本轮只能确认上述具体工程修正和会话中实际发生的行为，不能签署“全部剧情与知识使用正确”。未进行本轮一级完整剧情/UI 回放、二级游戏 UI 验收或三级游戏本体验收；Godot 插件渲染验证单独记录。
