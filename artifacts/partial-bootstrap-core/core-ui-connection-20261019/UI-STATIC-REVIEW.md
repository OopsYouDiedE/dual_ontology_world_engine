# Core UI 接线独立静态审查

2026-10-19。仅审读Main、GameEngine/Measurement、Session、DvFieldExecutor、WorldView、CampusMapView及对应DV宿主投影、必要UI/Actor消费者；未读取设计文档，未构建、启动、探针、会话或恢复。源码仍由其他代理收尾，本报告对应UI-STATIC-REVIEW-HASHES.json所记录的读取版本。代码事实不等同运行证据。

## 应处理的问题

### P1：保存/恢复未覆盖现场在途阶段

GameEngine.cs:165 RequireIdle只检查busy/maintenance/closing；:178 Restore同样不检查pendingEvent，:203/:225的异步版本仅等待work。Prepare完成并发送dv_action后，DrainCommands任务已经结束，busy=false；Main/DvFieldExecutor此时可能仍在真实走路，而pendingEvent非空。由此Save/SaveAsync可以在现场仍执行时返回，Restore/RestoreAsync可以立即InstallRestored（:191），清空pendingEvent与commands。

旧Main._dv_intent和执行器并不会随这个替换取消。几何结束后Main仍发送旧dv_complete；C#因无pending报告错误并丢弃，Main已经清空_intent，也没有dv_present带来的自动dv_next。若在既有UI继续恢复，还没有状态/view事件重建保留实体，旧地图身体和新DV地点可能不一致。

建议将保存/恢复公开边界明确约束到现场回执之后；可以拒绝pendingEvent非空的持久化请求，或建立同时等待现场Complete的屏障。恢复还需独立的宿主视图/实体重建协议。这里不能只把await work描述为“等待所有在途行动”。关闭有不同语义：Main主动中断现场后封存pending状态，可以如实保留，但不应将其说成动作完成。

### P2：地图门禁快照仍存在生产/消费者字段不匹配

CampusMapView.gd:31只读取snapshot.access.maps，:38缺键默认true。entry.dv:dvg_snapshot当前输出的access只有dorms/isolation_open/door_prints，没有maps；因此_access保持空表，_refresh_access_geometry不能从这个投影获得封门状态，所有地图键均可进入。正式DV资格仍负责限制所选动作，所以这不是已证明剧情越权；它是确定未完成的物理门禁接线。应补有来源的maps投影，或明确保留为未接通范围，不宣称隔离门状态已经进入真实碰撞。

## 审查中已修订的问题

初读Main.gd的quit分支先同步begin_shutdown再await shutdown_completed。标题页尚无会话时，GameEngine.CloseTrace的await work同步完成，缺session错误可在同一调用栈finally发出TraceClosed，Main开始等待时信号已错过，导致退出永久等待。已及时通知主代理；复读Main.gd:113现为begin_shutdown.call_deferred再await，和WM_CLOSE分支一致，静态消除了这个具体丢信号顺序。未实机验证关闭。

初读Main仅move进入现场，其余动作直接Complete；复读Main.gd:229已将存在travel.station的非move动作也交执行器，entry.dv:dvg_intent同步提供destination。这样显式现场接触不再由宿主先行假定成功。E类站点缺几何时仍将blocked，资产补齐在本轮之外；这会限制可用游玩范围，应在最终报告明示。

## 正式动作、异步与回执的静态接线

GameEngine把输入序列化后入commands，StartPump以busy/maintenance/closing/faulted守卫启动单一DrainCommands；每次DV转换与其观察者快照、执行主体快照在同一后台任务串行生成。EventsReady重入只入队，当前泵继续消费，未见恢复原busy丢输入路径。Snapshot与Measurement只读已完成snapshotJson缓存，不在Godot主线程遍历工作线程拥有的DV状态。发生转换/投影错误后faulted停止继续Prepare，避免把可能已提交的变换盲目重试。

pendingEvent非空时忽略下一步准备，重复dv_complete由completedEvents去重；匹配待办后才调用唯一Session.Complete。Main._field_input不提交回执，执行器先连接field_event再启动execute_move，收集同serial/who/action的daily结果，await返回后Main才做唯一_dv_complete。Main先清_intent再deferred提交，普通现场信号没有第二结算路径。执行器还核对目的地图、房间和显式站点及arrival_error；失败返回blocked并交拒绝回执，未发现formal-model几何替代。

Main事件队列以_draining串行等待现场动作与对白。玩家awaiting_input展示候选，由现有UISystem._select发select进入同一GameEngine.Prepare；AI只以HostOpen的controller设置空player_actor，仍由正式DV自主选择，没有宿主动作评分。profile/zone/seed/viewer均是开局选项。Session的HostOpen/HostViewer是生成DV函数边界，Session本身没有新增决策机制。

SaveAsync/RestoreAsync的Task.Yield避免在重入调用中把维护任务同步设成自身前驱；但这只能说明DV任务层的序列化，不能解决上面的现场在途缺口。同步Restore的Task.Run(...).GetAwaiter().GetResult()会阻塞Godot主线程直到恢复和快照完成，不是异步API；目前未见工作线程回调Godot主线程造成必然死锁，但恢复成本与画面卡顿未经测量。

## 实体、地图、相机与资源边界

DvFieldExecutor按actor保留唯一身体记录，首次物化核对声明map/执行room、walkable与占位距离，已有身体不按快照直接重定位。换图前保留NPC身体、转移执行主体到新地图Objects、写入实际from/to终点；异地执行采用同一WorldView、Campus适配器、StoryActor follower和地图墙体。地图出口仅在本轮_route_target_next目标匹配时触发，valid_transition核对资源、命名出生点或连续室外接缝和边界。缺绑定、资源或身体会blocked，不构造替代逻辑到达。

相机为WorldView根的Camera2D，由_physics_process跟随player.position；可见视图采用已有camera_limits与平滑。隐藏执行场地在独立SubViewport/World2D内创建，相机disabled，Sight与Hint隐藏、普通_process关闭，而_physics_process保留以推动适配器和daily到达检测。没有发现隐藏相机抢占可见Viewport相机的静态路径。对身体真实终点、相机画面、遮挡和帧呈现没有实视证据，不能据此宣布二级UI验收。

明确保留的物理范围：WorldView.create_body在StoryActor加入树后将collision_mask设为1，而人物collision_layer为2，所以人物不互相阻挡；_worlds[who]给每个异地执行主体独立World2D，execution_only也不生成其他人物。墙体/地图几何碰撞仍执行，人物间占位、互阻和群体碰撞不在这个协议里。主代理明确本轮保留此旧策略，不扩人物互阻规则。不能把“同一地图代码”扩写成所有人物处于同一物理世界，亦不能称完整现场或三级验收。

另一个范围限制：初始物化候选来自initial_placements/spawn/stands/Spawns，尚未读取person.anchor；entry.dv某些地点带anchor。当前有合法同room站点时仍可物化，但这不等于特定床/道具锚点已被采用。若需要指定开局精确站位，须消费anchor并验证，而不能以退回同房间站点代称锚点完成。
