# Gemini 建议核对与 DV Core 计时（2026-10-17）

## 范围与来源

核对用户粘贴的 Gemini 建议、当前 `language_core` 源码和本轮两次全新无窗口 formal-model 会话。两次均使用 `run_debug.py --profile`，同一入口、GC 配置和剧情源码；第二次只改变 `dvs_capture_heard_utterances` 的事件查找算法及分析器工作类型标签。第一次运行前已实施记录兄弟分支共享和快照池渐进清理，因此两轮比较只隔离收闻扫描这一项。原始源码指纹、构建日志、stdout/stderr、完整 trace、事件投影和玩家可见正文分别保留在 `level1-profile-01/` 与 `level1-profile-02/`，不覆盖。

分析器在诊断生成的每个 DV 函数入口计时，用调用栈扣除子函数时间。`profile-raw.json` 保留计数器；`profile-summary.json` 保留各函数和工作类型的调用次数、独占与包含总耗时、每次调用均值和独占占比。工作类型是函数名分类，平台 ABI 时间归属直接调用它的 DV 函数。该插桩增加大量微函数调用开销，分布和总时长仅适用于诊断构建；不是未插桩 CPU 采样、Godot 帧耗时或实机性能。`level1-profile-01/profile-summary-worktypes-v2.json` 用同一分类规则重算第一轮原始计数，原始文件未改。

`EVIDENCE.sha256` 记录两轮关键原始输出的逐字节指纹；完整 trace 各约 1.29 GB，保留在本地证据目录。版本库仅提交紧凑计时数据、结果、指纹与后一轮 stdout，避免把两份巨型 trace 当作源码提交。

## 建议裁定与改动

| 建议 | 裁定与处理 |
| --- | --- |
| `dv_with_many` / `dv_with_path` 深拷贝未变兄弟分支 | 成立。未变分支改为 `rt_snapshot`，更新路径与新值仍独立复制；Runtime 的可变父节点读时实体化保留隔离。 |
| 快照池每 1024 次全表清理 | 成立。改为按桶轮转清理，仍在访问桶时清除失效弱引用并逐项核对结构等价。 |
| `ReadItem` 与 `dv_read` 全面取消读时复制 | 不能直接采用。当前 `rt_copy_value` 与可变父节点读时实体化是独立副本合同；直接返回可变子值或冻结值会改变允许写入的路径和别名行为。 |
| 用 64 位结构哈希直接替代规划 JSON 键 | 不能直接采用。哈希可能碰撞，当前键还含达成及机会信息；去重必须保留完整等价判定。诊断后 `dvp_state_key` 约占 1.1% 独占时间，Gemini 的 60–75% 提速数字无本轮依据。 |
| 三次 `dv_predict` 合一 | 当前调用有条件分支，且预测事件编号用于来源回执；直接共用一个结果会改变证据来源。暂未修改。 |
| 话语预测按版本短路、推理脏引用 | 话语预选已按语义签名缓存有效预测；推理签名还覆盖前提和输出。笼统版本号不足以替代这些条件。暂未修改。 |
| 离场目标、折返、重演与四问剧情推断 | 文中引用旧轮次与旧 48 步窗口；当前会话已经使用行动队列和不同运行范围。仅凭该历史推断不能改内容门槛、预算或角色动机；本轮保留设计规范与现行内容。 |

分析器还定位到建议未提及的实际热点：`dvs_capture_heard_utterances` 每次遍历事件时，又为每条 `listener_parse` 扫描全部事件。现改为先索引 `speech_literal`，再按原顺序处理 `listener_parse`，保留来源、父链、说话者及同一来源后续收闻覆盖规则。无人物状态缓存，也不预置收闻。

## 后续诊断线索

第二轮仍有较大的 `dv_get` 与 `dvs_support_parents` 时间。前者需用低开销采样或局部 ABI 计时排除插桩影响；后者按引用重复扫描事件，适合另行审查来源索引与完整证据合同。本轮没有据此改动答案、规划预算、角色目的或内容前提。
