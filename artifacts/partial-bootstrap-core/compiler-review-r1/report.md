# DV 编译器独立工程审查 r1

审查对象为 `compiler-r1/c3` 封存编译器及其 Runtime；没有读取 DESIGN.md、设计规范或其他设计文件，没有运行游戏或流程回归。仅写入本审查目录，没有修改实现或提交。脚本 `review.py` 保留所有样例、生成源码、构建及运行的原始输出；命令与退出状态见 `commands.json`。它只允许新增样例目录，不可覆盖后直接重跑。

## 结论

这是能编译自身实现子集的真实源码编译器，不是把解释器包装为可执行文件。DV 实现解析、名称/参数数量检查和 C# 输出；C3 的程序体是直接的 C# 函数、调用、条件、赋值与循环，R.Block 是执行委托而非 AST 求值。Runtime 只提供值/平台操作，没有 reader、解释器或代码生成器。独立读取 C2/C3 源码确认字节相同；没有独立重建整个 C0 链，因此原完整链执行仍引用 compiler-r1 的原始记录。固定点说明此输入的确定输出稳定，不证明完整语言、类型安全或语义正确。

当前只有动态 object 值的过程式 S 表达式子集：defn/main、if、let、set、while、do、固定原语、普通命名函数。AST 是带标签列表，所谓 IR 直接是 C# 表达式字符串。不存在独立类型化 IR、静态类型检查或能力检查。不能据此宣称 AGENTS 所列完整编译器目标已达成，也不能证明旧 Core 对齐、现役宿主接入或游戏改善。

## 具体缺陷

**字符串目标编码缺陷。** `unicode_line_separator/input.dv` 的字符串包含原始 U+2028。C3 生成返回 0，但目标构建报 CS1010“常量中有换行符”。审查时的 scan_string 仅拒绝小于 32 的原始控制字符，emit 将字符串源码直接粘贴进 C#，没有目标语言编码层。该例是编译器接受的输入导致非法目标源码；对应源码、生成物、构建原始输出均保留。应在 DV 后端安全编码目标字符串，或在前端明确拒绝无法支持的字符，不能以目标构建报错充当 DV 诊断。

**静态检查边界缺失。** `bad_type` 的 `(rt_add "text" 2)` 和 `bad_condition` 的 `(if 1 ...)` 均生成并构建成功，执行才分别报 `Expected finite Number`、`Expected Bool`。`dead_bad_type` 将相同错误置于 false 分支后直接打印 `ok`，说明不是完整静态类型检查。该项是目标能力缺口；若明确声明动态子集，不能反过来称动态语义有误。

## 实际输入与结果

- `source_a` 与 `source_b` 将操作数从 25 改为 26，独立编译运行结果从 42 改为 43，排除固定结果样例包装。
- `strings` 输出实际引号、反斜杠、换行、制表符及“中”，通常转义路径有效；原始 Unicode 行分隔符是另行复现的失败路径。
- `forward_recursion` 使用前向函数引用与互相递归计算 odd(9)，实际打印 true。
- `scope_siblings` 的两个不同 let 域可分别绑定 x，实际打印 7 与 9；`scope_sequential` 的后续绑定读取前一个绑定，打印 9。
- `scope_leak` 在 let 外读取 x，被 DV 以 unbound local 拒绝。重复局部、嵌套遮蔽、重复参数均以 reserved, duplicate or shadowed local 拒绝；这是当前禁止遮蔽的限制，未将其判断为设计错误。
- 非法实参数量、未知函数、未闭合列表、非法转义均在 DV 阶段被拒绝；名称/调用错误通常带 UTF-16 offset，未闭合列表和非法转义没有位置。
- `unsupported_lambda` 被明确拒绝；不能把当前子集描述为支持原语言所有执行语法。

## 证据边界

`sources-before.json`、`sources-after.json`、`integrity.json` 记录本轮开始与结束的源文件/C3 源码/程序集指纹相同。之后实现可能已修复；本报告只针对保留的 compiler-r1/C3，不评价后续修改。原始输出使用局部 .gitattributes 保留字节。没有验证资源耗尽、非终止程序、全部数字边界、所有 Unicode 边界、能力隔离、其他目标后端、完整推演模块编译或 C0 reader 与 DV reader 的全部一致性。

验收级别：仅编译器工程与机制审查。一级、二级、三级游戏验收均未执行，未验证剧情、人物或游玩体验。
