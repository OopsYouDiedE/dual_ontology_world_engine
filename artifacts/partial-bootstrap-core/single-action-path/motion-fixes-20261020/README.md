`ui-baseline-2` 与 `ui-candidate-1/2` 使用实际组件、普通输入和既有对白片段。最后一次 `ui-candidate-2` 于 14.740 秒正常结束，源码前后指纹不变，日志中无脚本错误。实际查看其设置、手账和地图截图：弹窗位于前景，正文、关闭按钮及中文可读，底层对白被正确遮罩。

记录显示：基线中设置层低于标题，设置下的 Space 会推进对白；候选设置位于正确层级，弹窗期间对白行号保持不变。候选支持设置快速关闭再打开、设置到调查的串行切换、替换提示保留当前内容及空对白等待正常完成。独立 50 ms 中点记录在 1 倍和 4 倍游戏速度下分别得到约 0.703704 与 0.703637 的相同过渡进度；截图编码耗时不计为动画时长证据。

## 正式游戏记录与未覆盖范围

已有两次原版本的独立 90 秒、四倍速、审计模式会话，动作由引擎 AI 决定，采集器只发送普通开始/继续输入。两个原版本窗口分别记录绘制间隔 p95 41.433/42.582 ms、p99 92.190/93.278 ms，最长 2.660/2.801 秒；这些是基线事实，不能推断修复后的数据。软件 llvmpipe 环境也不代表玩家实际 GPU。

基线记录包含侦探两段和霍铎一段实际移动，以及两个实际被接受的回答；窗口结束仍在第一章，没有发生章节交接。第二次基线的 actor 数据声明 79,656 行，实际文件只有 69,632 行，尾部缺少 10,024 行，约 79.526 秒后的关联位置记录不足；其他主要采样流分别核对范围。关闭返回完成并不能证明所有证据完整。原文件、残留 partial 和审查发现均保留。Space 按下被对白处理，主机可见输入记录仅含抬起边缘，采集器另保留普通 tap 区间；不宣称单一主机流完整覆盖所有按键边缘。

候选版本未执行新的正式 90 秒游戏窗口。因此跨图准备、后台 NPC 与观察者重新绑定，以及 Core 数据交接的整局改善目前具有源码、构建和组件依据，尚无同条件正式游戏性能对照。地图实例化和基础网格创建仍有主线程工作，约 2 ms 切片预算只覆盖候选索引处理；没有把所有地图准备宣称为严格 2 ms 内完成。
