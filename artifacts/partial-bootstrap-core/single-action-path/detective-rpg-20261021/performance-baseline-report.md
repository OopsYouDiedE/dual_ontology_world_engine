# 引擎侦探 90 秒性能诊断（2026-10-21）

本轮实测最显著的持续主线程阶段是逐帧可见记录：12,369 次共 17.049 秒墙钟；其次是本轮采集器的 445 次 GPU 回读，共 7.624 秒。正式 DV Prepare 合计 5.293 秒，Complete 合计 0.717 秒。阅读与这些后台工作发生重叠，不能相加推导总耗时，更不能把阅读时间当作 CPU 耗时。

## 实际执行与身份

- 隔离根：`tmp/detective-rpg-runtime-20261021`。主代理提供独立 Git 元数据、实际源码/资源和重建成功的运行程序集。运行命令来自该隔离根自己的脚本，未修改隔离源码。
- 采集：`perf-ai-90s-x4-01`；PID 23092；引擎侦探、离屏真实渲染、四倍播放、90 现实秒、完整来源审计、5 Hz PNG；托管线程时间采样请求 80 秒，原生/GPU 分析关闭。
- 实际采集截止 90,002 ms；首个游戏钟记录在 2,753 ms，为 08:00；截止游戏钟 09:56，实际推进 116 分钟。并非由倍率换算。
- 启动器耗时 95.203 秒；采集关闭时刻 91,893 ms，较截止额外 1.891 秒。启动器还包含启动、采样连接、报告及复制证据。
- 采样连接发现进程耗时 1.578 秒；开始之前与采样结束之后均有覆盖缺口，不能外推整段 CPU。
- 来源前后复核差异为空；脚本指纹只覆盖 tracked 文件与已发现 DLL，主代理的完整隔离快照承担未跟踪实际依赖的封存责任。
- 唯一新增并复制的宿主目录是 `20261021-055320-5338`。游戏、采样进程退出码均为 0，无 Godot 错误行，托管报告可读。
- 结束后发现旧 PID 26276 是另一 Godot 编辑器。采样期未连续记录其活动，不能保证无资源争用；未结束用户进程。

## 具体热点与后续取舍

1. `Main.gd` 的 `PlayerViewTraceInner._after_draw` / `_collect_after_draw` 在每个实际绘制帧递归 `_scan`，对 Control 调用 `_wire`、文本提取与 `_context`，另建立可见对象数组；完成全部扫描后才比较 `_last_data` 去重。实测该完整阶段 17.049 秒，是明确的持续工作候选。任何后续优化必须保留逐帧首次可见正文、输入上下文和遮挡来源，不能仅降低采样频率来冒充同条件加速。
2. `dv_level3_capture.gd` 的 viewport `get_image()` 和 `get_data()` 属证据采集成本。实测分别 7.624 秒和 1.894 秒；这不是普通游戏自身逐帧 GPU 回读路径。采集与无采集窗口不能作同条件速度结论。
3. 正式计算主要位于 `30-session.dv` 选择与认知：choice 2.384 秒、cognition 1.826 秒。侦探认知占主体认知阶段一半左右；尚未获得 DV 函数粒度 CPU 证据，不能指定更深函数为根因。
4. `Session.cs` 的 Snapshot 投影 0.894 秒，编码 0.116 秒；`GameEngine.cs` 物化 0.168 秒。本轮数据不支持把 JSON 编码或宿主入队等待作为首要瓶颈。
5. `CampusMapView.gd` 的动态 AStarGrid 重建、房间候选排序是静态候选，但本轮没有原生脚本 CPU 分析，且现场段包含正常移动/异步等待；不能据此宣称寻路是本轮热点。

托管 topN 中等待类栈独占占比分别为 42.39%（LowLevelLifoSemaphore.WaitForSignal）、15.33%（WaitOneNoCheck）及 6.38%（GetQueuedCompletionStatus）。具体非等待候选包括 Godot variant 销毁 8.53%、dictionary 销毁 3.96%、ptrcall 3.21%、Memmove 3.04%。这是 sampled-thread-time 的栈占比，包含线程等待且有未解析符号，不能转换成 CPU 利用率，也不能直接归因到某个 GDScript 函数。

## 卡顿、阅读与封存边界

`frame_post_draw` 间隔达到 50 ms 的记录有七段，共 495.958 ms，均位于启动阶段 1.749–4.015 秒。最大 123.945 ms 与初始 view_build 重叠；另外几段与截图回读/复制重叠。该重叠分析不是因果证明。后续已记录窗口未再出现达到该阈值的绘制间隔，不代表不存在更短抖动。

正文阅读 40 段合计 78.257 秒；采集协议每隔 1.5 现实秒按一次 Space 保留并继续普通对白，未选择世界行动。阅读期允许正式后台 NPC 行动，所以阅读、现场执行、DV 阶段不能合并成互斥耗时饼图。输入门状态、等待回执及物理作业记录保留于原始计时，不能把正常阅读/走路都标为卡顿。

`capture-close.dvlog` 的归档错误为空；宿主 `close-result.dvlog` 为 `complete=true`、`audit_mode=true`、`unprocessed_commands=0`、`errors=[]`，但保存了真实 `pending_action=action156`。截止仍有一个未闭合 execution_begin；它属于窗口停止时在途行动，不能补造成功回执。本轮没有证明剧情完成、章节交接或整局体验达成。

离线 `summarize_interaction_timing.py` 产物没有 interactions，因为引擎侦探本轮 interaction_id 为空；它不能替代 command_id 分析。本轮另用 `analyze_performance.py` 配对工作阶段并生成 `phase-summary.dvlog`。`run/live-timing.dvlog` 在截止前最后刷新，完整宿主记录覆盖关闭所收集的计时；两者尾部边界不同。

原始证据在 `perf-ai-90s-x4-01/`：`run/*.dvlog`、`host-session/*.dvlog`、`session.dvdag`、`save.dvsave`、`managed.nettrace`、PNG 与原始控制台日志。派生结果为 `hitches.dvlog`、`interaction-summary.dvlog` 和 `phase-summary.dvlog`。未开展第二版本测量，不能宣布性能改善。
