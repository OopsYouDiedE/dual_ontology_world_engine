`Main.gd` 的 `PlayerViewTraceInner._collect_after_draw` 每帧仍递归 `_scan`、读取原生控件正文、绑定输入上下文并构造可见对象列表，随后才去重；本轮为 13.961 秒墙钟，仍是持续主线程工作候选。整合版已把 `_context()` 结果传给递归扫描，实测差异不能脱离控制/规划变化解释为同条件加速。截图 `get_image` 的 8.770 秒属于采集 GPU 回读，不是普通游戏自带的逐帧回读。选择阶段 3.532 秒，比认知 1.107 秒更突出；JSON 与物化合计约 0.248 秒，本轮不支持将其列为首要瓶颈。

后台归档的 445 张 PNG 编码合计 11.933 秒（中位 20.323 ms、最大 285.518 ms）；排队合计 1.312 秒，写盘 1.262 秒，哈希/通知 1.265 秒。这些工作不等于主线程阻塞。现场执行 11.320 秒包含真实移动和异步等待，不是纯物理 CPU；阅读 71.448 秒含 UI 打字/继续协议，并与正式后台 NPC 行动重叠，末尾还有未闭合正文阅读。

托管 sampled-thread-time 最大独占占比为线程池信号等待 44.13%、WaitOne 等待 16.66%；具体非等待栈为 Godot variant 销毁 12.28%、原生 ptrcall 4.42%、Memmove 2.69%。线程时间样本包含等待，不能称 CPU 利用率或把这些占比直接归于某个 GDScript 函数。

`hitches.dvlog` 记录九个 ≥50 ms 的实际绘制间隔。六段在开局 1.785—4.095 秒，最大 124.832 ms，与初始 view_build 重叠。其余在 15.778 秒（65.111 ms）、46.443 秒（61.196 ms）、87.616 秒（53.562 ms）；分别与 Complete/交付、截图 metadata、调度等有重叠。重叠不是因果证明，未知残差保留。正常阅读与走路不标为卡顿。
