# 生活翼同层合图与房间等待诊断（2026-10-20）

用户范围：仅合并建筑内同层地图，室外分区不合并。真实入口独立盲测的首要目标是查明进出房间卡顿与无说明的强制等待，不以通关为目标。

## 改动

- 四寝区及公共起居厅组合为 `living_floor`；原场景、纹理、法线保留为生成输入。共享门列对齐，公共厅中段增加六格以避免原局部底图相互重叠。物件、碰撞、标记和灯光同步变换；寝区内部尺寸、原站点半径和到达误差不放宽。
- DV 宿主绑定统一执行地图，保留逻辑地点和原执行房间标识。四区隔离门成为同图双向物理屏障，由原 DV 放行条件控制；不开启额外观察或传送。
- 真实 Main、渲染、物理与普通视口输入在离屏不可聚焦窗口运行；截图操作者不占桌面焦点，不用 headless 逻辑输出冒充游戏。瞬时输入包先写 pending 再原子改名，消费记录保存为二进制。
- 修复采样器参数与实际运行进程号：Windows 控制台程序是启动包装器，改采实际 Godot 进程；当前 dotnet-trace 使用 managed thread-time profile，其占比包括等待，不能当 CPU 利用率。自动启动直接触发正式 start，避免标题过渡期间过早 Enter 被忽略。
- 新增 `input_gate_state`，只在状态变化时记录对白/UI、提交锁、后台现场执行、在途动作、物理任务和队列等，用于解释等待，不改调度规则。

采样有开销：893 次截图的读回、像素复制排队、元数据分别累计约 16.735/3.338/0.988 秒；可见内容扫描累计约 26.402 秒。不能据此相加推算普通游玩性能。托管栈采样主要包含等待和 Godot 数据操作，不足以独立判定实际卡顿根因。

关闭报告 complete=true，无未处理命令、在途动作或截图归档错误，分析无未闭合阶段。审查未自行核验完整 session DAG，因此不额外担保全部来源快照。

## 已确认的门槛错误与修复

第三次移动的正式回执为 rejected，原因 `retained_body_room_mismatch`，真实身体位于 `(2416,973.833801269531)`；玩家画面没有说明，原行动费用仍按正式回执结算，游戏时间到 8:06。

几何探针单独复现：该点为 D 门槛，按房间几何属于 `zone_yi:north_1`，且不在任何原膨胀障碍矩形内；但所在 16px 导航格的中心落入邻墙，因此旧 departure_room 返回空。普通 WASD 的真实碰撞允许连续脚点到此，导航格中心不应抹掉这个真实出发身份。

修复只让门槛的出发身份按连续脚点与原膨胀障碍核对。原点修复后返回 `zone_yi:north_1`，导航格仍 solid=true；没有放宽导航网格、障碍膨胀、目标到达、站点半径、真实碰撞或 DV 费用。此工程几何复现与后续新会话实测分别报告。

另外，进入 R05 的现有目的地带 `anchor=site:bed`，执行器先真实走到该锚点，再选择房间终点；这是视觉上已跨门后仍可能继续自动行走的源码路径。本轮没有修改此目的地或主体调度，也不以删去这些步骤冒充同条件提速。
