# 独立证据审查

审查范围仅限本目录中的运行记录、摘要、输入/可见文本记录、截图、归档时序与停顿记录；未读取项目源码、设计文档或历史材料。PNG 仅作关键帧抽查，没有解码整批图片或遍历 session/save。

## 运行配置与实际移动

`host-session/inputs.jsonl` 首条记录给出 `controller=player`、`physics_ticks_per_second=240`、`max_physics_steps_per_frame=32`、`playback_speed=4.0`。`launch.json` 的命令也使用 `--mode=player`、`--seconds=240.0`、`--dv-speed=4.0`；`result.json` 记录捕获终点 240035 ms，游戏时钟从 8:00 到 8:10。`host-session/close-result.json` 记录 `complete=true`、无关闭错误、无未处理命令。

按 `input-events.jsonl`、操作者记录及抽看的 PNG，角色确实从 05 号房间进入 06 号房间，经上方门进入横向走廊，再进入 08 号房间并回到走廊。05/06/08 房间与走廊的范围变化在 `frame-000032097.png`、`frame-000082031.png`、`frame-000147290.png`、`frame-000202582.png` 和 `frame-000240003.png` 中可见；另查看了 08 房间桌边 `frame-000208642.png` 与点击后 `frame-000224626.png`。结束时仍在 `zone_yi:corridor`，`end.json` 显示仍等待玩家输入，且仅列出走廊到 R05–R08/活动厅的可选移动。未进入活动厅或其他区域；这属于本窗口未到达，不能推成不可达。

操作者记录了 08 号房间靠近书桌后按 E、再点击纸张坐标均无可见反馈。对应输入事件存在，抽看的前后 PNG 也未显示对话或新界面反馈；是否因距离、碰撞、热点映射或输入处理导致，证据无法区分。另有一次 06 房间内短按 D 60 ms 未出现在 `input-events.jsonl`，原因未知。05 房间第一次 S 150 ms 后画面未切房，继续 S 250 ms 才切换，表现为需要重新输入/延长按键，不能单凭截图判定具体阻塞环节。

## 可见对白与截图证据

`host-session/visible.jsonl` 有 38 条可见帧记录。抽查内容显示标题、时钟、附近物件提示（如床、风衣、书桌）和场景物件；未见通用过路对白或对话面板，操作者也未记录过路对白。因此本窗口没有观察到通用过路对白。可见文本是稀疏帧采样，结论只限于被记录和实际查看的片段，不能覆盖所有经过点或整个游戏。

`png-pixel-review.json` 只列出五张指定 PNG 的 `rgba_sha256_matches=true`。这说明该小样本与其被比较的 RGBA 哈希相符；文件没有说明独立比对实现或覆盖总体，不能据此声称全部截图完整。`run/archive-timing.jsonl` 有 930 条归档记录，抽查的关键帧均有记录且 `error=null`，并含捕获、编码、写入时间及 RGBA 哈希。关键抽查图片均能打开并与相应场景相符。完整逐帧可见性和未抽查 PNG 的像素正确性未审。

## 停顿与时间口径

`hitches.json` 将帧间隔定义为 `frame_post_draw` 回调间隔至少 50 ms、命令等待至少 100 ms；说明其分类为排他墙钟重叠，不是 CPU 时间，也不证明因果。记录中最大的帧间隔约 2021 ms，分解几乎全为 `unattributed_wall_time`；另有约 888 ms（含未归因时间）及约 858 ms（主要归为 `view_build`）的间隔。12 条 `slow_commands` 包含约 3311 ms 的启动和约 928 ms 的 `view_ready`；启动记录中还包含约 2582 ms `session_open`。这些时段会影响捕获期墙钟，但不能单独说明玩家经历了同样长度的可见卡顿。

计时口径应分开读：`result.json` 的捕获窗口是 240035 ms；`run/capture-close.json` 记归档与宿主关闭在 248427 ms；`result.json` 的 `launcher_elapsed_seconds` 为 252.172 秒，覆盖更宽的启动器生命周期。它们不是同一段墙钟量，不能把 252.172 秒直接当作游戏捕获时长。归档任务异步记录各帧的排队、捕获、编码、写入和结束时间；抽查末帧记录结束于约 240099 ms，晚于捕获终点，说明收尾/落盘延伸到捕获窗口之后。审查没有把主线程捕获、异步编码、宿主关闭和启动器总耗时相加或互相替代。

`gc-pauses.json` 存在 GC 事件记录，但本审查没有建立其时间戳与各帧间隔的一一对应。最大的若干间隔中有显著未归因墙钟时间；因此不能把 GC 暂停或规律性停顿未经匹配地断言为根因。当前材料支持“记录到长帧间隔及若干慢命令”，不支持给所有长间隔指定原因，也不支持据此作整体流畅度结论。

## 审查结论与限制

配置证据符合 240 Hz、32 步上限与四倍速。玩家实际完成了数个同层房间与走廊之间的移动；08 房间书桌附近的两种交互没有可见反馈，且一个短输入未记录。抽查范围内没有通用过路对白。截图归档有大量逐帧时序记录，但哈希复核仅覆盖五张；玩家可见文本记录为稀疏抽样。停顿数据把捕获与部分主线程分解开来，仍有大量未归因时间，GC 与停顿原因尚未匹配。上述结论限于本目录这次约 240 秒捕获及实际抽查内容。
