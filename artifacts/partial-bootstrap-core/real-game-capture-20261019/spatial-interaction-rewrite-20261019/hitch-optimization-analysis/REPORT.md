# 卡顿优化与四倍速独立盲玩

本轮执行了实际修改、工程排错和新的正式Godot渲染会话。Luna在全新上下文里自行读图、选择WASD/鼠标/交互输入；只接触本轮PNG与输入/采样索引，没有源码、设计、隐藏状态、旧路线或预置答案。主代理实际查看关键PNG，三个窗口分别由新的上下文只读审查。属于用户明确授权的三级独立盲玩局部窗口，不是两章通关验收；一级未运行，不执行流程回归，不用构建或关闭成功评价游戏体验。

## 实现与工程边界

- FrameArchive仅接收复制的RGBA8像素，在后台串行无损PNG编码并原子保存；主线程保留真实视口纹理读回，编码与写盘不再阻塞绘制。成功文件出现后追加frames索引，每张保留原像素SHA。最多八个未完成图像任务，饱和会明确记capture_backpressure；文本日志不静默丢弃。
- 采集日志、输入消费日志、现场元数据与在线时序也改成已序列化文本交给同一后台队列，保持追加次序。关闭持续处理PNG完成通知并排空通知追加的索引/日志，捕获终点与后台封存尾部分开。错误保留原字节、.partial和capture-close错误，不重试世界动作。
- 初次装图合并内容几何与门禁后的导航构建，初始字段快照只应用一次。通用房间目的地优先选具备四向16px转身空间的实际可走点；显式热点半径、身体碰撞、源/目标房间及回执判定不放宽。普通过门的通用surface移除，具有剧情来源的对白保持正式Complete后呈现。
- 四倍窗口显式speed=4，实际配置240Hz/32步；普通游戏默认仍为1倍。同房间行走仍不扣DV费用，不把四倍物理速度写成游戏钟或推演预算。按键释放使用现实毫秒截止时刻，并保存实际消费/释放时间。
- 自动附加.NET采样保留。Godot本地脚本/GPU控制台分析改为显式 --native-profiling full；日常测量默认off，仍有托管性能分析与被动帧/阶段插桩。完整分析旧窗口保留，不删除其开销数据。

中性归档探针在engineering-01/02保留已知RGBA、PNG及解码核对、已有文件不覆盖的错误与.partial；最终还核对文本first/second字节顺序。它不加载游戏、不推进DV。工程构建最初出现FileAccess同名引用冲突，修为System.IO.FileAccess；最终集中构建完成（29.93秒）。工程结果与下述实际行为分列。

01在5–60秒期间几乎逐秒出现300–400ms以上间隔，其阈值间隔累计20.289秒；02同区间0.767秒；03同区间0.114秒。该统计只累计被>=50ms阈值捕获的实际间隔，不等于可从游戏时长扣除的“浪费时间”，也不外推未测整局速度。01与02保持同一游戏程序集及托管采样，关闭脚本/GPU控制台分析后，原按秒复现的长停顿不再呈该模式。进一步将采集文本IO后台化后，03未重现02的约175ms日志/元数据阶段停顿。

Godot4.6.1的本地脚本分析器会按一秒周期收集、排序并打印脚本数据，这与本轮观察周期相近；实验只能定位到这组本地分析条件，尚未分别测定收集、排序、打印及GPU分析各自贡献。[对应官方源码](https://raw.githubusercontent.com/godotengine/godot/4.6.1-stable/core/debugger/local_debugger.cpp)。没有将关闭这组诊断工具称为“关闭所有性能分析器”。

## 最终窗口的组成与剩余长间隔

03主线程纹理读回中位19.249ms，像素复制入队中位4.925ms，元数据序列化/入队中位1.131ms，在线时序序列化/入队中位0.746ms。后台PNG编码中位17.340ms、写盘中位3.109ms；这是不同阶段的统计，不把中位数相加冒充某一帧或CPU时间。

最终最大绘制间隔仍为987.523ms，发生在3.728555–4.716078秒，互斥墙钟分配包含view_build 902.653ms、未归属28.373ms、纹理读回20.054ms、复制入队6.520ms，其余阶段29.923ms。首场景构建的约一秒停顿尚未消除，也尚未细分到所有资源/导航/UI子调用。5秒后的最大间隔63.471ms，后续仍有阈值间隔，不能称全程无卡顿。

GC原始暂停事件由只读GcPause分析器提取到各gc-pauses.json；其EventPipe时钟尚未与宿主每次间隔建立完整一一映射，不能把等待、GC、GPU或磁盘未经匹配地指定为未知段根因。所有残差与未闭合情况按原记录保留。
