# 独立只读审查：hitch-optimization-4x-02

审查范围仅限本目录中的 OPERATOR-NOTES、result/launch、host-session/close-result、inputs 与可见记录，以及 run 下的配置、hitches、archive-timing、input-events、capture-close、稀疏截图。未读取源码、设计文档、历史试玩或完整 save/session；未修改原始证据。审查时已读取同目录新生成的 `png-pixel-review.json`：它抽查首帧、四分之一、中间、四分之三和末帧共五张 PNG，五项 `rgba_sha256_matches` 均为 true。这只确认这五张抽样图与对应归档 RGBA 哈希相符，不能推广到全部 PNG，也不能证明帧级流畅或覆盖范围外画面。hitches 中的 background_archive 记录含 RGBA SHA-256；另有该抽样核对结果，二者覆盖范围均有限。

## 配置、输入与关闭

`run/input.json` 标明 `time_scale=4.0`、240 秒、玩家输入；`host_configuration` 记录 `playback_speed=4.0`、`physics_ticks_per_second=240`、`max_physics_steps_per_frame=32`。`launch.json` 同时记录 .NET CPU sampling 自动附加、目标采样 200 秒，最后一段未被采样；原生脚本分析请求为 off，GPU 分析状态未确认。因此这轮有 .NET 采样分析，不能描述成“无分析器”。

`input-events.jsonl` 有 39 条送达事件（含按键释放），覆盖启动点击、卧室和走廊 WASD、走廊 E 与两次点击。操作员记录的最后一个额外 S 100 ms 只在 `run/input.json` 中；送达事件流没有它，不能算已消费输入或用于解释末帧位置。结束存档仍为走廊、游戏时间 8:04，并有一个 `status=awaiting_input` 的行动待玩家选择；这是尚待继续的会话状态。`close-result.json` 报告 complete、零未处理命令、`pending_action` 为空、无错误，表示关闭时没有未完成的执行动作。结束存档中的 `pending.status=awaiting_input` 表示行动已等待玩家选择，属于待输入状态，不是尚未完成的执行 pending action。关闭/保存链路完成不代表游玩功能全面正常。

## 实际可见结果

我查看了标题页、卧室中段和末帧 PNG。画面与操作员记录相符：从标题页进入卧室，角色移动并进入乙区走廊；末帧清楚显示走廊及 07 门洞附近的角色。`visible.jsonl` 的所见采样正文只含标题“安眠者有福”、时钟和床/风衣交互提示，没有普通过路对白或人物对话文本。此窗口没有到达其他房间、没有遇见同伴，也没有触发可见对白，因而只能说所见范围未出现普通过路对白，不能推断其他场景的对白行为。走廊门洞附近多次 E 输入后，记录与截图均未见换房或文字反馈；范围仅限该处和这些输入。

## 间隔与归因限制

`hitches.json` 将 50 ms 以上实际帧间隔和 100 ms 以上命令等待分别记录，并明示各分段为独占墙钟重叠时间，不是 CPU 归因或因果证明。帧间隔列表中有 20 项：启动附近的最大值约 900.8 ms，其中约 851.0 ms 归入 view_build；约 99 ms 的间隔落在 session_open。之后仍有约 187.97 ms、178.89 ms、177.25 ms、155.18 ms、146.09 ms、132.93 ms、122.37 ms、107.31 ms 等间隔，主要重叠于诊断日志写入或截图 readback/metadata。6 个长命令等待中，启动项约 2.956 秒，主要重叠 session_open；其余最大约 361、307、225、222、120 ms，涉及 DV 选择/认知、可见轨迹、截图读取及其他阶段。它们证明本次采集窗口中仍存在长间隔，不能据此断定玩家必然感知为卡顿或认定单一根因。

所有 20 个已记录帧间隔的 `unattributed_wall_time` 合计约 129.3 ms，另有阶段分类和采样边界限制；这些残差仍未归因。PNG 约每 0.2 秒稀疏采样，不能验证帧级流畅度、遗漏短暂画面或完整交互表现。后台截图归档记录显示采集/编码时延也可能与帧间隔重叠，不能把分析器开销或截图工作的影响与普通游玩成本完全拆开。新生成的五图像素核对只验证抽样内容哈希，不改变该性能归因限制。

## 结论

这份证据支持：一次 240 秒、4 倍速的真实 Godot 玩家输入窗口按指定 240 Hz/32-step 配置运行；玩家可见移动从卧室推进至乙区走廊；会话归档关闭完成；记录范围内没有出现普通过路对白。它也显示启动和运行中仍有长帧间隔及长命令等待，且存在未归因残差。证据不足以声称全面消除卡顿、定位全部根因、完成进入其他房间或验证对白交互。五张抽样 PNG 的像素哈希均匹配其归档记录；这项结果仅适用于所列抽样，不能据此声称全量图片一致或无卡顿。
