# Luna 实际观察

日期：2026-10-24。独立观察范围为六幕 Highlights 舞台与一次约 2 分 50 秒的 `--jsonl --controller player` 正式 CLI 会话；本轮没有读取设计说明、历史试玩或谜底。

## 工程启动

Godot 解决方案构建实际退出码为 0；CLI Release 构建实际退出码也为 0。4.6.1 Mono 的 `--headless --editor --import` 实际退出码为 0，重新扫描并导入了高光角色/道具资源。

Highlights 游戏进程确实创建了窗口，但窗口连续显示全黑，没有可见标题栏按钮、对白或舞台，无法判断六幕的地形、人物比例、Y 遮挡、碰撞和演出效果。启动控制台只显示 Vulkan 不可用后回退到 D3D12 Basic Render Driver，以及 WASAPI 输出设备打开失败后使用 dummy audio；没有观察到 GDScript 错误。首张窗口图保留在 `screenshots/stage-1-shura-poet.png`，它记录的是黑屏，不能作为舞台完成画面。

Windows 操作技能 `@oai/sky` 首次成功截到黑屏。随后键盘输入/刷新失败，按技能要求重新枚举并选取窗口后，刷新再次报 `GetCursorPos failed: 拒绝访问 (0x80070005)`；因此没有继续沿用旧窗口状态，也没有进行桌面鼠标验证。之后在隔离 Godot 工作区中以 compatibility/OpenGL3 启动真实 Highlights 场景，使用标准 `InputEventKey` 逐幕切换并按空格推进，在实际 SubViewport 纹理上保存初始与推进画面；不是桌面窗口截图或正式游玩验收。六幕采集进程正常退出。第六幕额外按住 A 24 帧，侦探在图上发生可见位移；该输入没有确认墙体/道具碰撞或桌面焦点操作。

六幕截图都在 `screenshots/`，每幕各有 `initial` 与 `progressed` 两张。标题栏、段落计数、对白区和操作提示位置一致，能看懂空格推进、1–6切幕和局部移动；但是每幕标题下的条件说明挤成很长的一行小字，实际游玩时不容易扫读。1280×992 截图中角色大多约二三十像素高，和宽大的舞台留白相比偏小，主要剧情道具也显得稀疏。

逐幕观察：

- 疯骑士舞台用浅色重复网格铺满走廊，两侧红柱和上方窗、门、拱形装饰很醒目，但地面格纹抢过角色；对话提到桥口，画面没有明显桥体线索。角色分散在场景中，人物尺度明显小于门拱和窗饰。
- 人在史仕舞台的深色六角地面与灰砖边墙配色清楚，中心石碑和左右遗物可辨，但中央陈设周围空旷，人物仍偏小。灰色砖框与深色地板接缝规整。
- 十九路棋舞台有三人围桌，台词提示“黑子落在左上星位”并显示已走棋数，但截图里桌面是无格线、看不到棋子，文字讲解和图像动作脱节；读者无法从画面确认落点。
- 最后馈赠舞台清楚呈现四座锚形石像与两名角色；推进后的收尾对白短，画面偏静态，没有明显奇迹粒子或物件变化。
- 热饭舞台木地板、蒸锅蒸汽、饺子桌、木箱和布袋可一眼辨认，环境叙事最完整。人物聚在桌子附近，屏幕下半仍有大片空地。
- 最后抢运舞台的紫色液面和搬运物件醒目，但两个门洞与高处炉/窗各自带着矩形砖地块，像直接贴在浅色网格地面上，边缘接缝突兀。推进至段落结束时对白仍是“绳索仍在摇。沈鼎等高处回话。”，底栏同时显示“已实际送达：0件 / 当前搬运：1件”；人物携货、交接或等待的可见动画不足以解释这一状态。按 A 后角色确实移动到货物附近，但截图不能确认碰撞边界，也不能确认搬运物是否跟随。

演出文字整体没有普遍冗长：侦探内心话与热饭纠错对白短、口语；部分顶部条件说明仍是长句小字。六幕按空格推进属于舞台节选，不能据此声称真实行动链、完整剧情或正式通关已完成。

## CLI 正式会话

初始 `status` 显示观察者为侦探、游戏时刻 08:00、地点为乙区卧室、状态 idle。`options` 给出前往宿舍走廊、回想醒来前、检查书架和检查风衣四项候选，成本和实体 ID 均可见。

第一次输入 `focus detective.opening.wake` 触发了 `阶段 · prepared` 错误；此时引擎已有待处理开场行动。`next` 返回的交互阶段是 focus，但 `selected` 为空；随后 `confirm` 执行了恶魔的开场广播并回到 idle。侦探候选再次出现后，`focus detective.opening.wake` 与 `confirm` 成功，游戏时刻推进一分钟。侦探读到三句简短内心话：最后记得上船、认出风衣属于自己、想先出去看看。

随后两次尝试聚焦“穿上风衣”都得到同一个 `阶段 · prepared` 错误，中间需先调用 `next` / `confirm`。两次确认分别处理了 Huo 和 Shen 的后台行动；它们都标记 `visible=false`、正文为空，但 JSONL 仍携带 actor、action、source_refs 和“陌生学员·?”称谓元数据。玩家可见结果为空；这类私有事件字段仍进入接口响应，不能当作侦探实际看见的姓名或行动。

人工输入的选择与结果能在 JSONL 中区分，但 `阶段 · prepared` 没说明需先完成在途行动，操作者要靠猜测 `next` 才能继续。CLI 的单行 JSONL 在 80 列终端里大量折行且中文以转义码呈现，适合机器读取，人工查读较费力。广播篇幅和措辞明显比侦探内心话更正式、更长；侦探回忆本身短且容易读懂。

会话在约 2 分 50 秒时通过 `quit` 正常退出，进程退出码为 0；关闭结果记录 `host-closed-during-active-session`，游戏时刻为 08:01。`session.dvdag` 是退出前显式 `trace` 写出的完整当前轨迹；退出时正式封存的引擎性能记录为 `session.dvlog`。本次没有执行 Godot 几何或正式地图现场检查，也没有到达章节交接或通关。
