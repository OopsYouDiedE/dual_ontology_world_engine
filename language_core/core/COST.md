# DV action accounting

`dv_action_cost_vector(time, computation, stamina)` represents three independent nonnegative finite resources. Numeric validation uses the existing finite-number ABI; no preference score grants resources. `dv_action_cost_bounds(minimum, maximum)` requires explicit per-dimension bounds.

`dv_action_cost_ledger(id, balances)` starts a persistent-by-copy ledger. `dv_action_cost_quote(ledger, physical, action, event, bounds)` is read-only and binds ledger identity/revision and world identity/revision. `dv_action_cost_admit(ledger, physical, quote)` returns `{ledger, receipt}`, debits maximum from available balances and adds it to reserved. Multiple outstanding receipts cannot spend the same available balance. Admission and settlement invalidate old quotes; existing receipts can settle despite later admissions.

`dv_action_cost_settle(ledger, receipt, actual, outcome)` verifies the complete stored receipt, enforces minimum ≤ actual ≤ maximum for every dimension, accepts `applied` or `rejected`, releases the reservation and refunds only maximum minus actual. Both outcomes consume actual; a retry needs a fresh event. Settled receipts and admitted event identities remain recorded, preventing replay and refund reuse.

`dv_action_cost_execute(ledger, physical, quote, actual)` admits and validates actual before calling `dv_execute`, then settles its bound receipt. It returns `{ledger, execution, receipt}`. Execution time is previous world time plus actual time. A rejected law result still consumes the declared actual cost. Exceptions return no new state; callers publish the returned ledger and world together. Use this wrapper for formal execution.

These mutable-by-copy data values are a trusted single-threaded protocol, not unforgeable capabilities. The owner must retain the latest authoritative ledger and publish returned state atomically; forks/rollback or fabricated bounds/actual measurements are outside this accounting boundary. Actual cost and bounds come from the execution adapter, never from player preference scoring. This module does not implement measurement, chapter logic, or static capability safety.
`dv_action_cost_finish(ledger, physical, quote, actual, outcome)` accounts for adapter operations without a physical law. It returns the same shape as execute, advancing time/revision and recording the event in seen. The adapter must perform the operation only after admission; use the lower-level admit/settle pair when its effects require staging. Quotes accept catalog operation identities; the trusted caller validates the frozen action catalog and cognition version before admission.

Rejected law results advance world time by actual time, increment revision, and record the event in seen plus an action-cost history entry without applying physical effects. Non-law finish uses the same clock commit. All execution results expose event, time and actual_cost; applied law world transitions stay unchanged.

User decision for formal DV sessions: the approved catalog computation cost is a method-call resource, retaining its original value (currently 1). It is distinct from the algorithm model budget, whose unit is one local assumption, predictive-law invocation, or feature comparison. Each paid method is limited by a frozen catalog work_limit and the actor's total remaining model_budget. The runner supplies model_work_remaining, decrements it across candidates and rechecks, and retains total remaining model_budget. No prediction or comparison may resume for free after exhaustion; the result remains unknown. Record charged computation, work_limit, expanded, work_remaining and total remaining separately; never claim they use identical units. This decision does not change approved time costs or the formal world clock.
