# 家具喝茶谜：脑内推理原型

本场景是公共研究室家具喝茶案的可操作原型，仍未完成整案验收。片段完成条件见 [设计规范](../../../docs/design-standard.md)。

[现行首宣大纲](../../../docs/游戏和核心宣传视频和图片录制/机制主线宣传片大纲.md)拟以脑内推演为约30秒主机制、言灵精准命中为约15秒短机制；本页记录的茶案与言灵试验台仍是各自独立原型。恶魔提问、实体授课和真名救场尚未接入这些场景，不能从现有原型说明推定它们已经可录。

当前入口是 `res://scenes/Reasoning/Reasoning.tscn`，由 `TeaReasoningScene` 驱动；旧早餐实验入口为 `res://scenes/Reasoning/BreakfastExperiment.tscn`，言灵课题 `Spellwork.tscn` 保留。场景使用 Godot .NET 4.6.1，最小窗口为 1280×900，不修改原 `Main2D.tscn` 主场景。

现场默认全屏显示。WASD/方向键移动，E 优先与附近人物交谈，F 检查器物（附近无人时E也可检查），Tab 进入或返回脑内重演，Esc 返回；札记为独立的只读材料窗口，仅显示材料、正文与来源。脑内是独立工作区：左侧重演，右侧行为假设；点击人物切换草稿，“当时所知”和句式帮助按需展开。现实与重演使用各自的场景实例和 World2D，退出脑内保留现实位置。地图 `StudyRoom.tscn` 使用 [ReasoningStudy 自定义图集](../../ShareAsset/Internal/Props/ReasoningStudy/README.md) 的 A2 地面、地毯及 A4 墙面、墙顶，建筑由 Terrain 自动连接铺装。工作桌、书柜、工作台与窗使用新 B 图集，少量 Victorian 家具仍保留。`godot_csharp/tools/build_study.gd` 只重建 StudyRoom。侦探使用 `detective.tres`，四名案件人物使用 `placeholder.tres`。

自定义控件主题集中在 `ReasoningTheme.cs`，覆盖按钮、输入框、弹出菜单、滚动条与时间轴；不修改整个项目的默认主题。视觉依据与边界见 [界面设计记录](../../../docs/reasoning-art-direction.md)。

2026-09-24：脑内工作区按用户参考图改为深绿背景、场景纸边与右侧书写纸，局部布局在 `TeaReplayLayout.cs`。人物标题和规则当前优先使用简体中文系统楷体；原先的清松手写体5保留为候选字体，辅助文字采用系统宋体。纸下词语可在光标处插入，保留人物切换、句式帮助、行为组织与证据对照。错误行着色，非法草稿禁用从头重演；左侧支持回退、播放、逐步及已记录范围拖动。画面明确区分已修改草稿和旧重演。

本轮验证：`dotnet build godot_csharp/DualOntologyWorldEngine.sln --no-restore`，以及 Godot Compatibility 有头执行 `res://scenes/Reasoning/check/manuscript_check.gd`，检查1280/1586宽度及1280×900窗口、词语插入、非法与修正规则、真实回放、回退和返回现场后的草稿保留。截图及日志复用 `artifacts/tea-reasoning/manuscript-*`。构建存在 Dialogue 插件原有可空性警告；沙箱内引擎报告系统证书存储读取失败，编辑器退出写用户设置也受权限限制，场景运行与本轮界面检查可完成。此记录不代表整案试玩或美术已获用户验收。

额外执行 `check/capture_tea.gd` 的现场回归未全通过：人物1（整理者）的交谈动画、镜像及侦探交谈动画三项失败，见 `artifacts/tea-reasoning/manuscript-regression.log`；本轮没有据此宣称全场景回归通过，也未改动人物演出逻辑。

## 调查交互

开场不再直接列出完整残局，顶部先引导寻找右上方主厨。主厨可介绍“茶去了哪里、椅子为什么湿、柜内为何有满杯”三个疑问；选择只改变当前提示，不锁定路线，也不会填入重演答案。直接先检查其他地点仍可推进。

`TeaInvestigation.cs` 管理人物交谈与问题提示。两人转向对方，播放现有talk动作；文字和证据在人物动作接触帧出现。对话期间锁移动，结束后保留朝向；下方人物的对话框放在上方以保留人物可见性。E/F区分同一位置的人物和物品；鼠标点击会先寻路走近，再自动交互。椅布有独立检查标记，悬停显示对象名称。F8切换调试瞬移。

痕迹与陈述分别收录：温瓶盆与纸盘检查不附赠当事人证词；第一声铃后的目击询问主厨，第二声铃后的目击询问整理者。椅布痕迹解锁换杯与旧记忆的追问。柜内满杯先是主厨陈述，检查柜子后才取得开检查口所见的杯碟承托和锁舌材料。模拟差异只显示对应已收录材料；开场不泄露全部终态。

当前已改进首次调查与人物反馈，但完整谜题、多解和“是否好玩”仍须完成案件验证与试玩，不能凭引导按钮或动画认定达成。

## 当前操作与范围

四名人物从开场一起运行；空规则会等待。玩家可查看规则、当时所知和材料，提交行为草稿并观察重建过程。当前草稿只保存在内存中，不支持磁盘保存或多个候选同时保存。

“组织行为”提供借用归还、换杯暂放、收布、收存等参数化假设，生成的文本可直接编辑；也保留自由规则，例如 `当 总是，则 查看 窗边`。任务句式以准备、铃声和公开通知触发，由人物执行实际查看、前往、拿放和倾倒。相同通知下，相同认知状态不会反复执行同一自由规则；新通知或认知变化可使其再次响应。

“证据对照”列出全部已知差异、尚未调查的关键材料，并可跳到差异出现的重演帧。中途结果不代表整案通过；关键调查未完成时不宣布成功。每次修改均从初态重新模拟。

## 当前规则边界

茶场景使用 Core 的类型化 AST `Evaluate`、`Observation.Observe`、共享 CTB 与 `SimulationSession`。搬运的拿起和放置通过 `ActionOp.Take/Place` 结算，支持嵌套承托、锁定、持有者与承托环检查。游戏层保留人物方案组织、房内寻路及倒茶、茶铃、抽椅布等领域效果；并非完整接入 `DecisionSystem`。独立检查覆盖嵌套取放/观察、拒绝后的原子性与等待后的状态复核。

公共研究室是 Core 的 Space 对象。地点、家具、器物通过现有 `SpatialProperty.Space / Holder` 形成归属与承托关系，`WorldRuntime.Sync` 同步现实投影的父子结构。TileMap继续负责装修、碰撞和遮挡；客观房间子树不会自动成为人物的可见清单。当前仍是茶案的局部接入，并非通用房间编辑器。

## 当前验收边界

茶铃在相应通知下的任务结束后发生，不再要求赶隐藏行动值。因果检查项目 `check/tea/Tea.Check.csproj` 覆盖参考解、另一人送洗空杯的合法解、茶量守恒，以及重新查看椅布、分开收存杯碟、直接倒茶等反例。还检查非法输入整体拒绝、空间归属同步和交互点可达。

`check/round2_ui_check.gd` 覆盖实际输入、椅布与柜子检查、行为组织器及证据对照。`check/round2_playtest.gd` 提供游戏内输入与视口截图，不控制桌面；带 `--tea-no-guidance` 可关闭路线指引。命令行有头测试使用 OpenGL Compatibility。第二轮改动与验收边界见 [设计记录](../../../docs/reasoning-round2-design.md)。测试通过不等于已证明好玩，也不证明十至三十分钟的体验目标。

## 旧实验：早餐铃声与言灵

以下内容保留旧实验的规则和验证说明。旧实验请从 `res://scenes/Reasoning/BreakfastExperiment.tscn` 进入，不代表当前家具喝茶入口。

旧实验的房间、人物、设备和管线均由 Draw 方法绘制，不依赖图片素材；其窗口最小尺寸为 1100×800。

## 操作

点击右侧人物切换规则草稿。左侧直接输入，一行一条行动，允许中文之间省略空格；支持 `#` 批注。蓝色表示已掌握的关键词，黑色表示有效词汇，红色表示未知词或非法数值。编辑区下方同时显示整行句法诊断。非法方案不会部分执行。

“执行此人物方案”提交选中人物；“执行两人方案”先共同验证再提交。规则运行时编辑的是下一次草稿，当前方案保持提交时的内容。初始两份方案可直接执行。

截止行动值控制自动播放的上限；步/秒只改变展示节奏。单步推进一个 Core 调度事件，因此同一行动值可能包含多人行动。“重置实验”清除记录、词汇解锁和草稿，回到初始状态。

## 逐步发现

初始只能移动、校时、监听、等待、提交与比较记录。先进行两处校时监听，回餐厅提交并比较，才开放设备检查。检查后才能控制开关。主动开启、关闭各进行一轮对照；关闭条件必须完整监听到已发现的第二次声音时刻。每轮需要重新提交记录。随后开放特定节奏实验，完成后才开放言灵。

共享调查札记是两人明确公开的记录；人物认知经 `Observation.Observe` 更新。比较器仅使用公开的声音、时刻和设备操作条件，不读取隐藏的声音来源或重放标记。阴性监听记录也必须提交。

## 言灵：学园道本语

行动规则使用中文描述人物行动，言灵使用独立的有限词汇语言。旧命令“设立 只接受 本轮 原声”已移除。

设计参考 [Toki Pona 官方介绍](https://tokipona.org/) 的少量宽泛词汇。这里实现的是道本语启发的学园受限方言，具有明确的实验锚定语义；不是完整的自然语言翻译器。用户的新设计要求优先：语法简单，难度来自精确描述，不靠增加复杂语法。

基本句式为 `对象 o 动作 e 事物`，一行一句，以空格分词，可使用句号与 `#` 批注。`pi` 组成后置修饰组。后期开放 `kalama li 描述 la 命令` 情境句。编辑器显示结构词、已知词与未知词，并给出草稿的字面解释。语法错误整篇不提交；语法成立但范围不合要求的咒文会实际执行。

课题要求厨房接收本轮两个独立来源的首次声音，拒绝重复到达和上轮留声，交谈室接收器保持原样。试声使用五次实际调度事件，不以咒文字符串或按钮点击次数判定成功。

1. 范围实验仅开放器物、房间用途、声音、接纳与排除等词。实际改变厨房且交谈室未受影响，才开放序数与否定。
2. 次序实验需要保留两种本轮声音并排除重复。上轮留声的首次到达构成反例，实验成功后开放时间词及情境句。
3. 最终实验同时检查范围、来源次序与发声时间。直接描述、情境描述和排除式描述均可通过，不限定唯一写法。

实验语义明确约定：声音的 `nanpa wan` 按每个发声来源分别计数，拒绝也算一次到达；`pi tenpo ni` 描述发声轮次，`sin` 在此试验台是同义简写。`pi` 分组延伸至短语末尾，不把组内修饰静默移到组外。`jo ala` 与 `weka` 在这台二态接收器上等价。

未覆盖的声音照常接纳。多个命令命中时，后句覆盖前句。每篇发声替换施术者有权控制的试验台约束；无权控制且未被命令提及的器物保留原约束。咒文若指向超出位格的器物，整篇拒绝。发声占用 2 行动值，试声须在发声结算后开始；“试声”只清空本轮计数，“重置课题”清空咒文、词库进度与全部运行状态。

## 引擎边界与验证

`RuleLanguage` 将人物方案转换为游戏层类型化指令。`UtteranceLanguage` 将言灵解析成对象范围和 Core `Condition`。`UtteranceLab` 将语义条件编译为本试验台的四种声音状态接纳域，以 `SimulationSession`、`ActionIntent` 和 `Effect.Sequence/Set` 原子结算；位格由 Core 前置条件复核。人物认知统一经 `Observation.Observe` 更新。声音传播、实验资料与词汇进度属于游戏层；Core 不包含 UI、几何或实时逻辑。

```powershell
dotnet build godot_csharp/DualOntologyWorldEngine.sln
dotnet run --project godot_csharp/scenes/Reasoning/check/Reasoning.Check.csproj
```

独立验证通过实际人物方案推进完整推理流程，并执行范围误伤、低位格拒绝、旧声反例、三种等价咒文、多句覆盖和原子提交验证。`check/capture.gd` 与 `check/capture_spell.gd` 渲染两个场景，并通过实际界面控件检查着色、操作、解锁和重置。
