# 四翼生活区域美术模块

`LivingWings.gd` 提供 `static furnish(kit: Node3D, entry: Dictionary) -> void`。由 E 的 LibraryE 在建好房间内部之后调用，替换该区域原先直接遍历 `_prop` 的步骤；不要在旧家具已经生成之后再调用，否则会叠放。

输入 `entry` 使用 `library-layouts.json` 的既有 `map`、`id`、`size`、`furniture`。支持 `zone_jia`、`zone_yi`、`zone_bing`、`zone_ding`。家具脚点完全沿用 `prop.at`，不变更房间划分、床位占用和角色归属；是否为已陈设寝室只读取现有 `desk_0` 家具。

新模型包含床架凹框、车木柱、床单翻折、衣柜冠线、抽屉书桌、独立椅背、铜传声管、带镜盥洗台、餐具柜、灶具把手与锅、屏风、谱架及布袋。甲乙丙丁只用不同的绿、青灰、铜色织物材料区分，不引入角色剧情陈设。桌面按用途摆纸、墨水或工作板，不沿用所有桌面都有花瓶烛台的公共厅配方。走廊保留通道，只补内侧壁灯。

本模块不生成墙、外侧面、门或门硬件。现有 `inner_bolt` 家具明确推迟到门的认知呈现入口。探索记忆、人物状态、房间压暗和薄雾由主入口控制，本模块不会切换它们，也不会产生观察事实。

不使用 SVG 或新位图纹理；木、布、金属沿用 E 的现有材质，公共活动厅地毯沿用已存在的位图资源。源码生成几何细节不冒充手绘原稿。灰烬扇形与灰尘手印属于有语义的证据纹样，仅保留命名锚点与待作者资源标记，不能凭空绘制方向/指纹；乐谱面为空白纸，不新增曲谱内容。

子任务未启动 Core、未修改公共文件、未提交。最终画面、家具遮挡、灯光及尺寸由主任务统一 Godot 实机采集并对照；接口及静态审读不能替代视觉验收。
