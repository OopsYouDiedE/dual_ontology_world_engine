# C# Core 维护规范

本目录使用 .NET 8、C# 12、nullable reference types 和 implicit usings。以下规则补充仓库根目录规范。

## 语法与结构

- 使用文件范围命名空间。类型与公开成员使用 PascalCase，参数和局部变量使用 camelCase，私有字段使用 `_camelCase`。
- 局部类型可直接从右侧推断时使用 `var`；数值精度、接口边界或目标类型不明显时显式声明。行动值使用 `double`，标签强度使用 `int`，现有心智评分保留 `float`。
- 已有目标类型时使用 `new(...)` 与集合表达式 `[]`、`[..items]`。纯转发和简单计算使用表达式体；有状态变更的多步逻辑展开书写。
- 简单构造赋值优先使用主构造器。实体及其他具有运行时身份的对象保持 `class`；按值比较的结果与 AST 使用 `record`。不为减少几个字段强行建立继承体系。
- 同一机制内的紧密相关小类型可以共用文件。跨机制职责分开；不得以合并文件或删除有效注释冒充实现精简。
- XML 注释说明契约、边界和算法。单句 summary 使用一行；不为每个参数重复名称，不保留与签名失配的注释。

## 严格程度

- 必需依赖使用非 nullable 参数。可缺失的信息用 `?`，正常的无候选/未获知状态不抛异常。不要重复检查内部非 nullable 参数。
- 初始化后固定的引用使用 `get` 或 `readonly`，创建时可配置的数据使用 `init`。世界状态、插件集合和运行配置按实际需要可变；`readonly` 不表示集合内容不可变。
- 世界树子节点通过 `Reparent` 修改，外部只读 `Children`。标签、属性和 Facet 保留直接扩展能力，不为每个内容字段新增数据类。
- 保留有业务意义的边界检查：行动值必须推进、支付不得透支、计划不得提交过期状态、选择器必须返回真实候选。不要增加纯形式的格式校验。
- 实体关系和 AST 参数直接引用对象。显示名称只用于呈现，不能参与运行时对象定位或规则去重。
- 动态属性在定义和读取端约定同一类型。声明式数值资源使用 `double`；`Get<T>` 不做隐式数值转换。未知字段与值为 null 是不同状态。

## 机制入口

- 新行动优先声明 `Intent.Changes` 与 `Requirements`。`SimulationSession` 负责行动槽和恢复时间，`ActionRuntime.ResolveDetailed` 是行动结算入口。
- 候选推演使用带 Soul 的 `StateView`；执行审查使用客观视图。不得通过候选过滤提前读取隐藏事实。
- 效果扩展在 Prepare 阶段只写 `EffectPlan`，禁止修改真实实体、推进时间或消费随机数。复杂扩展仍须遵守先准备、后提交的规则。
- 规则套路只组合已有 AST，固定对象使用引用，可变行动位置使用 `RuleSlot`。操作符统一小写；字符串仍可表达内容扩展，不另建操作符 ID。
- 保留学院仍使用的闭包动作适配。闭包不支持无副作用预测，也不保证多步回滚；新增可预测行动不得依赖此路径。
- Core 不引入 Godot 节点、实时循环、房间内几何计算、碰撞或 UI。用户已在后续请求中授权实施成长、文学案例与长期平衡运行机制；以可复现的因果轨迹验证改动。
