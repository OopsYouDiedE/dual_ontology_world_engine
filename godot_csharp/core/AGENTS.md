# C# Core 维护规范

本目录使用 .NET 8、C# 12、nullable reference types 和 implicit usings。以下规则补充仓库根目录规范。

## 推荐语法糖使用规范

- 优先使用能够减少样板代码、且不削弱静态类型检查的 C# 语法糖。
- 类型可由上下文明确推断时，优先使用 `var`、目标类型 `new(...)`、集合表达式 `[]` 与 `[..items]`，避免重复书写已有类型信息。
- 简单条件赋值优先使用三元表达式 `condition ? a : b`；多分支值选择优先使用 `switch` 表达式与模式匹配。存在多步状态变更时仍使用普通控制流展开书写。
- 空值访问与默认值处理优先使用 `?.`、`??`、`??=`。
- 纯转发、简单计算与单表达式成员优先使用表达式体 `=>`。
- 小型、不可变且按值比较的数据优先使用 `readonly record struct`。具有运行时身份的对象继续使用 `class`。
- 对已有类型增加基于现有状态的通用行为时优先考虑扩展方法（Extension Methods）；扩展方法不得用于模拟实体额外状态。
- 具有明显运算符语义的结构，使用运算符重载。
- 长数字允许使用数字分隔符 `_` 提高可读性。
- 优先使用 C# 已有语法表达直接逻辑。

## 语法与结构

- 使用文件范围命名空间。类型与公开成员使用 PascalCase，参数和局部变量使用 camelCase，私有字段使用 `_camelCase`。
- 局部变量类型可直接从右侧推断时使用 `var`；数值精度、接口边界或目标类型不明显时显式声明。引擎里全部浮点数使用 `double`，标签强度使用 `int`。
- 已有目标类型时使用 `new(...)` 与集合表达式 `[]`、`[..items]`。纯转发和简单计算使用表达式体；有状态变更的多步逻辑展开书写。
- 简单构造赋值优先使用主构造器。实体及其他具有运行时身份的对象保持 `class`；按值比较的结果、闭环领域模型与 AST 使用 `record`。不为减少几个字段强行建立不合理的继承体系。
- 同一机制内的紧密相关小类型可以共用文件。跨机制职责分开；不得以合并文件或删除有效注释冒充实现精简。
- XML 注释说明契约、边界和算法。单句 summary 使用一行；不为每个参数重复名称，不保留与签名失配的注释。

## 严格程度

- 必需依赖使用非 nullable 参数。可缺失的信息用 `?`，正常的无候选/未获知状态不抛异常。不要重复检查内部非 nullable 参数。
- 初始化后固定的引用使用 `get` 或 `readonly`，创建时可配置的数据使用 `init`。世界状态、插件集合和运行配置按实际需要可变；`readonly` 不表示集合内容不可变。
- 世界树子节点通过 `Reparent` 修改，外部只读 `Children`。非世界实体（如欲望 Motive、条款 Clause、认知事实）不得伪装为 Entity 挂载到树上。
- 保留有业务意义的边界检查：行动值必须推进、支付不得透支、计划不得提交过期状态、选择器必须返回真实候选。不要增加纯形式校验。
- 实体关系和 AST 参数直接引用对象。显示名称只用于呈现，不参与对象定位、规则分派、判定或去重。
- Core 内部禁止使用 `string` 表达机制语义、分类、标签、状态键、关系类型、操作符、效果类型、规则类别、槽位类型或其他标识。`string` 仅用于名称、描述、叙事文本、日志和外部输入输出。
- 禁止使用 `Dictionary<string, ...>`、字符串键属性表和字符串标签集合构建 Core 机制。内部语义使用枚举、明确类型、成员、接口、泛型、AST 节点或对象引用表达。
- 固定或有限集合使用枚举、结构体、record 或其他明确类型。稳定领域状态使用明确成员或专用类型保存。
- 实体功能扩展优先使用扩展方法（Extension Methods）。只有数据确实开放且异构时才允许使用 `object` 或弱类型容器，并限制在明确边界内。
- 行动审查与执行上下文统一使用不可变 `ActionContext` record；切面关系使用 `FacetType` 枚举，言灵槽位使用 `SlotSpec` 结构体。禁止在方法签名中传递弱类型字典。

## 机制入口

- 新行动优先声明 `Intent.Changes` 与 `Requirements`。`SimulationSession` 负责行动槽和恢复时间，`ActionRuntime.ResolveDetailed` 是行动结算入口。
- 候选推演使用带 Soul 的 `StateView`；执行审查使用客观视图。不得通过候选过滤提前读取隐藏事实。
- 效果扩展在 Prepare 阶段只写 `EffectPlan`，禁止修改真实实体、推进时间或消费随机数。复杂扩展仍须遵守先准备、后提交的规则。
- 规则套路只组合已有 AST，固定对象使用引用，可变行动位置使用 `RuleSlot`。操作符优先使用强类型枚举（如 `ExprOp`、`EffectOp`）及对应 AST 工厂，消除对魔术字符串的依赖。
- 不保留旧字符串机制入口、弱类型上下文字典或闭包动作兼容路径。所有行动使用声明式变化与前置条件，学院及其他调用方同步迁移。
- Core 不引入 Godot 节点、实时循环、房间内几何计算、碰撞或 UI。核心改动以可复现的因果轨迹与严格平衡测试进行验证。
